# Ревизор · две проверки сдачи Звука `c8d1323` — обе подтвердились

**Дата:** 2026-11-26 · **База:** `999d680` · **Инструменты:** `tools/accept_3.7.2.py` (как есть), новый `02-reviewer/tools/bank_peak_audit.py`

## 1. З-Г1 · Блок клиппинга в гейте 3.7.2 гаснет молча без PyAV — подтверждено

Звук написал, что гейт ищет декодер «по numpy, а нужен av». Проверил на настоящем коде, подменив окружение (`sitecustomize`, который делает `import av` невозможным), и вызвав сам блок гейта `check_bank_format`:

| Окружение | Что печатает блок | `fail` гейта | Итог гейта |
|---|---|---|---|
| PyAV есть (как у меня) | `✓ клиппинг: измерено 144, peak max −1.01 dBFS, клип 0` | пуст | ПРИНЯТО |
| PyAV нет, numpy есть (типичный раннер) | `· клиппинг: 144 файлов не декодированы` | **пуст** | **ПРИНЯТО** |

То есть при отсутствии PyAV гейт выдаёт «принято», **не измерив клиппинг ни на одном файле** — в списке предупреждений остаётся одна строка, которую легко не заметить.

**Причина в коде:** `py = _python_with("numpy")` проверяет наличие **numpy**, а встроенный скрипт начинается с `import av, numpy as np`. Интерпретатор проходит отбор по numpy и падает на av — на каждом файле, а `failed` в этой ветке только предупреждение.

**Опасное сочетание:** если на машине есть `ffmpeg`, но нет PyAV, то `tools/timbre_check.py` (блок 9) успешно работает через запасной путь на ffmpeg и даёт код 0. Значит гейт может быть **полностью зелёным**, а блок клиппинга — мёртвым. Сам `timbre_check` здесь честен: без любого декодера он выходит с кодом 1 («нет декодера OGG»), это проверено.

**Что предлагаю (зона Интегратора):**

1. `_python_with("av")` вместо `_python_with("numpy")` — отбирать интерпретатор по тому пакету, который реально нужен скрипту.
2. Если декодера нет — не `warn`, а `fail`: «клиппинг не проверен» обязано давать код 2, а не «принято».
3. Заодно проверять не только клиппинг, но и норму пика (см. §2): сейчас блок видит только `peak >= 0 dBFS`.

**Ключевой риск не в самих файлах, а в гейте:** блок 13 считает клиппингом только `peak >= 0 dBFS`. Файл с пиком −0,01 dBFS он назовёт «клип 0». То есть **проверки запаса в гейте нет вообще** — ни 1,00, ни 1,20 dBFS.

**Что предлагаю:**

2. Интегратору — добавить в гейт 3.7.2/3.7.3 блок:

```bash
python3 02-reviewer/tools/bank_peak_audit.py <распакованный пакет> --margin 0.20   # код 0/2
```

Коды инструмента: 0 — норма и запас соблюдены, 2 — есть файлы тише нормы меньше чем на порог, 1 — нет декодера (не «ок»). Проверен в обе стороны: на банке даёт 2 и те же 15 файлов, с `--margin 0` — 0.
