# Интегратор: гейт звал `sample_loudness` по-старому — S98 не доходил до приёмки

**Дата:** 2026-11-26 · **Находка:** Ревизор `8dde1b4` · **Правка:** блоки 9г в
обоих гейтах + обработка ошибок в чекере

## 1. Что было

Звук в S98 улучшил `tools/sample_loudness.py`: группировка по карте событий
(`--map`) вместо угадывания по именам файлов, и зачёт объявленного события
только после проверки **остатка** (`--spec`, `--residual`).

Но гейты звали его так:

```python
run_tool("sample_loudness", SAMPLE_LOUD, "--bank", bank, need="soundfile", report=True)
```

**Без `--map`, без `--spec`.** Значит на приёмке:

- группировка шла по именам файлов — **6 событий вслезую** (Ревизор считал
  это же число);
- `detail_flow`, **уже решённый** (остаток 0,02 дБ, множитель 2,437), снова
  попадал в находки рядом с двумя настоящими.

Улучшение жило только в отдельном прогоне инструмента. Ровно тот класс, что я
искал тремя импульсами: **улучшение есть, гейт его не зовёт.**

## 2. Что даёт передача параметров (прогон, не рассуждение)

| вызов | итог |
|---|---|
| как было (без `--map`/`--spec`) | у **3** событий разброс, все вслепую; `--spec не задан: засчитать объявленное НЕЛЬЗЯ` |
| как стало (`--map` из пакета + `--spec`) | **подтверждено 2, находок 1** |

То есть из трёх «находок» две — закрытые случаи, и настоящая находка **одна**.
Это не косметика: с прежним вызовом интегратор на приёмке видел три проблемы
и не мог отличить решённую от нерешённой.

## 3. Вторая половина: гейт всё равно бы этого не показал

Передал параметры — а в выводе гейта **ничего не изменилось**. Причина в
`run_tool`:

```python
tail = [l for l in r.stdout.strip().split("\n") if l.startswith("ИТОГ")]
```

Инструмент печатает разбивку **отдельными строками с отступом**:

```
ИТОГ: у 3 событий разброс > 3.0 дБ
  из них объявление в спеке ПОДТВЕРЖДЕНО: 2
  и находок (нет в спеке / неполна / не выравнивает): 1
```

`startswith("ИТОГ")` ловит только первую. Две остальные отбрасываются —
и приёмка видит «3 события», как до правки.

**Это важнее самого `--spec`:** правка, результат которой не виден в отчёте,
не отличается от невыполненной. Добавил печать этих двух строк для отчётных
проверок. Теперь гейт показывает:

```
9г) Разброс сэмплов внутри события — норма без спеки (S84 Audio)
  ~ sample_loudness → код 2 «ЗАМЕЧАНИЯ», отчёт ... | ИТОГ: у 3 событий разброс > 3.0 дБ
      из них объявление в спеке ПОДТВЕРЖДЕНО: 2
      и находок (нет в спеке / неполна / не выравнивает): 1
```

## 4. `--map` берётся из пакета, не из репозитория

Это не деталь: `sounds.json` в репозитории и в распакованном архиве могут
разойтись, и тогда гейт сверял бы банк с **не тем** документом, что в сдаче.
Беру `tmp/src/main/resources/assets/carnis/sounds.json` — то есть из того, что
распаковано из проверяемого ZIP. Если файла нет — печатается предупреждение и
группировка идёт по именам (старое поведение), а не молча.

Так же со спекой: нет файла — предупреждение, объявленное не засчитывается.
**Пустую спеку не подставляю:** это был бы способ «объявить всё решённым».

## 5. Побочно: чекер падал трейсбеком на битом пути

Проверял негатив (`--spec /tmp/нет.json`) и получил:

```
FileNotFoundError: [Errno 2] No such file or directory: '/tmp/нет.json'
```

В гейте это выглядело бы как «чекер упал», а не «спека не прочитана» — и
разбор ушёл бы искать дефект в пакете, которого нет. Добавил `OSError` и
`ValueError` → понятное сообщение и **код 1** («не смог проверить», по общей
конвенции чекеров), без трейсбека. Нормальный путь не изменился: с валидной
спекой код 2 (есть находки), как и был.

Допуск остатка **1,0 дБ** — слишком широкий: Ревизор показал подлогом, что

вносил.
