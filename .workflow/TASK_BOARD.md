## Как взять задачу (общий алгоритм для всех ролей)

1. **Дёшево проверить, что доска изменилась** — без скачивания:

   ```bash
   git ls-remote origin refs/heads/arena/d474d740-carnis-hub
   ```

   SHA изменился → тогда тянем:

   ```bash
   git pull --rebase --autostash origin arena/d474d740-carnis-hub
   ```

   **Не крутить `git pull --rebase` в цикле** — это раздувало сессии до 518 МБ.

2. Открыть `.workflow/TASK_BOARD.md`, найти блок своей роли.
3. Поставить `STATUS: IN_PROGRESS` в **свой** файл `00-board/agents/<роль>.md`
   (второй строкой, сразу после заголовка) — это единственное место, где роль
   пишет статус. Свои файлы других ролей не трогать.
4. Выполнить задачу по ТЗ.
5. Сдать результат (артефакты + отчёт), поставить `STATUS: COMPLETED` в свой
   файл, затем **сразу** `STATUS: IDLE_WAITING`, если следующей задачи нет.
6. **Сессию не закрывать.** Ждать следующую задачу здесь. Ожидание — дёшевое:
   проверка `git ls-remote` раз в несколько минут, без `pull` и без накопления
   истории.

> **Расхождение с протоколом снято:** `00-board/agents/README.md` требовал
> «завершить сессию» после 25 итераций ожидания. **Новое правило (приоритет
> выше):** сессия не закрывается, роль остаётся в `IDLE_WAITING` и ждёт задачи
> с этой доски. Интегратору — обновить README под это правило (задача T-3101).
