# Интегратор: переприёмка 3.7.3 после правки громкости

**Дата:** 2026-11-26 · **Основание:** `coder_s70_volume_fix.md` — Кодер прямо
пишет, что приёмка Ревизора относится к прежнему ZIP `052c2e0c…` и «не
переносится автоматически на новый SHA».

## 1. Что произошло

Кодер снял двойное применение громкости у `hive.detail_flow[0]`
(`volume` 1.5 → 1.0, `pitch` 0.95 сохранён, Java не тронута). Пакет
пересобран.

| | было | стало |
|---|---|---|
| ZIP | `052c2e0c3405…` | **`c7d782544708…`** |
| размер | 12 631 363 Б | **12 631 357 Б** (−6 Б, ровно одна цифра) |
| манифест | — | `092c661d65af…`, **761/761** |

## 2. Переприёмка на новом SHA — код 0

`tools/accept_3.7.3.py` на `c7d78254…`: **ИТОГ: ПРИНЯТО — все проверки пройдены**,
код **0**. Ключевое из прогона:

- манифест 761/761, файлов в пакете 761;
- версия 3.7.3 — 4 из 4;
- звуки: `sound_orphans` код 0 (сирот 0, ссылок в пустоту 0);
- **`✓ громкость: одно место на событие (R24 §4)`** — строка отчёта из
  прошлого прогона стала строкой нормы;
- `volume_double_check` на новом ZIP: **СХОДИТСЯ**, событий с `volume != 1.0`
  в JSON стало **16** (было 17);
- банк 144 `.ogg`, пакет == банк 144/144, манифест канона актуален;
- реестр 16/16, glow 9/9, ambient и timbre — сходятся.

## 3. Единственное изменение в содержимом — та самая громкость

Гейт печатает семантическую сверку с прежним пакетом:

```
· hive.detail_flow[0]: volume None -> 1.0 (разрешено S17)
· hive.detail_flow[1]: volume None -> 1.0 (разрешено S17)
ИТОГ: СХОДИТСЯ — события и наборы файлов те же, менялись только громкости
```

То есть правка не задела ничего, кроме заявленного поля. Это ровно то, что
просил Ревизор в §4 вердикта.

## 4. Что это значит для релиза

Прежний вердикт «ПРИНЯТ, блокеров нет» относился к `052c2e0c…`. Новый SHA
прошёл **полный гейт заново** (мой прогон), но окончательное слово — за
Ревизором: по его же правилу вердикт привязан к SHA. `.jar` не собираю,
релиз не объявляю.

Задача для Ревизора: подтвердить приёмку на `c7d782544708…`.
