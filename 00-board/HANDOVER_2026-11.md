**Правило иммутабельности:** каталог сдачи `01-coder/<версия>/` **никогда не
переименовывается и не заменяется**. Пересдача = новый каталог `…-R2`, `…-R3`.
Актуальная версия определяется по номеру `-R`, а не по дате файла.

## 4. Как устроена работа (чтобы не изобретать заново)

Волна = одна версия. Роли: **Кодер** (пишет код и пакет) → **Ревизор**
(проверяет, выносит вердикт) → **Интегратор** (принимает, мержит, выпускает
релиз). **Звук** и **Художник** сдают графику и звук параллельно.
**Архитектор** (этот документ и я) — решения, ТЗ, арбитраж.

Каждая роль **закрывает работу только файлом `00-board/reports/<роль>_<тема>.md`**:
пути, SHA-256, числа, что осталось непроверенным.

**Порядок приёмки Интегратора** (проверен на 3.5.3, работает):
распаковать ZIP → `sha256sum -c` → валидность JSON → версия в четырёх местах →
`cmp`/`sha256sum` по оверлею → сверка PNG → CI на новом коммите → merge в `main`
→ тег `v<версия>` → GitHub Release с `.jar` → `STATUS.md` + акт в `VERIFICATIONS/`.

Полный цикл Д1–Д7 **не перезапускается** ради точечных правок — проверяется
только дельта. Это решение 2026-11-25, и оно сэкономило несколько полных циклов.

## 5. Доступ к GitHub

Токен — **fine-grained PAT**, привязан к репозиторию `BlockBaster3K/carnis-hub`,
права: `Contents: Read and write`, `Actions: Read`. Передаётся **только через
переменную окружения**, в файлах репозитория его нет и быть не должно:

```bash
export GITHUB_TOKEN=github_pat_...
cd ~/carnis-hub
bash tools/agent_push.sh arena/d474d740-carnis-hub "[роль] сообщение" пути/файлы
```

`tools/agent_push.sh` сам берёт токен из окружения, не пишет его в `.git/config`
и в reflog, умеет делать `pull --rebase` при расхождении веток.

**Репозиторий публичный** — читать (`git pull`, `git clone`) можно вообще без
токена. Токен нужен **только для push**.

⚠️ Если токен утёк (в чат, в скриншот, в файл) — **выпусти новый** с теми же
правами и отзови старый на https://github.com/settings/personal-access-tokens.
Отзывать «про запас» смысла нет: пока агент работает, токен нужен.

## 7. Ключевые решения — чтобы не переигрывать

1. **Ревизор проверяет только дельту** после точечных правок. Полный пересчёт
   Д1–Д7 — только на новой крупной версии.
2. **3.6.0 идёт без K5 и без A3/A6.** Релиз, который можно скачать и поставить,
   важнее релиза, который ждёт картинку.
3. **K4 → K6-S → K5** — порядок, при котором правки не пересекаются.
4. **A2 отложен** до игрового подтверждения.
5. **Методику проверок нельзя менять «под художника»** — можно только устранять
   в ней внутреннее противоречие (как с критерием толщины штриха). Методика
   живёт в `02-reviewer/`, решение о правке оформляется отдельным отчётом.
6. **Локальный Gradle build не запускать** — на песочнице 1 ГБ RAM / 2 CPU
   были OOM. Сборка делается в CI.
