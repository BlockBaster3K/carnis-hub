## 1. Четыре подлога — было два пропуска, стало ноль

Ревизор проверил `prove_no_code_multiplier` подлогами. Результат:

| подлог | до | после |
|---|---|---|
| Д. `playSound(…, CONST.get(), SoundSource.BLOCKS, 0.3F, 1.0F)` | **НЕВЕРНО** ✓ | **НЕВЕРНО** ✓ |
| Г. `playLocalSound(x,y,z, CONST.get(), 0.3F, 1.0F, false)` | ПОДТВЕРЖДЕНО ✗ | **НЕВЕРНО** ✓ |
| Б. `playSound(…, CONST.get(), this.getSoundSource(), 0.3F, 1.0F)` | ПОДТВЕРЖДЕНО ✗ | **НЕВЕРНО** ✓ |
| А. присваивание `float v = … CONST.getId()…` | — | **НЕВЕРНО** ✓ |
| Е. контроль (как в репозитории) | ПОДТВЕРЖДЕНО ✓ | ПОДТВЕРЖДЕНО ✓ |

Причина, которую он назвал точно: провал ставился только если
`volume_from_args()` **сумел разобрать** громкость. Незнакомая форма давала
`None` → «без громкости» → заявление проходило. **Белый список переворачивает
логику:** доказуема ровно одна форма —

```
^return\s+[\w.]*\.CONST\.get\(\)\s*;\s*$
```

всё остальное (вызов, присваивание, аргумент) → заявление не доказано.

## 2. Проверил, не задевает ли это решение по `detail_flow`

Ревизор пишет: «`playLocalSound` — именно тот вызов, которым играется
`hive.detail_flow`». Пошёл смотреть — и **в этом пакете форма другая**:

```java
level.playLocalSound(x, y, z, detail, SoundSource.AMBIENT, 0.30F, 1.0F, false);
```

`SoundSource` здесь **есть** (8 аргументов), то есть `0.30F` разбирается верно.
Дыра реальна для формы без `SoundSource`, но **к текущему коду неприменима**.
Это стоит записать: иначе следующий агент решит, что решение по `detail_flow`
стоит на непроверенном основании.

## 3. Та же слепота была и в ОСНОВНОМ пути — это важнее всего

`call_site_volume` перебирает вызовы и возвращает первое разобранное. Если
вызов **найден, но не разобран**, цикл заканчивался и печаталось
«вызов не найден» — то есть отказ по неверной причине. Хуже: проверь я форму Б
для `synapse_shock`, инструмент сказал бы «вызова нет», а разбор пошёл бы
искать событие, которого «нет», вместо того чтобы сказать «я не умею это читать».

**Сделал fail-closed:** неразобранный вызов теперь даёт
```
sinapse_shock: вызов SYNAPSE_SHOCK найден, но громкость не разобрана —
форма вызова не поддержана: null, pos, …, this.getSoundSource(), …
КОД: 3
```

Проверил подлогом на реальном `SynapseNodeBlock.java` (`SoundSource.BLOCKS` →
`this.getSoundSource()`) — пойман.

**Заодно измерил, сколько таких форм в пакете сейчас: 0.** Все 9 событий с
вызовом разбираются, у `spawn_idle` вызова нет вовсе (это его свойство, а не
слепота). То есть новый отказ ничего не ломает.
