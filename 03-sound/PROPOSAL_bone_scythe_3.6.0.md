## 1. Готовая запись в `sounds.json` (два события, вставить рядом с `item.ossified_scythe.*`)

```json
"item.bone_scythe.swing": {
  "subtitle": "carnis.subtitle.bone_scythe_swing",
  "sounds": [
    { "name": "carnis:combat/bone_scythe_swing_01", "stream": false }
  ]
},
"item.bone_scythe.hit": {
  "subtitle": "carnis.subtitle.bone_scythe_hit",
  "sounds": [
    { "name": "carnis:combat/bone_scythe_hit_01", "stream": false }
  ]
}
```

**`pitch` и `volume` в `sounds.json` не задавать** — намеренно. Сейчас тембр задаёт сам `ScytheItem` (`soundPitch = 1.15F`, `soundVolume = 0.8F` у `BONE_SCYTHE`; `ModItems.java:153–155`). Если записать те же числа ещё и в декларации, значения **перемножатся** (0.8 × 0.8 = 0.64 по громкости, 1.15 × 1.15 ≈ 1.32 по высоте) и коса уйдёт в другой регистр и на −4 дБ тише.

`"stream": false` — оба звука короткие одноразовые, не лупы; стриминг для 0.3–0.4 с только добавит задержку.

Сабтайтлы — в обе локали (`en_us`, `ru_ru`).

## 2. ⚠️ Требование к Кодеру (без этой правки события будут мёртвыми)

Проверено по коду пакета `3.5.3` (не по описанию):

| место | факт | следствие |
|---|---|---|
| `ScytheItem.java:42` | `hurtEnemy()` жёстко играет `ModSounds.OSSIFIED_SCYTHE_HIT` для **любой** косы | новые события `item.bone_scythe.hit` не вызовутся **никогда** |
| `CombatItemEvents.java:42,49` | и `onScytheAirSwing`, и `playWorldSwing` играют `ModSounds.OSSIFIED_SCYTHE_SWING` | `item.bone_scythe.swing` не вызовется **никогда** |

То есть без правки кода два события в `sounds.json` — мёртвые записи: файлы в jar есть, звук не играет, и это не поймает ни CI, ни `Verify overlay reached the jar` (он проверяет наличие пути, а не вызов).

**Правка Кодера — по образцу уже существующих полей.** У `ScytheItem` уже есть `soundPitch` / `soundVolume` с геттерами; добавить двумя полями того же рода:

```java
private final SoundEvent hitSound;    // + геттер getHitSound()
private final SoundEvent swingSound;  // + геттер getSwingSound()
```

конструктор — двумя параметрами (для совместимости с текущим вызовом можно добавить перегрузку), регистрация в `ModItems`:

```java
BONE_SCYTHE      -> hitSound = ModSounds.BONE_SCYTHE_HIT.get(),   swingSound = ModSounds.BONE_SCYTHE_SWING.get()
OSSIFIED_SCYTHE  -> hitSound = ModSounds.OSSIFIED_SCYTHE_HIT.get(), swingSound = ModSounds.OSSIFIED_SCYTHE_SWING.get()
```

и заменить три вызова: `ScytheItem.hurtEnemy` → `this.getHitSound()`, `CombatItemEvents.onScytheAirSwing` и `playWorldSwing` → `scythe.getSwingSound()`.

Плюс два `RegistryObject<SoundEvent>` в `ModSounds` (по образцу `OSSIFIED_SCYTHE_*`, `ModSounds.java:174`) и два ключа субтитров в локалях.

**Альтернатива, если Кодер не хочет менять сигнатуру:** оставить один класс, но выбирать событие по `stack.getItem() == ModItems.BONE_SCYTHE.get()` внутри `hurtEnemy`. Работает, но это то же самое «зашитое знание», от которого мы уходим; поля предпочтительнее.

CI такое не ловит.

## 4. Проверка отличия от окостеневшей косы (числа)

| метрика | `bone_scythe` (лёгкая) | `ossified_scythe` (тяжёлая) | разница |
|---|---|---|---|
| длительность замаха | **0.437 с** | 0.717 с | −39 % |
| длительность удара | **0.337 с** | 0.597 с | −44 % |
| центр замаха | **2412 Гц** | 1918 Гц | +494 Гц (светлее) |
| центр удара | **1124 Гц** | 1267 Гц | −143 Гц (суше, ниже) |
| RMS замаха / удара | −18.56 / −18.52 | −18.04 / −18.57 | в норме |
| peak | −3.54 / −2.57 | −4.95 / −3.04 | лёгкая чуть пиковее |
| энергия < 120 Гц | **0.01 % / 0.01 %** | 0.01 % / **4.19 %** | у лёгкой **нет низа** |
| хвост тишиной | 0.10 / 0.21 с | 0.00 / 0.00 с | у лёгкой чище |

**Правило пары выполнено:** лёгкая короче на 39–44 %, выше по замаху и полностью лишена низкочастотного «веса» (0.01 % против 4.19 % у тяжёлой). При постановке подряд разница слышна по весу, а не по громкости — громкость у них одинаковая.

⚠️ **Одно замечание по `crest`:** инструмент в репозитории (`tools/sound_metrics.py`) печатает `crest` как **отношение амплитуд** (5.6 / 6.3 / 4.5 / 6.0), а не в дБ. В моих отчётах по банку `crest` всегда в дБ (15.0 / 16.0 / 13.1 / 15.5) — это те же числа, 20·log₁₀. Уточняю, чтобы при сверке не выглядело расхождением.
