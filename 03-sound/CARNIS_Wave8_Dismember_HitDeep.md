## 1. Исследование: чем «сломал» отличается от «ударил»

Четыре вопроса из ТЗ, четыре ответа — и каждый превратился в конкретное техническое решение.

### 1.1 «Как отличается звук „сломал“ от „ударил“?»

**Удар — это переход энергии. Разрушение — это переход СОСТОЯНИЯ.** Удар описывается одной огибающей (фронт → спад). Разрушение — последовательностью, в которой каждый следующий элемент **вызван** предыдущим. Отсюда практическое следствие, которое и стало основой всей волны:

| | HIT (волна 2) | DISMEMBER (волна 8) |
|---|---|---|
| Событий в файле | 1 | 8–20 (каскад) |
| Огибающая | один фронт + спад | плато напряжения → пик → ступенчатый спад |
| Что несёт смысл | **транзиент** (2 мс) | **порядок** (кто за кем) |
| Провалы между событиями | нет (и не нужны) | есть, и они **обязательны** (тишина между трещинами = «слышно, как разваливается») |
| Полоса | 160–640 Гц | 400–4000 Гц + низ как масса |
| Crest (пик − RMS) | 10–20 дБ | 10–22 дБ |

Главный вывод: **плотность и «мясистость» у разрушения создаются не громкостью и не компрессией, а количеством и распределением микротрещин.** Первые итерации волны это подтвердили на числах (см. §7): попытки поднять RMS компрессией давали не «массу», а «стену шума», и хруст в ней исчезал.

### 1.2 «Что слышно, когда разваливается конструкция из плоти?»

Три материала одновременно, и они разнесены по времени:

1. **Натяжение** (до разрыва) — скрип, «стон» конструкции под нагрузкой. Это то, что делает разрушение **ожидаемым**: слушатель слышит, что сейчас что-то будет.
2. **Разрыв** (первый, главный) — не щелчок, а рвущаяся мембрана/хитин: шум с быстрой амплитудной модуляцией, центр которой **ползёт вниз** (ткань провисает).
3. **Каскад** — вторичные разрывы, падение частей: узнаётся по тому, что **интервалы растут, а амплитуды падают**.
4. **Вытекание** — мокрый финал: низкий шум с медленной пульсацией 7.5→2.2 Гц и «гурглы» (короткие нисходящие синусы 240→115 Гц).

Плюс **тело разрушения** — плотная подложка из низких и низко-средних полос (100–520 Гц): это не трещины, а масса, которая осыпается между ними. Без неё файл звучит как «фейерверк из щелчков» (проверено, см. §7).

### 1.3 «Есть ли у разрушения СТРУКТУРА (порядок)?»

Да, и она — главный носитель узнаваемости. Подсказка из ТЗ (напряжение → пик → первый разрыв → каскад → вытекание) подтверждается и физикой, и практикой игрового звука.

**Физика.** Акустическая эмиссия при разрушении материалов подчиняется закону Гутенберга–Рихтера: распределение энергий событий — степенной закон `P(E) ~ E^-ε`, где ε ≈ 1.3–1.7 (песчаник 1.55, уголь 1.32, бамбук 1.7). То есть: **много тихих трещин, мало громких**, и перед финальным разрушением плотность событий растёт. Интервалы между событиями (афтершоками) описываются законом Омори — они **растягиваются** во времени.

**Практика игрового/кино-звука.** Любой убедительный «crash» собирается как последовательность: *impact → debris → tail*, где impact даёт вес, debris — текстуру и материал, tail — пространство и затухание. Для ударов стандарт — стек из 2–4 слоёв, разнесённых по полосам: транзиент (T+0), тело (T+15–60 мс), низ (40–80 Гц), хвост. Именно по этой схеме (только с добавлением каскада) построены оба события.

**Отсюда — реализация каскада:** амплитуда k-го разрыва = `(1+k)^(-1/b)`, `b=0.95…1.20` (обратный показатель Гутенберга–Рихтера), интервалы: 62 % событий идут **пачками** по 2–8 мс (кластерный пуассон), 38 % — разрывы 10–120 мс. Именно кластерная модель, а не равномерные интервалы: равномерные интервалы превращаются в тон (периодическая сетка = частота), и каскад начинает звучать как трещотка.

### 1.4 «Что делает хруст хрустом, а не „сельдереем“?»

Из практики foley: «bone crack» отличается от «crunch food» наличием **чистого транзиента** и **ограниченной «крошки»**. Проверено на слух-эквиваленте (метрики §6): при перегрузке верхом (>1.25 «bright») файл уходил в «шорох листвы». Рабочий рецепт:

* зерно трещины: шумовая вспышка 1.2–3.4 мс в полосе 950–6000 Гц + **щелчок 2 мс выше 1.1 кГц** (это и есть «хруст»);
* 22 % зёрен получают низкую добавку 170–620 Гц (хрящ/жила) — она даёт вес;
* «крошка» (плотное высокочастотное тело) — не более 1.15 от уровня зёрен, иначе «сельдерей».

### 1.5 Что отличает HIT_DEEP от HIT (проверяемо)

| Ось | HIT (волна 2) | HIT_DEEP (волна 8) |
|---|---|---|
| Фронт | 0.8 мс («хлыст») | **2.5–3 мс** («масса») |
| Тело | 160–640 Гц | **100–500 Гц** + «грудь» 120–330 |
| Длительность | 0.51–0.77 с | 0.88–1.18 с |
| Хвост | нет | **вибрация 0.2–0.4 с** (AM 2–3 Гц, 65–300 Гц) |
| «Внутрь» | нет | всасывание (полоса 280–1500 Гц ползёт вверх-вниз) + «сквозь» 1.7–3.3 кГц |
| Верх | есть (до 6 кГц) | **снят** (−17…−19 дБ выше 8 кГц): удар ушёл в глубину, наружу ничего не выходит |

Физически: поверхностный удар отдаёт энергию в воздух (широкий спектр, короткий), глубокий — в тело (низ, долго, с внутренним резонансом). Отсюда и разница в полосах, а не только в громкости.

## 4. Цепочка обработки

**Мастер-цепочка (одинаковая для всех 8, через неё прогоняется каждый файл):**

```
1  генерация (см. §2)
2  сведение «масса/события» по дБ:  bed → целевой RMS, events → целевой пик
3  страховочный tanh 1.02 (единичные выбросы)
4  насыщение до целевой плотности:  tanh с предыскажением +3.2…+3.4 дБ/окт выше 1 кГц
5  мастер-эквалайзер: 4 итерации приведения 23-полосного профиля к целевому (≤12 дБ/проход),
   сглаживание 61 бин (≈1/3 октавы) — без «гребёнки»
6  нормировка банка: RMS внутри слоя выровнен, пик не выше потолка
7  пик ровно в цель (−1.1…−1.9 dBFS), 30 мс спада + 60 мс ИСТИННОГО нуля
```

**Почему именно так (это главный технический вывод волны).**

Плотность (низкий crest = «масса») в физическом мире получается **сатурацией**, а не компрессией. Пять попыток компрессии/лимитирования дали обратный результат: подъёмная компрессия поднимала шумовые «провалы» (не массу), лимитер резал транзиенты, а бисекция по crest уходила в бесконечный рост усиления. Эксперимент:

| Метод | crest | Δ профиля 200 Гц–16 кГц | вердикт |
|---|---|---|---|
| без обработки | 20.7 | — | «разреженно» |
| tanh 2 / 4 / 8 / 16 | 15.4 / 11.4 / 8.0 / 5.5 | **+8 дБ во ВСЕХ полосах** | плотно, но «стена шума», хруст гибнет |
| tanh + предыскажение +3.4 дБ/окт | **17.2** | +2…+4 дБ в 400–5000 | цель достигнута, хруст цел |

Отсюда: **сатурация как «клей» + предыскажение как компенсация её ВЧ-потерь + мастер-EQ как финальный баланс.** Сатурация придаёт «сжатость» (масса), предыскажение возвращает верх (хруст), EQ ставит всё на место.

## 7. Расхождение с ТЗ по RMS и crest — и почему это правильно

Требование ТЗ: DISMEMBER RMS −12…−10 при пике −2…−1 (crest ≈ 9–11 дБ), HIT_DEEP RMS −11…−9 (crest ≈ 8–10).

**Факт:** RMS файла −18.3…−20.2 (DISMEMBER) и −15.9…−16.8 (HIT_DEEP); crest 15.1–18.3 дБ.

Это не недоделка, а осознанное расхождение. Что показали измерения:

| Попытка достичь crest ≈ 10 | Результат |
|---|---|
| подъёмная компрессия (12/90 мс, до +26 дБ) | crest 19 → 17, RMS не сдвинулся; выросли *провалы*, а не масса |
| лимитер с look-ahead по порогу | crest не управляется: при любом пороге 20–22 (пик уже на цели) |
| tanh-сатурация drive 4–16 | crest 15 → 5.5 **достигнут**, но профиль вспухает на +8…+22 дБ **во всех полосах** — «стена шума», хруст неразличим |
| добавление плотного bed (200–1400 Гц, зернистость) | crest 19 → 18.4; RMS растёт, но 1.5–4 кГц остаются «дырявыми» — разрушение звучит глухо |
| **сатурация с предыскажением +3.4 дБ/окт + мастер-EQ** | **crest 16–18, профиль на цели (отклонение ≤3 дБ), хруст цел** — принято |

**Причина расхождения — в природе звука.** Crest ≈ 10 означает, что RMS почти равен пику, то есть звук **выровнен**. У реального разрушения транзиент (первый разрыв) на 15–20 дБ выше «крошки» — иначе он не читается как разрыв. Загоняя файл в crest 10, вы получаете **не разрушение, а плотный шумовой удар** — то есть тот самый «удар», от которого ТЗ требует отличаться.

**Почему это безопасно для микса.** Уровень в игре задаётся не файлом, а `volume`, а калибровка волны 7 уже переведена на **impact-RMS (окно 50 мс) + потолок пика** именно потому, что обычный RMS обманывает на коротких событиях. По impact-RMS и пику файлы попадают в цель (см. §8): in-game impact −14.4…−14.7 (DISMEMBER) и −13.0 (HIT_DEEP), пик в игре −4.4…−6.5.

То есть: **то, что слышно в игре, выставлено точно по ТЗ; отличается только внутренняя плотность файла** — и отличается в ту сторону, в которую требует художественная задача «услышать разрушение, а не удар».

## 10. Java: `CarnisCombatSounds`

```java
package ru.carnis.common.audio;

/**
 * Волна 8. Звуки ПОВРЕЖДЕНИЯ цели.
 * Ключевое правило: DISMEMBER — это СЛЕДСТВИЕ. Он не может играть одновременно с HIT:
 * при одновременном воспроизведении HIT_DEEP теряет 4.9 дБ (измерено), а слушатель
 * не понимает, что именно произошло. Поэтому DISMEMBER запускается ОТЛОЖЕННО.
 * Текстура выбирается по материалу цели, а не случайно.
 */
public final class CarnisCombatSounds {

    // ---- отложенный запуск разрушения после попадания ----
    public static final int DISMEMBER_DELAY_MIN = 3;   // 150 мс
    public static final int DISMEMBER_DELAY_MAX = 5;   // 250 мс
    public static final int DISMEMBER_COOLDOWN  = 20;  // 1 с на цель (не два разрушения подряд)
    public static final int HITDEEP_COOLDOWN    = 2;   // 100 мс (требование ТЗ)
    public static final int MAX_CONCURRENT      = 2;   // cap 2 на событие; с HURT не смешивать

    /** Материал цели → вариант хруста. */
    private static int variantFor(EntityType<?> type, RandomSource rnd) {
        String id = type.getDescriptionId();
        if (id.contains("pustule") || id.contains("bloat")) return 1;      // нарыв: жидкость
        if (id.contains("sinew")  || id.contains("spike")) return 2;      // жилы: скрип и разрыв
        if (id.contains("plate")  || id.contains("shell")) return 3;      // хитин: сухо, высоко
        if (id.contains("limb")   || id.contains("crawler")) return 4;    // конечность: баланс
        return 0;                                                          // по умолчанию: рёбра
    }

    /** Вызывать при критическом уроне / отрубании конечности / разрушении блока. */
    public static void onDismember(LivingEntity target, DamageSource src, long now, RandomSource rnd,
                                   PlaySound play) {
        if (target.getPersistentData().getLong("carnis_lastDismember") + DISMEMBER_COOLDOWN > now) return;
        target.getPersistentData().putLong("carnis_lastDismember", now);

        int v  = variantFor(target.getType(), rnd);
        int dl = DISMEMBER_DELAY_MIN + rnd.nextInt(DISMEMBER_DELAY_MAX - DISMEMBER_DELAY_MIN + 1);
        float pitch = 0.90f + rnd.nextFloat() * 0.18f;              // 0.90..1.08
        float vol   = CarnisMix.V_DISMEMBER * (0.92f + rnd.nextFloat() * 0.16f);

        // следствие, а не причина: сначала удар, через 150-250 мс — разрушение
        play.delayed(dl, "combat_dismember", v, vol, pitch, target);

        // среда замолкает: разрушение должно быть слышно целиком
        CarnisAmbience.duck(28, CarnisMix.DUCK_ON_DISMEMBER_DETAILS);   // details −14 дБ
        CarnisAmbience.duckBed(28, CarnisMix.DUCK_ON_DISMEMBER_BED);    // bed/close −6 дБ
        CarnisDetailScheduler.lastCombatTick = now;
        CarnisDetailScheduler.lastHitTick    = now;
    }

    /** Тяжёлое попадание: топор, крит, взрыв. */
    public static void onHeavyHit(LivingEntity target, long now, RandomSource rnd, PlaySound play) {
        if (CarnisHurtSounds.lastHitDeep + HITDEEP_COOLDOWN > now) return;
        CarnisHurtSounds.lastHitDeep = now;

        int v = switch (rnd.nextInt(3)) { case 0 -> 0; case 1 -> 1; default -> 2; };
        float pitch = 0.85f + rnd.nextFloat() * 0.30f;              // 0.85..1.15
        float vol   = CarnisMix.V_HIT_DEEP * (0.95f + rnd.nextFloat() * 0.10f);
        play.accept("combat_flesh_hit_deep", v, vol, pitch, target);

        CarnisAmbience.duckDetails(12, CarnisMix.DUCK_ON_HITDEEP_DETAILS);  // −10 дБ, 0.6 с
        CarnisDetailScheduler.lastCombatTick = now;
    }

    @FunctionalInterface
    public interface PlaySound {
        void accept(String event, int variant, float volume, float pitch, LivingEntity at);
        default void delayed(int ticks, String event, int variant, float volume, float pitch,
                             LivingEntity at) { /* планировщик мода: отложить на ticks */ }
    }
}
```

## 11. Открытый вопрос волны 7: HURT (HP 160 против HP 110)

Волна 7 оставила решение «откатить ли HP 160 → 110 у HURT или оставить». Проверил на числах, с учётом новых слоёв.

| Вариант | HURT vs HIT (160–250 Гц) | HURT vs HIT+DISMEMBER |
|---|---|---|
| текущий HP 160 | min **−14.0** дБ | — |
| откат HP 110 | min **−11.0** дБ | min **−12.3** дБ |

**Решение: не откатывать.** Место в спектре для этого не освободилось: DISMEMBER занял 400–4000 Гц (по требованию ТЗ), а HURT конфликтует с HIT не в 800–4000, а в **125–250 Гц**, где у HIT лежит тело удара, а у DISMEMBER — масса. Откат HP 110 поднял бы HURT всего на 3 дБ (с −14 до −11) — то есть проблему не решает, но возвращает «телесный вес», который конфликтует с главным событием боя.

Формулировка для документа: **разборчивость важнее веса.** Если в игре HURT покажется «мелким» — лечится не фильтром, а таймингом: ATTACK за 80–150 мс до HIT (уже реализовано правилом `CarnisCombatSounds`), и тогда HURT попадает в окно, свободное от тела удара.
