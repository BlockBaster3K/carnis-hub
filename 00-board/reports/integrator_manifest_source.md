# T-3175 / З-18: манифест — рядом с пакетом, а не из репозитория

**Дата:** 2026-11-26 · **Роль:** Интегратор · **Зона:** `tools/`
**Статус:** ✅ выполнено · **Критерий приёмки выполнен**

## 1. Суть дефекта

`accept_3.7.0/3.7.1/3.7.2.py` при запуске с одним аргументом брали манифест
из **фиксированного пути репозитория**:

```python
man_arg = sys.argv[2] if len(sys.argv) > 2 else DEFAULT_MANIFEST
# DEFAULT_MANIFEST = 01-coder/<вер>/project-<вер>-clean.manifest.txt
```

Проверяющий, получивший ZIP **из git** (`git show`), сверял корректный пакет
с манифестом **своего рабочего дерева** — возможно, от другой сборки — и
получал ложное «манифест: не сошлось 16 строк» → **код 1**.

Это **тот же класс дефекта, что З-17**: результат приёмки зависел от
неучтённого состояния рабочего дерева проверяющего, а не от пакета.

## 2. Что сделано

### 2.1 Манифест по умолчанию — сосед пакета

`find_manifest()` теперь возвращает **пару** (путь, источник):

| Источник | Когда | Доверие |
|---|---|---|
| `given` | указан вторым аргументом | доверенный |
| `near` | лежит рядом с ZIP | **доверенный** |
| `repo` | резервный путь по версии | **не доверенный** |
| `none` | не найден нигде | — |

Порядок: явный аргумент → сосед пакета → путь репозитория → ничего.

### 2.2 Проверка знает, откуда манифест

`check_manifest(extract_dir, manifest, src)`:

- **`near`** — строгая сверка. Расхождение = `fail`, код 1. Как раньше.
- **`repo`** — расхождение **не приговор**: пакет мог быть получен из git,
  а манифест в дереве — от другой сборки. Печатается предупреждение
  «З-18: манифест взят из репозитория…», строка уходит в блок **ВНИМАНИЕ**.
- **`none`** — «манифест не найден, сверка sha256 не выполнена» +
  строка в блок ВНИМАНИЕ. Это **пропуск**, а не ✗.

## 3. Проверка в обе стороны

| № | Сценарий | Ожидание | Факт |
|---|---|---|---|
| A | манифест рядом с пакетом (норма) | код 0 | ✅ код 0, 3.7.0/3.7.1/3.7.2 |
| B | **ZIP из git, манифеста рядом нет, в репо битый** | **код 0** | ✅ **код 0** + предупреждение З-18 |
| C | то же, каталог пакета назван правильно | код 0 + ВНИМАНИЕ | ✅ код 0, предупреждение в итоге |
| D | битый манифест **рядом** с ZIP | код 1 | ✅ код 1 — строгая сверка не ослаблена |
| E | манифеста нет нигде | не «не сошлось», а «не выполнено» | ✅ честное «сверка sha256 не выполнена» |

Случай D важен: он доказывает, что предупреждение из B не превратилось
в «пропускать любые расхождения».

## 4. Правки во всех трёх гейтах

Как и с З-17, изменения внесены в `accept_3.7.0.py`, `accept_3.7.1.py` и
`accept_3.7.2.py`. Иначе Ревизор получил бы ложный ✗ и на перепроверке
старых версий — то есть дефект остался бы живым для двух третей гейтов.

Регресс проверен: все три гейта на реальных пакетах дают **код 0**.

## 5. Что осталось за границей

Манифест — единственный артефакт, который гейт берёт «сбоку» от пакета.
Пути внутри `KEEP_IDENTICAL` и сдачи Художника — это **файлы репозитория**,
а не артефакты сборки, поэтому они и должны читаться из дерева: их
устаревание означало бы, что роль не сдала работу, и это правильно ловится.

## 6. Итог

Приёмка больше не зависит от того, как устроено рабочее дерево проверяющего:

- **эталон** — диск → git-объект → честный пропуск (З-17);
- **манифест** — сосед пакета → репозиторий (с оговоркой) → честный пропуск (З-18).

В обоих случаях «не смог проверить» отделено от «проверил, не сходится».
