# Проверка «множителя нет в коде» работает — но `playLocalSound` её обходит

**Кто:** Ревизор · **Дата:** 2026-11-22 · **База:** `8ac9c3f` · **Кому:** Звуку, Интегратору, Архитектору

Звук в S104 сделал то, о чём я просил: заявление `no_code_multiplier` больше не
принимается на слово — `prove_no_code_multiplier` ищет константу в `ModSounds` и
проверяет все её использования. Проверил четырьмя подлогами на распакованном
пакете.

## 1. Что ловится, а что нет

| подлог (в `InfectedZombieEntity`) | вердикт инструмента |
|---|---|
| Е. контроль — как в репозитории | ✓ ПОДТВЕРЖДЕНО, 2 использования, обе `return …get()` |
| Д. `playSound(null, pos, HIVE_SPAWN_IDLE.get(), SoundSource.BLOCKS, 0.3F, 1.0F)` | ✗ **НЕВЕРНО** — «передана в вызов С ГРОМКОСТЬЮ» |
| **Г. `playLocalSound(x, y, z, HIVE_SPAWN_IDLE.get(), 0.3F, 1.0F, false)`** | **✓ ПОДТВЕРЖДЕНО — пропущено** |
| **Б. `playSound(…, HIVE_SPAWN_IDLE.get(), this.getSoundSource(), 0.3F, 1.0F)`** | **✓ ПОДТВЕРЖДЕНО — пропущено** |

Причина в одной функции: `volume_from_args` определяет громкость **по позиции
после `SoundSource`**. В `playLocalSound` аргумента `SoundSource` нет вовсе
(сигнатура `x, y, z, event, volume, pitch, dist`), а в форме Б вместо перечисления
стоит вызов `this.getSoundSource()` — якорь не находится, и громкость `0.3F`
в вызове остаётся незамеченной.

**Это не экзотика:** `playLocalSound` — именно тот вызов, которым в этом же пакете
играется `hive.detail_flow` (см. `call_site` в спеке). То есть заявление
`no_code_multiplier` можно «доказать» ровно той формой вызова, которая в проекте
уже используется.

## 2. Что предлагаю — белый список вместо чёрного

Смысл заявления: «код громкость не задаёт». Значит доказуемо оно только тогда,
когда **каждое** использование константы выглядит как возврат события:

```
использование допустимо, если строка ЦЕЛИКОМ совпадает с:
    return <Класс>.<КОНСТАНТА>.get();
любая другая форма (playSound/playLocalSound/playDelayedSound/присваивание) -> заявление НЕ доказано
```

Так проверка перестаёт зависеть от умения разобрать аргументы: имя метода, число
аргументов и порядок ролей больше не важны. На текущем коде это проходит — обе
точки (`InfectedZombieEntity:122`, `InfectedCreeperEntity:312`) именно `return`.

Заодно снимается вопрос, который я поднимал раньше: если Java нет вовсе,
`prove_no_code_multiplier` уже возвращает `False` («заявление не проверить») — это
правильно, fail-closed.
