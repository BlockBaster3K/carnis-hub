## 2. Четыре комбинации — где теперь стена

| geo | анимации | итог |
|---|---|---|
| **B** (`models/`, 11 костей) | **B** (`animations/`) | **почти**: костей 11 < 12, нет glowmask, нет hurt/death. Имена — чистые ✓ |
| A (`assets/carnis/geo`, 51) | A (`assets/carnis/animations`) | UV **108×86 при листе 64×64**; `sickle_blade`; нет hurt/death |
| A | B | UV 108×86; битые `arm_right`, `hive_spike_1`, `leg_left`, `leg_right`, `scythe_blade` |
| B | A | 11 < 12; битые `cyst_1`, `cyst_2`, `heart`, `jaw_left`, `jaw_right` |

Закономерность простая: **имёна костей сходятся только внутри одного комплекта** —
смешивать `assets/…` и `models/…` нельзя ни в какую сторону.

## 3. Три оставшихся пункта (и один структурный)

1. **Костей 11 при норме ≥ 12.** Нужна хотя бы одна осмысленная кость — не
   декоративная (`creature_pack_audit` считает «реальные» кости и декорацию
   отбрасывает).
2. **glowmask** — файла `infected_zombie_glowmask.png` нет вовсе; есть
   `infected_zombie_glow.png` 64×64 с двумя цветами (чёрный + 8 px циан),
   альфа 255 везде. Нужно: бинарная альфа, единственный непрозрачный цвет
   `(255,92,57)`, имя `_glowmask`.
3. **`hurt` и `death`** — отсутствуют в обоих наборах.
4. **Структурно (R14 §11):** упаковщик читает `04-artist/assets/carnis/…`, а
   согласованная пара лежит в `04-artist/models/` + `04-artist/animations/`,
   то есть **в пакет не попадёт**. Нужен один канонический layout: перенести
   `models/geo` → `assets/carnis/geo/infected_zombie.geo.json`,
   `animations/` → `assets/carnis/animations/`, а старые 51-кость и её анимации
   **удалить тем же коммитом**.

## 4. Итог

Прогресс реальный: раньше не работала **ни одна** из четырёх сборок, теперь одна
из четырёх проходит по именам и по UV — и это именно та, которую Художник довёл
последней. Не хватает трёх чисел и одной раскладки. Содержательная работа
(текстура, анимации) — на уровне; остались формальности, которые как раз и
блокируют попадание в пакет.
