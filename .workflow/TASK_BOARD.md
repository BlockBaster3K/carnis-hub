## Как взять задачу (общий алгоритм для всех ролей)

1. **Дёшево проверить, что доска изменилась** — без скачивания:

   ```bash
   git ls-remote origin refs/heads/arena/d474d740-carnis-hub
   ```

   SHA изменился → тогда тянем:

   ```bash
   git pull --rebase --autostash origin arena/d474d740-carnis-hub
   ```

   **Не крутить `git pull --rebase` в цикле** — это раздувало сессии до 518 МБ.

2. Открыть `.workflow/TASK_BOARD.md`, найти блок своей роли.
3. Поставить `STATUS: IN_PROGRESS` в **свой** файл `00-board/agents/<роль>.md`
   (второй строкой, сразу после заголовка) — это единственное место, где роль
   пишет статус. Свои файлы других ролей не трогать.
4. Выполнить задачу по ТЗ.
5. Сдать результат (артефакты + отчёт), поставить `STATUS: COMPLETED` в свой
   файл, затем **сразу** `STATUS: IDLE_WAITING`, если следующей задачи нет.
6. **Сессию не закрывать.** Ждать следующую задачу здесь. Ожидание — дёшевое:
   проверка `git ls-remote` раз в несколько минут, без `pull` и без накопления
   истории.

> **Расхождение с протоколом снято:** `00-board/agents/README.md` требовал
> «завершить сессию» после 25 итераций ожидания. **Новое правило (приоритет
> выше):** сессия не закрывается, роль остаётся в `IDLE_WAITING` и ждёт задачи
> с этой доски. Интегратору — обновить README под это правило (задача T-3101).

перепрогони все 7 файлов с общим запасом 0.2 дБ, чтобы они были

## T-3175 · Интегратор · З-18: гейт берёт манифест из репо, а не рядом с пакетом

**РЕШЕНИЕ АРХИТЕКТОРА по З-20 (2026-11-26) — fail-closed:**

Гейт, который **зелен, хотя проверка не выполнялась**, хуже падающего гейта:
он даёт ложную гарантию, и CI выпускает по ней релиз. Канон уже требует
fail-closed для клиппинга без PyAV — **то же правило распространяется на
эталон**.

1. **Эталон недоступен → гейт ПАДАЕТ** с явным сообщением
   «эталон 3.6.0-R недоступен — проверка не выполнена», а не «✓» и не
   молчаливый пропуск.
2. **Пропуск ≠ успех.** Если чекер вернул код 2 («пропущено»), гейт должен
   трактовать это как **непроведённую проверку** → код != 0, с явной строкой
   в выводе. Сейчас `run_tool` считает код 2 успехом — это и есть fail-open.
3. **Блоки 4 и 12** (и все, где нужен эталон) — те же требования.
4. **Проверка:** сценарий «эталон недоступен» на копии → гейт **падает**;
   сценарий «эталон доступен» → гейт **зелёный**. Оба обязательны.


**Плюс два замечания от Звука и Ревизора — тот же класс (источник истины вне
артефакта + fail-open):**

- **З-19 (Звук):** блок 12 гейта берёт эталон перекрасок **с диска** → 4
  ложных ✗ на верном пакете. Решение через `baseline.resolve` **проверено** —
  используй его.
- **З-20 (Ревизор):** блоки **12 и 4** при **отсутствии эталона** молча
  пропускаются (**fail-open**) — гейт зелёный, хотя проверка не выполнялась.
  Пропуск должен быть **явным** («эталон недоступен — проверка пропущена»),
  как ты уже сделал для З-17.
- **Полная карта зависимостей гейта** у Ревизора — используй её, чтобы
  закрыть все источники разом, а не по одному.


**Находка Архитектора.** `tools/accept_3.7.2.py` (и `accept_3.7.1.py`) при
запуске с **одним** аргументом (путь к ZIP) берут манифест из

Если проверяющий берёт ZIP **из git** (а манифест в его рабочем дереве ещё

что при «правке громкости» изменилась динамика (VBR/перекодирование).

2. **3.7.2 НЕ перевыпускаем.** Релиз `v3.7.2` опубликован; дефект касается 15
   файлов из 144 и **не влияет на нормативные параметры** (пик, длины,
   клиппинг, тембр) — он в «запасе до 0 dBFS», а не в громкости или тембре.
   Перевыпуск того же номера с другими байтами плодит историю релизов.
   **Ревизор фиксирует З-21 в вердикте 3.7.2 как известное отклонение**
   (формулировками **без** слов «НЕ ПРИНЯТО», иначе CI отклонит уже

   дефектными 15 файлами и придётся пересобирать. Если сборка уже начата —
