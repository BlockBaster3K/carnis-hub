## 3. Находка: сдача и рабочая копия — разные файлы

`04-artist/deliverables/Carnis_3.8.1_animations_core9.zip` содержит
`assets/carnis/animations/infected_zombie.animation.json` **с пятью** анимациями
(`idle, walk, attack, hurt, death`) — то есть `hurt`/`death` в сдаче **есть**.
Но этот файл ссылается на кости `root`, `right_arm`, `jaw`, `tendril_left`,
`tendril_mid`, `tendril_right`, которых **нет ни в одной** из двух наших
геометрий. Файлы не совпадают побайтово (сдача ≠ рабочая копия).

Итого: **сдача несовместима с геометрией, а рабочая копия — неполная**.
Для приёмки нужен один файл, в котором одновременно: 15 костей геометрии,
`hurt`, `death` и совпадающие имена.

`infected_zombie` не изменился: 21 кость, 89 цветов / 11,5 %, те же три провала
(альфа `[0,80,180,255]`, нет glowmask, нет `hurt`/`death`).

Но появился **новый моб** `infected_zombie_b` (16 костей, 89 цветов / 11,3 %,
`idle 3 / walk 4 / attack 4`) — и у него **ровно те же три дефекта**:

```
✗ infected_zombie_b: альфа не бинарная [0, 80, 180, 255]
✗ infected_zombie_b: нет glowmask (правило Р-3)
✗ infected_zombie_b: нет анимаций hurt, death
```

То есть это не «забыл в одном файле», а **воспроизводимый шаблон работы**: маска
делается как `_glow.png` с чёрным фоном, полупрозрачность пишется в cutout-текстуру,
`hurt`/`death` не делаются вовсе. Пока шаблон не изменён, каждый следующий моб
будет приходить с этим же набором, и приёмка 33 существ в 3.8.0 упрётся в него
же — только в 33-кратном размере.

Прошу Художника не «починить зомби», а **изменить приём**: (1) маска — отдельный
файл `_glowmask.png` с бинарной альфой и `(255,92,57)`; (2) альфа главной
текстуры — либо строго бинарная, либо `translucent`-рендер, и это решение
записано в `04-artist/PALETTE.md`; (3) `hurt`/`death` — обязательная пара в
каждом файле анимаций. Тогда все последующие мобы выходят правильными сразу.
