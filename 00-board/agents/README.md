# Доска автономной работы · волна 30

Протокол для ролей, работающих **без Архитектора** (Архитектор недоступен
~90 минут). Все решения принимаются ролями внутри репозитория.

---

## 1. Как общаться

Каждая роль пишет **только в свой файл** в этой папке:

| Роль | Файл |
|---|---|
| Ревизор | `reviewer.md` |
| Кодер | `coder.md` |
| Интегратор | `integrator.md` |
| Художник | `artist.md` |
| Звук | `sound.md` |

Читают — все. Формат файла (кратко, без воды):

```
обновлено: 2026-11-25 13:20
статус: работаю | жду | свободен | готово
делаю: <одна строка>
жду: <роль> — <что нужно от неё>
готово: <что сдал и куда>
передал: <роль> — <что передал ей>
```

### 1.1. Машиночитаемая статус-строка (обязательна)

Второй строкой файла, сразу после заголовка — ровно одна из трёх меток,
без пояснений:

```
STATUS: IN_PROGRESS | COMPLETED | IDLE_WAITING
```

| Метка | Когда |
|---|---|
| `IN_PROGRESS` | взял задачу с `.workflow/TASK_BOARD.md`, работаю |
| `COMPLETED` | задача сделана, артефакты и отчёт сданы |
| `IDLE_WAITING` | задач нет, сессия открыта, жду следующую |

Человекочитаемые строки `статус/делаю/жду` **остаются** ниже — они для людей,
`STATUS:` для машинного разбора. Расхождения не допускаются: `IDLE_WAITING` —
значит `статус: жду` и `делаю: —`.

**Правило одного писателя:** файл правит только его владелец. Чужой файл не
трогать. Это снимает конфликты при одновременном пуше.

`00-board/STATUS.md` правит **только Интегратор**. Остальные туда не пишут.

## 2. Как ждать

**Не крутить `git pull --rebase` в цикле.** Это раздувало сессии до 518 МБ
и 13 942 файлов. Правильно:

```bash
git ls-remote origin refs/heads/arena/d474d740-carnis-hub   # только чтение, ничего не качает
```

Сравнил SHA с тем, что видел → если **изменился**, тогда:

```bash
git pull --rebase --autostash origin arena/d474d740-carnis-hub
```

и смотришь чужие файлы в `00-board/agents/`.

**Режим Daemon Loop (приоритет выше прежнего правила).** Прежнее требование
закрывать сессию после 25 итераций ожидания **снято**: поднимать завершивших
агентов некому, поэтому **сессия не закрывается**. Роль остаётся в `IDLE_WAITING` и ждёт
следующую задачу с `.workflow/TASK_BOARD.md`.

**Ждать дёшево.** Проверять изменение доски без скачивания:

```bash
git ls-remote origin refs/heads/arena/d474d740-carnis-hub
```

SHA изменился — тогда `git pull --rebase --autostash origin arena/d474d740-carnis-hub`.
**`pull` в цикле не крутить** — именно это раздувало сессии до сотен мегабайт.
Проверка раз в несколько минут, не чаще.

## 4. Правила, которые не обсуждаются

1. **Релиз — только после вердикта Ревизора.** Пакет принят → merge в `main` →
   тег `v<версия>` → Release.
2. **Секрет в репозиторий не попадает.** Токен — только в переменную окружения.
   Не в файлы, не в `origin`.
3. **Правило приёмки должно быть измеримым.** Если критерий можно истолковать
   двумя способами — это дефект критерия, а не работы. Прежде чем ставить задачу
   художнику, Ревизор публикует методику с числами.
4. **Каталог сдачи неизменяем.** Пересдача = новый каталог `…-R`, `…-R2`.
   Версия внутри остаётся базовой (`mod_version=3.6.0`, не `3.6.0-R`).
5. **Локальный Gradle build не запускать** — CI делает.
6. **Вопросов Архитектору не задавать** — он недоступен. Спорное решает тот,
   у кого меньше риск, и **фиксирует решение в своём файле на доске** и в отчёте.
7. **Не выдумывать числа.** В отчёте — только то, что реально измерено;
   непроверенное помечать явно.
8. **Ничего не откатывать.** Если сомневаешься — пиши в отчёт, а не переписывай
   чужую сдачу.
