# Почему 3.8.0 прошёл приёмку, хотя в нём есть дефект

Проверял после находки с порядком файлов. Здесь — граница нормы: что гейт
3.8.0 реально проверяет, а что принимает на веру. Всё измерено прогонами.

## 1. Гейт проверяет не весь пакет, а 33 новых

`tools/accept_3.8.0.py`, строка ~890: чекер вызывается с `--only` по списку
новых существ из реестра. В логе приёмки это выглядит так:

```
v пак существ: geo/UV/A3R1/Р-3/анимации — чисто, 33 существ (З-Г5)
```

Слово «чисто» относится к **33**, а в пакете **49** geo. Разница — 16 существ,
принятых ранее. Их никто не перепроверяет. Это осознанное решение (проверять
дельту, а не весь пакет заново), и оно верное по замыслу — но у него есть
следствие, которое я и нашёл.

## 2. `nerve_pillar` — дефект, который приёмка не видит

```
geo/block/nerve_pillar.geo.json   texture_width/height = 64 x 64
textures/block/nerve_pillar.png   16 x 64   (4 кадра по 16x16, .mcmeta)
UV кубов                          до 44 x 34
```

Модель объявляет полотно 64x64, а текстура — 16x64. UV до 44x34 при ширине 16
означает: правые 2/3 модели берут пиксели за пределами изображения. В игре это
растянутые/мусорные пиксели на рёбрах шипов.

Что делает приёмка 3.8.0 в этот момент:

```
· geo — у всех 16 комплектов:
   ✓ geo есть у всех 16
· блоки, предметы и броня (7 шт):
   ✓ nerve_pillar
```

Она проверяет **наличие файла**, а не его сходимость с текстурой. UV-аудит
(`creature_pack_audit`) к блокам не применяется: блок не в списке `--only`.

Проверил остальные шесть geo-блоков — у всех размер geo и PNG **совпадают**
(`hive_eye` 16x16/16x16, `pulsing_heart` 64x64/64x64, `pustule_cluster`
64x64/64x64, `bio_purifier` 64x64/64x64). `nerve_pillar` — единственный с
расхождением. Значит это не общая конвенция «16x64 — норма для анимированных
блоков», а единичная ошибка.

Ещё деталь: у Художника в `Gate_A_35_block_textures.zip` этот файл — **16x16**.
То есть 16x64 появилось позже, при нарезке анимации. Причина правки понятна
(анимация из 4 кадров), но `texture_width/height` в geo не обновили.

## 3. Что это значит для 3.8.1

Есть два разных вопроса, и их надо не смешивать:

**(а) Что проверяет приёмка.** Ей nerve_pillar безразличен: блок, не в `--only`,
UV к блокам не применяется. Пакет с ним проходит — и 3.8.0 прошёл.

**(б) Что видит игрок.** На шипах колонны — растянутые пиксели. Для блока,
на который смотрят вплотную, это заметно.

Я не чиню ни то, ни другое: `texture_width` — часть модели, её меняет Художник;
расширять UV-аудит на блоки — менять норму приёмки, это решение Архитектора.

## 4. Полный список расхождений, найденных за этот заход

| # | что | где | ловит ли приёмка 3.8.0 |
|---|---|---|---|
| 1 | нет `infected_spider_b`, `infected_creeper_b` | `04-artist/models/` | нет (их нет и в норме) |
| 2 | модели Художника — другой риг, 11 из 13 костей зомби не совпадают | `04-artist/` vs пакет | нет |
| 3 | glowmask Художника: фон чёрный непрозрачный, свечение циан | `04-artist/textures/` | нет (в пакете маски верные) |
| 4 | маски названы `_glow.png`, игра ищет `_glowmask.png` | `04-artist/textures/` | нет |
| 5 | 9 пар `.animation.json` с одним именем и разным содержимым | пакет 3.8.0 | нет — `setdefault`, лотерея |
| 6 | версии с `hurt`/`death` лежат в `animations/`, код грузит `animations/entity/` | пакет 3.8.0 | нет |
| 7 | 35 из 49 geo не подключены к java | пакет 3.8.0 | нет |
| 8 | `nerve_pillar`: geo 64x64, текстура 16x64, UV до 44x34 | пакет 3.8.0 | нет — печатает «✓» |

Пункты 5-8 — в **уже принятом** 3.8.0. Это не «сломалось в 3.8.1»; это было
принято и залито в релиз.

## 5. Что предлагаю

**Сначала инструменты, потом сборка.** Пока приёмка зависит от порядка файлов
в ZIP, любой вердикт по 3.8.1 ничего не стоит: тот же архив с другим порядком
даст другой ответ. Порядок действий, который я считаю правильным:

1. `setdefault` -> явный провал при двух файлах с одним именем и разным
   содержимым (пункт 5);
2. одна папка анимаций, и сверка с путём из кода (пункт 6);
3. UV-аудит применить и к geo-блокам, а не только к существам (пункт 8);
4. перепроверить 3.8.0 по полному списку, а не по дельте;
5. и только тогда возвращаться к вопросу «8 моделей».

Пункт 4 может дать ещё находки: 16 существ вне `--only` ни разу не проверялись
глубоким аудитом.

## Чего не делал

- не менял `texture_width` у nerve_pillar (это модель Художника);
- не расширял норму приёмки (это решение Архитектора);
- не правил чекер и не переупаковывал 3.8.0;
- не открывал новый тег и не трогал релиз.

## Приложение: граница «36 существ» проверена отдельно

Чтобы не путать два числа, прогнал чекер по явному списку 36 существ
(33 новых из реестра + зомби, скелет, паук, крипер):

```
Существ: 36, провалов: 0, предупреждений: 10
ИТОГ: СХОДИТСЯ
```

То есть **по тем, кого приёмка вообще смотрит, 3.8.0 действительно чист** — и
это не ошибка гейта. Ошибка в другом: 13 существ пакета (49 - 36) глубоким
аудитом не покрываются ни разу, и `nerve_pillar` как раз из непокрытых.

Поэтому формулировка «3.8.0 прошёл приёмку» верна и «в 3.8.0 есть дефект» тоже
верна. Они не противоречат друг другу: приёмка проверяет дельту, дефект — вне
дельты. Это нормальная инженерная ситуация, а не чья-то халатность; важно лишь
не считать «принято» синонимом «проверено всё».
