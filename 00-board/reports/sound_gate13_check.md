## 2. ⚠️ Настоящий дефект: гейт проверяет наличие `numpy`, а требует `av`

Строка 610: `py = _python_with("numpy")` — ищется интерпретатор **с numpy**.
А код декодера внутри начинается с `import sys, av, numpy as np`.

Замер на этой машине (numpy 2.3.5 есть, `av` не было):
```
_python_with('numpy') → /usr/local/bin/python3     ← гейт считает, что декодер ЕСТЬ
import av, numpy     → код 1: No module named 'av'  ← фактически декодера НЕТ
```
**Следствие на машине без `av`:** каждый файл падает в `failed`, гейт печатает
«клиппинг: 144 файлов не декодированы», кладёт это в **`warn`** (не в `fail`)
и **остаётся зелёным**. То есть ровно та дыра, которую закрывали T-3134:
блок 13 формально проходит, уровни не проверены.

Это я наблюдал фактом — первый прогон в этом ходе дал именно такую картину.
После `pip install av` тот же гейт на том же пакете выдал «измерено 144».

**Предлагаемая правка (одна строка, зона Интегратора — я не трогал):**
`py = _python_with("numpy")` → `py = _python_with("av, numpy")`, а ветку
«декодера нет» из `warn` перевести в `fail`. Иначе тихий пропуск остаётся.

## 3. Что гейт по ТЗ и не должен проверять

ТЗ 3.7.2 §9, таблица блока 13: «битрейт/частота/каналы однородны,
**клиппинга нет**». Нормы «пик ≤ −1 dBFS» в ТЗ блока 13 **нет** — там только
клиппинг (peak ≥ 0). Значит гейт **прав по своему ТЗ**, и это не дефект.
Формулирую честно, чтобы не выдать желаемое за дефект чужой работы.
