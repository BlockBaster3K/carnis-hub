**Пакеты:** 3.7.3 `8ef67394…` (как есть), scaffold `01-coder/3.8.0/` (коммит `625ba40`)
**Коммит Кодера в проверке:** `625ba40 build(coder): scaffold 3.8.0 from authorized base`

## 1. Сдача Кодера по scaffold 3.8.0 — заявление верно

Кодер заявил: «`01-coder/3.8.0/` — точная копия проектной основы 3.7.3, **762 файла, 0 различий**».
Проверил независимо: распаковал `project-3.7.3-clean.zip` (`8ef67394…`) в `/tmp` и сравнил деревья по sha256.

| проверка | заявлено | получено |
|---|---|---|
| файлов в scaffold | 762 | **762** |
| файлов в ZIP 3.7.3 | 761 | **761** |
| лишнее в scaffold | — | только `MANIFEST.txt` |
| недостающее | — | нет ни одного |
| различий по sha256 | 0 | **0** |

То есть scaffold = принятый пакет 3.7.3 байт-в-байт плюс один текстовый `MANIFEST.txt`. Архивные ZIP в scaffold не копировались — это верно и экономно.

**Мелкое замечание (не блокер):** `01-coder/3.8.0/MANIFEST.txt` — это **справка по 3.7.3**, первая строка: «Carnis 3.7.3 source scaffold — NOT PACKAGED». В каталоге 3.8.0 файл будет читаться как манифест 3.8.0. При упаковке 3.8.0 его надо перевыпустить, иначе реестр версий снова разойдётся.

## 2. Главное: scaffold наследует дефект громкости

`01-coder/3.8.0/src/…/sounds.json` содержит **те же** `detail_flow_01 = 0.731` и `detail_flow_02 = 1.0`.
Мой прогон на каталоге scaffold даёт **ровно те же три находки**, что на ZIP 3.7.3, включая
«правка УХУДШИЛА разброс пары — 7,71 → 10,43 дБ». Значит:

* если править только 3.7.3 — 3.8.0 родится с тем же дефектом, и его приёмка упрётся в ту же строку;
* правку `0.731 → 2.437` дешевле сделать **один раз в основе**, а затем пересобрать пакет.

## 3. Новый инструмент: `02-reviewer/tools/volume_semantics_audit.py`

Причина его появления — не «ещё одна проверка», а конкретный промах: пересборка `7cd55a2` прошла гейт **зелёной** (код 0, ПРИНЯТО), хотя баланс пары ухудшился на 2,72 дБ. Оба существующих инструмента баланса подключены отчётными, и один из них (`sample_loudness`) в принципе не видит режим: он смотрит только на **отношение** множителей, а оно при 0,731 и при 2,437 одинаково.

Инструмент читает только пакет и спеку, ничего не правит, и держит шесть каналов:

1. **Таблица по сэмплам**: `volume` в `sounds.json`, множитель `call_site`, эффективная громкость, цель.
2. **Двухрежимная сверка**: считает, какой из семантик пакет удовлетворяет — `json` (значение ключа = цель) или `effective` (`call_site × ключ = цель`). Если цель выполнена только в semantics, **противоположной** метке `targets_mode` — замечание «метка врёт, пакет верен» (со `--strict-label` — находка).
3. **Адресная подсказка**: для несоответствия печатается, какое значение ключа требуется в каждой семантике (`0.731` при «json» либо `2.437` при «effective»).
4. **Сторож половинчатой правки** (`--baseline <предыдущий пакет>`): цель требует изменить ключ, а ключ остался базовым → находка с перечислением, какие сэмплы события всё-таки изменены.
5. **Разброс по звуку** (`--baseline`): RMS самих `.ogg` + объявленные множители, до и после. Рост разброса больше `--worse-tol` (0,5 дБ) — находка. **Этот канал не зависит от семантики спеки вообще** — именно его не хватило.
6. **Абсолютный уровень**: берёт пик в dBFS, **заявленный прозой спеки** (`why`/`deviation`), и сверяет с фактическим пиком после множителей. Ловит случай «отношение выровнено, а событие заглушено».

Коды: `0` — сходится; `2` — находки; `3` — проверить нельзя (нет `sounds.json`, спеки или базового пакета).

**Самопроверка:** `02-reviewer/tools/volume_semantics_audit_selftest.py` — **7/7**. Фикстуры синтезируются на месте (два `.ogg` с разрывом 7,74 дБ, `sounds.json`, спека), покрыты: половинчатая правка, верный пакет, врущая метка (мягко/строго), заглушённое событие, отсутствие `sounds.json`, отсутствие спеки, пакет без звука.

## 5. Что прошу

1. **Кодеру** — `detail_flow_01: 0.731 → 2.437` **в основе `01-coder/3.8.0/`** и пересборка 3.7.3 из неё; `_02` и `call_site` не трогать. После правки мой инструмент должен дать код 0.
2. **Звуку/Архитектору** — снять `targets_mode: "json"` при эффективных числах (или переписать числа как `2.437/1.000`). Пока метка врёт, любой, кто читает спеку буквально, повторит ошибку 0,731.
3. **Интегратору** — подключить `volume_semantics_audit` к гейту **нормативным для событий, чьи ключи изменились** (отчётным для остальных). Это ровно та дыра, через которую прошла пересборка 0,731: гейт сказал «ПРИНЯТО», а баланс стал хуже.
