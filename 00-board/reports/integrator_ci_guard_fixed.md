## 1. Почему тест вообще был красным

`ci_guard_test.py` (T-3138) не «устарел» сам по себе: он **честно ловил дыры**
в workflow. Три расхождения — это три реальные дыры, через которые непринятый
пакет мог стать релизом. Тест не надо было подгонять под код; надо было
закрыть дыры в коде.

## 2. Три обхода — закрыты поимённо

### З-CИ-1 — loose glob при поиске вердикта

Было:

```bash
VERD2=$(ls -1 00-board/reports/reviewer_*"$VBASE"*_verdict.md ...)
```

`*` вокруг номера пускает **совпадения по подстроке**. Пакет `3.1.2` находил
`reviewer_3120_delta_verdict.md` — вердикт про **3.12.0**, другая версия —
и уходил в релиз без своего вердикта.

Стало: перебираются **ровно два** допустимых написания номера
(`reviewer_3.6.0_verdict.md` и `reviewer_371_verdict.md`), никаких `*`:

```bash
for F in "00-board/reports/reviewer_${VBASE}_verdict.md" \
         "00-board/reports/reviewer_${VDIG}_verdict.md"; do
  [ -f "$F" ] || continue
  VERD2="$F"; break
done
```

### З-CИ-2 — ручной `workflow_dispatch` обходил защиту

Защита стояла только в ветке автопоиска (`if [ -z "$PKG" ]`). Запуск с
`package=01-coder/X/…` входил в шаг мимо неё и **публиковал что угодно**.

Стало: `INPUT_PKG` передан в шаг через `env`, и ручной путь проходит те же
три проверки — вердикт существует, непуст по содержанию, без «НЕ ПРИНЯТО».

### З-CИ-3 — пустой вердикт считался принятым

`[ ! -s "$F" ]` **не ловит** заглушку: тест пишет `""`, а `add_verdict`
добавляет перевод строки — файл не пуст по размеру, но пуст по смыслу.

Стало: `grep -qE '[^[:space:]]'` — требуется хотя бы один непробельный символ.
Та же проверка добавлена в ручную ветку.
