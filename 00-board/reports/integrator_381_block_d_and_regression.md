# Блок D в гейте 3.8.1 + регрессия, внесённая звуком

## 1. Найдена дыра: Java проходит приёмку без проверки

Гейт 3.8.0 разрешает любые изменения `src/main/java/` флагом
`--allow src/main/java/` и **внутрь не смотрит**. Проверил:

```
grep -nE 'java|Entity' tools/accept_3.8.0.py   ->  проверки содержимого нет
verify_373_delta.py ... --allow src/main/java/  -> java проходят молча
```

Замер на 3.7.3 → 3.8.1:

```
.java 3.7.3: 228 | 3.8.1: 229
добавлено: 1 (CuriosSlotRegistration.java)
изменено:  1 (CarnisMod.java)
проверено по содержимому: 0
```

Сейчас это два файла. Но в 3.8.1 должны появиться **файлы 8 вариантов мобов** —
и они пройдут так же молча, даже если сошлются на несуществующую модель или
анимацию. В игре это молчаливый отказ: GeckoLib ничего не нарисует. Ровно тот
класс, что `_glow.png` вместо `_glowmask.png`.

## 2. Блок D: код не ссылается на отсутствующие ресурсы

Добавил в `tools/accept_3.8.1.py` четвёртый нормативный блок. Он разбирает
литеральные ссылки в java вида
`new ResourceLocation(..., "geo/entity/x.geo.json")` и сверяет с содержимым
пакета.

**Позитив** на реальном пакете 3.8.1:

```
D) Код не ссылается на отсутствующие ресурсы (§4d)
  .java файлов: 229 | ссылок на ресурсы: 50 | битых: 0
  v все 50 ссылок ведут в существующие файлы
```

**Негатив** — удалил `infected_spider.geo.json` из копии пакета:

```
  .java файлов: 229 | ссылок на ресурсы: 50 | битых: 1
    ✗ geo/entity/infected_spider.geo.json   <- InfectedSpiderGeoModel.java
  ✗ код ссылается на ресурсы, которых нет в пакете
    в игре это молчаливый отказ: GeckoLib ничего не нарисует
```

Указывает не только «есть битая ссылка», но и **какой файл** её содержит.

**Fail-closed** проверен в двух случаях:

```
нечитаемый пакет     -> «пакет не читается — проверка невозможна» -> провал
пакет без .java      -> «в пакете нет ни одного .java» -> провал
```

Второй важен: пустая проверка не имеет права выглядеть как успешная — это уже
ловилось в проекте на «Существ: 0, ИТОГ: СХОДИТСЯ».

**Чего блок НЕ делает:** не проверяет смысл кода, не компилирует, не заменяет
тесты. Только «ссылка ведёт в существующий файл».

## 3. Регрессия: 27 файлов Звука сломали приёмку УЖЕ ВЫПУЩЕННЫХ версий

Пока я работал, Звук залил 27 `.ogg` в канонический банк
`03-sound/sounds/entity/` (коммит `e17f833`). Банк стал 171 файл вместо 144.

Последствие — **не в 3.8.1, а в выпущенных версиях**:

| версия | было | стало |
|---|---|---|
| 3.7.3 | ПРИНЯТО | **ЕСТЬ РАСХОЖДЕНИЯ — 2** |
| 3.8.0 | ПРИНЯТО (на принятом пакете) | **ЕСТЬ РАСХОЖДЕНИЯ — 3** |

Причина одна и та же:

```
✗ банк: 27 файлов есть в хранилище, но НЕ в пакете
    entity/creeper_a_anchor.ogg
    entity/creeper_a_death_blast.ogg
    ...
```

Гейт сверяет банк с пакетом и требует, чтобы каждый файл банка был в пакете.
27 новых файлов вариантов — от 3.8.1, в пакетах 3.7.3/3.8.0 их быть не должно.
Формально гейт прав: в его модели «банк == пакет». Содержательно — это
переселение файлов будущей версии в канонический банк прошлых.

## 4. Что это значит

**Для Звука (это его решение, не моё):** 27 файлов нужно либо убрать из
канонического `03-sound/sounds/` и держать в `sounds_381/` до интеграции, либо
признать, что канонический банк — теперь «банк на все версии», и тогда норму
`банк == пакет` придётся менять для всех версий сразу. Первое безопаснее:
прошлые версии не должны переставать проходить приёмку из-за будущей работы.

Плюс отдельно: `MANIFEST_canon_144.txt` описывает 144 файла, в банке 171.
Манифест не пересчитан — гейт это тоже ловит («эталон устарел, S65»).

**Для меня:** я не трогаю файлы Звука и не правлю норму `банк == пакет`.
Пока 27 файлов лежат в каноне, ни 3.7.3, ни 3.8.0 не проходят приёмку —
то есть регрессия уже в дереве, и её видит любой, кто запустит гейт.
