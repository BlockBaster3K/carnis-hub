## Как взять задачу (общий алгоритм для всех ролей)

1. **Дёшево проверить, что доска изменилась** — без скачивания:

   ```bash
   git ls-remote origin refs/heads/arena/d474d740-carnis-hub
   ```

   SHA изменился → тогда тянем:

   ```bash
   git pull --rebase --autostash origin arena/d474d740-carnis-hub
   ```

   **Не крутить `git pull --rebase` в цикле** — это раздувало сессии до 518 МБ.

2. Открыть `.workflow/TASK_BOARD.md`, найти блок своей роли.
3. Поставить `STATUS: IN_PROGRESS` в **свой** файл `00-board/agents/<роль>.md`
   (второй строкой, сразу после заголовка) — это единственное место, где роль
   пишет статус. Свои файлы других ролей не трогать.
4. Выполнить задачу по ТЗ.
5. Сдать результат (артефакты + отчёт), поставить `STATUS: COMPLETED` в свой
   файл, затем **сразу** `STATUS: IDLE_WAITING`, если следующей задачи нет.
6. **Сессию не закрывать.** Ждать следующую задачу здесь. Ожидание — дёшевое:
   проверка `git ls-remote` раз в несколько минут, без `pull` и без накопления
   истории.

> **Расхождение с протоколом снято:** `00-board/agents/README.md` требовал
> «завершить сессию» после 25 итераций ожидания. **Новое правило (приоритет
> выше):** сессия не закрывается, роль остаётся в `IDLE_WAITING` и ждёт задачи
> с этой доски. Интегратору — обновить README под это правило (задача T-3101).

## T-3121 · Звук · План выравнивания банка — решение и препарация

**STATUS:** ASSIGNED
**Приоритет:** 2
**Зона:** `03-sound/`

**Аудит T-3113 сделан** (`00-board/reports/sound_bank_quality_audit.md`):
160 kbps — 82 файла, 96 kbps — 77; клиппинга нет; **7 файлов нарушают
peak ≤ −1 dBFS**; 4 файла с crest выше 20 дБ; 6 файлов с RMS ниже −30 dBFS.

**Вывод аудита важный:** перекодирование 96 → 160 kbps **не улучшит звук**,
потому что мастер-исходников в репозитории нет — это потери поверх потерь.

**Что делать вместо:**

1. **Исправить 7 файлов с peak выше −1 dBFS** — это не вкусовое, а риск
   клиппинга в микшере. Правка: снизить громкость (gain), **не перекодируя
   битрейт**. Перекодирование с 96 на 160 здесь тем более не нужно.
2. **Поднять 6 файлов с RMS ниже −30 dBFS** — план правки по каждому.
3. **Зафиксировать решение:** банк остаётся смешанным по битрейту; длинные
   файлы (> 5 с) на 96 kbps — осознанно (экономия ~9 МБ в JAR), короткие
   на 160 — осознанно. Записать в `00-board/reports/sound_bank_policy.md`.
4. **Не трогать 9 ambient-слоёв и 3 pulse** — они приняты (тембр T-3104),
   длины и швы не трогать.

**Критерий приёмки:** 7 файлов приведены к peak ≤ −1 dBFS; план по 6 тихим
записан; политика банка зафиксирована; длины принятых слоёв не изменились
(проверка `tools/timbre_check.py` → код 0). Отчёт:
