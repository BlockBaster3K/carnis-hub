# carnis-hub

Шина проекта **Carnis** — единая точка обмена артефактами между агентами
(Кодер, Ревизор, Звук, Художник, Архитектор) и единственным писателем
репозитория — **Интегратором**.

Репозиторий не является местом разработки: здесь лежат только **сдачи**
(иммутабельные), вердикты, акты приёмки, чистые снапшоты исходника
по версиям и указатели состояния. Сборка проекта идёт отдельно и
подключается только по команде Архитектора «ФАЗА 2».

## Префиксы коммитов

| Префикс | Кто |
|---|---|
| `[integrator]` | Интегратор — все коммиты в этот репозиторий |
| `[coder]` | Кодер (сдача передана Пользователем) |
| `[reviewer]` | Ревизор |
| `[sound]` | Звук |
| `[artist]` | Художник |
| `[architect]` | Архитектор (ТЗ, решения, вердикты) |

Файлы в репозиторий загружает **Пользователь через браузер**;
Интегратор файлы от других агентов напрямую не получает. Его зона —
приёмка, хеши и производные файлы (`VERIFICATIONS/`, `STATUS.md`,
отчёты), поэтому фактический автор коммита всегда `[integrator]`;
префикс исходного потока указывается в тексте коммита при
необходимости (например: `[integrator] architect: D1-D4 blockers spec`).

## Правила (5)

1. **Иммутабельность сдач.** Файлы сдач не изменяются и не удаляются
   никогда. Исправление = **новая папка версии** (`3.4.9-R2/`), старая
   остаётся на месте целиком.
2. **Никаких force-push и переписывания истории.** Только обычные
   коммиты (merge/squash допустимы), история `main` — линейный журнал
   приёмок.
3. **Без секретов и кэшей сборки.** В коммитах запрещены токены,
   пароли, ключи, а также `.gradle/`, `build/`, `run/`, `out/`, `.idea/`,
   `*.iml`, `*.class`, `logs/`, `*.log`. Gradle-wrapper
   (`gradle/wrapper/*`, `gradlew`, `gradlew.bat`) — наоборот, обязателен
   к коммиту, когда появится.
4. **Лимит 100 МБ на файл.** Файлы больше 100 МБ не принимаются;
   решение по ним — через GitHub Releases.
5. **Вердикты только по файлам и хешам.** Приёмка «на слово» не
   выдаётся: состав берётся из Git, `SHA256SUMS_*` пересчитываются,
   каждый пункт чек-листа проверяется пофайлово.

Дополнительно к правилам:

- **Единственный писатель** — Интегратор. Другие агенты не пушат в
  репозиторий напрямую; их материалы передаются через Пользователя.
- **Никаких решений задним числом**: акт приёмки `VERIFICATIONS/VERIFY_<папка>.md`
  фиксирует дату, состав с байтами, хеши, вердикт PASS/FAIL и список
  аномалий.

## Протокол приёмки (команда «проверь <папка>, чек-лист: …»)

1. **Состав** — список файлов (путь, байты) из Git.
2. **Хеши** — если есть `SHA256SUMS_*`: пересчитать `sha256sum` и
   сверить; любое расхождение = FAIL.
3. **Чек-лист** — каждый пункт отмечается есть/нет пофайлово. Если
   чек-лист не передан — фиксируется «чек-лист не предоставлен»,
   проверяются структура и хеши.
4. **Гигиена** — посторонние файлы, превышение лимита 100 МБ,
   запрещённое из правила 3 (в том числе в истории коммитов).
5. **Акт** — `VERIFICATIONS/VERIFY_<папка>.md`: дата, состав с байтами
   и хешами, вердикт PASS/FAIL, список аномалий.
6. **STATUS.md** — обновление таблицы потоков.
7. **Дайджест Пользователю** — короткая форма для Архитектора:

```
ДАЙДЖЕСТ <папка>
Принято: N файлов, X Б (состав в 3 строках)
FAIL/аномалии: … (или «нет»)
STATUS/VERIFICATIONS: обновлены
Ждём: …
```

## Статические проверки

Выполняются Интегратором, как только в репозитории появляются
соответствующие материалы; результат — в `VERIFICATIONS/` или
в дайджесте:

- валидность всех `.json` (`sounds.json`, языковые файлы) через
  `python -m json.tool` / `json.load`;
- паритет ключей `en_us.json` ↔ `ru_ru.json` (наборы ключей равны);
- совпадение версии в `gradle.properties` / `build.gradle` /
  `mods.toml` (актуально: **3.4.9**);
- инвентарь `.ogg` в репозитории × объявления `sounds.json`
  (сироты и отсутствующие — списком);
- отсутствие запрещённого из правила 3 в истории коммитов.

## 07-project/ — снапшоты исходника проекта

`07-project/` — чистые снапшоты исходника проекта по версиям
(`07-project/3.4.9/`, `07-project/3.4.9-R2/`, …), по одному
каталогу на версию. Внутри — только исходники и ресурсы: без
кэшей сборки (`.gradle/`, `build/`, `run/`, `out/`), без
секретов и кредов. Снапшоты иммутабельны: правка = новый каталог
версии.

Загрузку файлов в `07-project/` выполняет **Пользователь через
браузер**; Интегратор файлы от других агентов напрямую не
получает — его зона: приёмка, хеши, производные файлы
(`VERIFICATIONS/`, `STATUS.md`, отчёты).

Сборка `.jar` по этим снапшотам выполняется **только в ФАЗЕ 2**
и только по команде Архитектора; появление снапшота само по себе
сборку не запускает.

## ФАЗА 2 (только по команде Архитектора «ФАЗА 2»)

В репозиторий кладётся полный исходник проекта (код, ресурсы,
gradle-обвязка с wrapper) — чистой копией в
`07-project/<версия>/`. Далее: `gradle build` в среде Интегратора →
артефакт `.jar` в `06-build/` (или GitHub Releases) → отчёт сборки.
**До этой команды сборка не начинается.**

## Контакты и роли

- **Интегратор** — единственный писатель и верификатор репозитория;
  его отчёты и `STATUS.md` ведутся на русском, код и скрипты — на
  английском.
- **Архитектор** — принимает решения по дайджестам, ставит задачи
  потокам, отдаёт команды Интегратору через Пользователя.
- **Пользователь** — транспорт между агентами и владелец репозитория.
