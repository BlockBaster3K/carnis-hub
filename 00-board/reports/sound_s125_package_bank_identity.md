## 1. Как обошёл блок «нужен ZIP, а он раздувает память»

Три цикла подряд S1 и S3 стояли открытыми с пометкой «нужен ZIP 3.7.3;
`sparse-checkout add 01-coder` раздувает память до 125–139 МБ». Пометка была
честная, но вывод — ленивый: **файл из истории не нужно разворачивать в дерево.**

```
git show HEAD:01-coder/3.7.3/project-3.7.3-clean.zip > /tmp/pkg373.zip
```

Один blob, 12 631 366 байт, **0,1 с**, рабочее дерево не тронуто, sparse-набор
не менялся, память осталась **113 МБ**. Дальше ZIP читается `zipfile` прямо из
памяти, распаковывать не нужно вовсе.

**Урок общий:** «нужен материал вне sparse-набора» ≠ «надо расширять набор».
Для любых файлов из истории работает `git show`.

## 5. Чего в плане не было: пакет 3.8.0 собран из ДВУХ банков

Критерий приёмки волны 52 говорит «пакет == банк побайтово». Для 3.8.0 я его
проверил — и выяснилось, что буквальное прочтение неверно:

| сравнение | результат |
|---|---:|
| `.ogg` в пакете 3.8.0 (`33e332c5…`) | **276** |
| из них равны `sounds_380` (132 файла) | **132** |
| из них равны канону 3.7.3 (144 файла) | **144** |
| покрыто двумя банками | **276 из 276** |
| файлов в пакете, которых нет ни в одном банке | **0** |
| файлов с расхождением байт | **0** |

**Пакет 3.8.0 — надмножество: 144 канона + 132 новых.** Если бы кто-то проверял
«банк 3.8.0 == пакет» по каталогу `sounds_380`, он получил бы **132 из 276** и
решил, что 144 файла потеряны. Их не потеряли — они намеренно из канона.

## 6. Ссылки в `sounds.json` — 0 в обе стороны

```
событий 214 | уникальных ссылок 276 | файлов в двух банках 276
ссылок в пустоту: 0
файлов без события: 0
```

### Мой баг по ходу

Первый прогон дал «ссылок в пустоту 2» (`block/heart_pulse`, `block/pustule_burst`)
и одновременно «файлов без события 2» — **те же два**. Это был не дефект пакета,
а мой разбор: в `sounds.json` ссылка может быть **строкой**, а не словарём с
`name`. Я обрабатывал только словари, поэтому две строковые ссылки не попали в
множество. Симптом «два туда и два обратно, ровно те же имена» — и есть подпись
ошибки разбора, а не данных.
