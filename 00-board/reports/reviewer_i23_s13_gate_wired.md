## 2. Дефект: если JSON не прочитан, норма **молча ослабевает**

`_baseline_master()` при `OSError`/`ValueError` возвращает `{}` — то есть
«файла нет» и «файл битый» неотличимы от «записей нет». Дальше в блоке 12б:

```python
if typ == "стац" and src == "таблица":
    stationary_cand.append(...)   # ОТЧЁТ, не провал
```

**Прогон, доказывающий это** (та же популяция 132 файла, тот же пакет):

| | JSON на месте | `BASELINE_MASTER` → несуществующий путь |
|---|---|---|
| записей прочитано | 147 | **0** |
| сверено | 132 | 132 |
| стационарных в отчёте | 0 | **12** |
| **fail** | 0 | **0** |
| вердикт блока | ✓ 132 в норме | ✓ **132 в норме** |

Вывод в обоих случаях **зелёный**. Значит: удалить, переименовать или
испортить `03-sound/baseline_master.json` — и норма crest деградирует до
табличной **без единого сигнала в вердикте**. Это ровно тот класс, который
З-24 запретил («недостижимые события проходили незамеченными»), и прямое
нарушение З-29 п.5, где записано: нет записи в эталонной таблице → **гейт
падает**, а не «пропускает».

Риск не теоретический: в sparse-клоне без `03-sound/` (как у меня в начале
сессии) файла просто нет, и гейт на такой машине скажет «132 в норме».

**Правка (одна ветка, ~6 строк):**

1. `_baseline_master()` возвращает `None` при отсутствии/ошибке чтения файла —
   не `{}`.
2. В блоке 12б: `if _BM is None: fail.append("baseline_master.json не прочитан
   — норма crest не проверена (З-29 п.5)"); return`.
3. Стационарный файл **без** записи в JSON → `bad_crest` (провал), а не
   `stationary_cand` (отчёт). Отчёт допустим только пока переходный период;
   сейчас все 147 покрыты, значит отчёт уже не нужен ни для одного файла.
