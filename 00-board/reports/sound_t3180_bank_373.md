## П.1 — КРИТИЧЕСКАЯ ПОПРАВКА: мёртвых слотов нет

Я обязан начать с ошибки, которую сам же и допустил.

### Что я утверждал в T-3163

> «2 настоящих мёртвых слота — `block/heart_pulse`, `block/pustule_burst`
> (достижимость проверена по `sounds.json`, не по `.java`)»

**Это неверно.** Оба файла **подключены к событиям** — я потерял их при разборе
`sounds.json`.

### Причина — мой конкретный дефект анализа

В `sounds.json` Minecraft звук можно записать **двумя способами**:

```json
"sounds": ["carnis:block/heart_pulse"]                    ← строка
"sounds": [{"name": "carnis:block/heart_pulse", ...}]     ← объект
```

Я собирал множество используемых файлов **только из объектов**
(`isinstance(s, dict) and 'name' in s`). Строковых записей во всём файле ровно
**2** — и это ровно те два файла, которые я объявил мёртвыми.

Воспроизвёл свой дефект числом:

```
только объекты:    использовано 142 файлов
объекты + строки:  использовано 144 файлов
РАЗНИЦА: ['block/heart_pulse', 'block/pustule_burst']  ← объявлены «мёртвыми» ошибочно
```

Оба события записаны строкой:

```json
"pulsing_heart_beat": {"sounds": ["carnis:block/heart_pulse"]}
"pustule_burst":      {"sounds": ["carnis:block/pustule_burst"]}
```

### Доказательство в обе стороны

| Сторона | Проверка | Результат |
|---|---|---|
| `sounds.json` → файл | событие `pulsing_heart_beat` ссылается на `carnis:block/heart_pulse` | ✓ ссылка есть |
| `sounds.json` → файл | событие `pustule_burst` ссылается на `carnis:block/pustule_burst` | ✓ ссылка есть |
| код → событие | `PulsingHeartBlockEntity.java:171` и `FleshBulbBlockEntity.java:62` вызывают `ModSounds.PULSING_HEART_BEAT` | ✓ вызывается |
| код → событие | `PustuleClusterBlock.java:113` вызывает `ModSounds.PUSTULE_BURST` | ✓ вызывается |
| регистрация | `ModSounds.java:42` и `:156` — `registerVariableRangeSound(...)` | ✓ зарегистрированы |

**Итог: оба звука не просто объявлены, а проигрываются в игре из двух мест
каждый.** Никакого «решения по мёртвым слотам» не требуется — решать нечего.

### Почему это важно, а не косметика

Если бы я в T-3163 получил санкцию «удалить 2 мёртвых слота», я бы **удалил
два работающих звука** — сердце пульсирующего сердца и разрыв пустулы. Пакет
прошёл бы гейт (сирот 0 — ссылки в пустоту он бы поймал, но только если бы
файл убрали, а событие оставили; при удалении и файла, и события — не поймал
бы никто). Хорошо, что правило «не удалять без санкции» сработало.

**Мой прежний вывод «достижимость проверена» был ложным** — я проверял
`sounds.json` неполным разбором и не проверил `.java`. Записываю это как
дефект метода, а не как описку.
