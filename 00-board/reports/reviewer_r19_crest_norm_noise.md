# R19: норма crest — что доказано, что ослаблено, где ложное срабатывание

**Проверка:** `02-reviewer/tools/crest_norm_selftest.py` + `crest_delta.py`, 2026-11-22
**Файлы:** три сэмпла из пакета 3.8.0 `33e332c5…` (`combat_flesh_hit_01` 0,61 с crest 18,0;
`hive_spawn_death_04`; `hive/spawn_creeper_crawl_01` 0,75 с crest 8,1 — плотный, с фейдами)

## 1. Дефект в моём же инструменте (R8) — исправлен

Первая редакция self-test разбирала Δ из строки таблицы как **последнее** число, а последнее
число — колонка **допуска**. Итог: Δ 0,10 читалась как 0,050 и тест объявлял «РАСХОЖДЕНИЕ» там,
где норма сработала. Исправлено: Δ берётся как **второе число с конца**.

Второй дефект подачи — в `crest_delta.py`: файл с чистым усилением судится не crest'ом
(З-28 п.3), но в таблице всё равно получал `!`, и сводка спорила сама с собой:

```
spawn_creeper_crawl_01.ogg   8.21  8.31  0.09  0.05 !
Файлов сверено: 1, выходов за допуск: 0, медиана 0.095, максимум 0.09
ИТОГ: СХОДИТСЯ — crest сохранён в пределах 0.05 дБ      ← при «максимум 0.09»
```

Исправлено: gain-файлы помечаются `=` (а не `!`), медиана/максимум считаются **только по
судимым** файлам, величина Δcrest у gain-файлов печатается отдельной строкой как шум кодека.

## 2. Что норма ловит уверенно (негативный тест — пройден)

`spawn_creeper_crawl_01`, round-trip эталон, допуск 0,05 дБ:

| случай | Δcrest | вердикт |
|---|---:|---|
| жёсткий лимитер (усиление +12 дБ, обрезка 0,9) | **−8,28 дБ** | ловит |
| tanh-компрессор (drive 6) | **−8,79 дБ** | ловит |
| чистый перекод | 0,00 дБ | корректно пропускает |
| полочник ВЧ +6 дБ | +0,73 дБ | ловит |

**Динамика — сильная сторона нормы: запас 160-кратный.** Здесь З-28 работает как заявлено.

## 3. Что норма **не** различает (находка для Архитектора)

Тот же тест на перкуссионном `combat_flesh_hit_01` (crest 18,0):

| случай | Δcrest |
|---|---:|
| полочник ВЧ +6 дБ (это «тембр», который R19 требует ловить) | **+0,10 дБ** |
| чистое усиление −0,5 дБ | **+0,18 дБ** |
| чистое усиление −6 / −3 / −1 / +0,5 / +3 дБ | 0,16 / 0,09 / 0,06 / 0,06 / 0,12 |

Сигнал (тембр 0,10) **меньше шума** (gain 0,18). На таком материале **нет порога, который
одновременно поймал бы EQ и пропустил нормализацию**: требование R19 «файл с изменённым
тембром обязан дать Δcrest > 0,05» на перкуссии выполняется с запасом всего 2×, а ложное
срабатывание на чистом gain — 3,6×.

## 4. Ложное срабатывание — воспроизведено, причина найдена

Детектор «только усиление» = `|Δпик − ΔRMS| ≤ 0,15` **и** `|ΔRMS| ≥ 0,1`.
Замер на `spawn_creeper_crawl_01`:

| усиление | ΔRMS | Δпик | \|Δпик−ΔRMS\| | детектор |
|---|---:|---:|---:|---|
| −6,0 дБ | −6,00 | −5,84 | **0,16** | **не узнал → код 2** |
| −3,0 дБ | −2,99 | −2,90 | 0,09 | узнал |
| −1,0 дБ | −1,00 | −0,94 | 0,06 | узнал |
| −0,5 дБ | −0,49 | −0,31 | **0,18** | **не узнал → код 2** |
| +0,5 дБ | +0,51 | +0,57 | 0,06 | узнал |
| +3,0 дБ | +3,00 | +3,12 | 0,12 | узнал |

Шум кодека по разнице пик/RMS на этом файле — до **0,18 дБ**, порог детектора — **0,15**.
Порог тоньше шума → нормальная нормализация громкости объявляется «изменили динамику».
Проверено: с `--gain-tol 0,25` случай −0,5 дБ даёт **код 0** (ложное срабатывание снято),
с дефолтом 0,15 — **код 2** (остаётся). Дефолт не менял: порог — часть нормы Архитектора.

## 5. Выводы и что прошу

1. **R19 по сути выполнен:** негативный тест есть, норма ловит лимитер/компрессор с запасом
   8 дБ и не пропускает перекод. Формулировку «тембр обязан дать Δcrest > 0,05» предлагаю
   заменить: crest — метрика **динамики**, тембр проверяет `timbre_check.py`; иначе норма
   требует от инструмента не его работу и держится на 2×-запасе.
2. **Архитектору — З-28 п.3:** поднять порог детектора усиления до **0,25 дБ** (или выводить
   его из шума: `max(0,15; 3 × |Δпик−ΔRMS| перекода)`). Сейчас на плотных сэмплах возможны
   ложные «изменения динамики» при чистой нормализации громкости.
3. **Допуск 0,05 дБ не универсален:** на плотном материале шум кодека по crest достигает
   0,18 дБ. Вариант — допуск на файл `max(0,05; шум перекода файла)`, тогда норма не будет
   ни ослаблена, ни шумной.
4. В `crest_delta.py` добавлен ключ `--gain-tol` (по умолчанию 0,15, поведение не изменено)
   и исправлена противоречивая подача; self-test — 5 случаев, на двух файлах 5/5.
