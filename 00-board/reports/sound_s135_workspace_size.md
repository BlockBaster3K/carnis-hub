Присланная команда **в рабочем дереве не удалила ни одного файла**: под её шаблоны

Всё, что команда могла взять, лежало **вне репозитория**: `~/.cache` (99 МБ). Удалён —
это кэш скачанных колёс, восстанавливается сам. Проверено после удаления:
`deps_gate_check` → **6 из 6 на месте**, `imageio_ffmpeg` берёт ffmpeg из `site-packages`,
а не из кэша.

## До 128 МБ дойти нельзя — арифметика

| компонент | МБ | можно ли уменьшить |
|---|---:|---|
| `cn2/.git` | **133** | **нет** (см. ниже) |
| `cn2/01-coder` | 139 | только удалением версий — они tracked в git и нужны приёмке |
| `cn2/03-sound` | 48 | masters, банк, архивы перекрасок — материал в работе |
| `cn2/04-artist` | 19 | чужая зона |
| остальное | 9 | 00-board, tools, 02-reviewer, uploads |

**Минимально возможный размер — 133 МБ, и это один `.git`.** Цель 128 МБ недостижима даже
при полностью пустом рабочем дереве.

| сценарий | размер | влезает в 128 МБ |
|---|---:|---|
| как есть после чистки | 348 МБ | нет |
| удалить весь `01-coder` | 209 МБ | нет |
| удалить `01-coder` кроме 3.8.1 | 226 МБ | нет |
| удалить всё рабочее дерево | 133 МБ | **нет** |

## Почему `.git` не ужимается: репозиторий повреждён

`git gc --prune=now` и `git repack -a -d --window=250 --depth=50` **падают одинаково**:

```
fatal: bad tree object c3bed9cca6a3556fc0dbde73937e50eff92d4470
fatal: failed to run prune
```

Проверка пака: `pack-a32cc6c0….pack: bad` (131 МБ из 133). Причина — окружение за сессию
несколько раз откатывалось (HEAD уезжал с `aca81b8` на `f2ce9a1`, объекты `41e6e7d`,
`4a338ad`, `6b86cb1` становились «Not a valid object name»), и часть объектов pack-файла
осталась усечённой.

**Что это значит на практике:** я не могу ни ужать историю, ни гарантировать её целостность.
Удалять `.git` и клонировать заново **я не стал**: 22 untracked-файла и 17 МБ распакованного
`01-coder/3.8.1` (в git его нет вообще) при этом исчезнут безвозвратно — а это чужая работа
и единственная копия скаффолда 3.8.1 в этой файловой системе.

## Что ещё убрано безопасно

Снял свои же временные ref-ы от `fetch --depth=1`: `origin/tip`, `origin/tip2`, `origin/tip3`,
`origin/tip4`. Историю они не освободили (она в том же повреждённом паке), но это мусор
в ссылках, которого не должно быть в общем репозитории.

## Если 128 МБ — жёсткое требование

Единственный способ — **пересоздать `.git` заново** (свежий `git clone --depth=1`), и это
решение не моё, потому что цена:

1. пропадут 22 untracked-файла отчётов других агентов;
2. пропадёт распакованный `01-coder/3.8.1` (17 МБ), которого нет ни в git, ни в истории;
3. пропадёт локальная история, включая коммиты, которых нет на remote.

Оценка результата: свежий `clone --depth=1` даст ≈ 40–60 МБ `.git` + 139 МБ `01-coder`
= **около 200 МБ**, то есть **в 128 МБ всё равно не влезет**, пока в дереве лежат версии
3.5.0–3.8.1. Чтобы дойти до 128 МБ, придётся ещё и выбросить старые версии из `01-coder`,
а они tracked и нужны приёмке 3.7.3/3.8.0.

**Вывод: цель 128 МБ недостижима в этом дереве без удаления проектных данных.** Нужно либо
поднять лимит, либо дать санкцию на удаление версий 3.5.0–3.6.0 (или `01-coder` целиком).
