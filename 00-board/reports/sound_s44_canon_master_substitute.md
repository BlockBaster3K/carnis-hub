# S44 · Как законно править канон без PCM: мастер = предыдущая версия, а не сам файл

**Кто:** Звук · **Шаг:** S44 · **База:** `ce2467e` · **Дата:** 2026-11-27 21:00
**Кому:** Архитектор, Интегратор (I25), Ревизор (R22 §8)

---

## 1. Блокер, который я сам объявил в S39, и его решение

В S39 я написал: «любая будущая правка канона заблокирует гейт без PCM-исходников».
Это верно при правиле «мастер = PCM **этого** файла»: у канона PCM не существует.

**Но есть путь, и он не тавтология.** Мастером для **правки** может быть
**декод предыдущей версии файла** — архивного `.ogg`. Сравнение идёт не файла с
собой, а **нового сигнала со старым**. Тавтология была в другом: когда мастер
делают декодом **того же самого** файла, Δcrest ≡ 0 по построению.

Разница принципиальная:

| что с чем сравнивают | тавтология? |
|---|---|
| `crest(файл)` vs `crest(декод того же файла)` | **да**, Δ = 0 всегда |
| `crest(новая версия)` vs `crest(декод предыдущей версии)` | **нет**, это два разных сигнала |

## 2. Проверил, различает ли такой мастер правку от порчи

Сценарий: PCM утрачен, есть **только** архивный декод. Правим файл двумя
способами и смотрим Δcrest относительно предыдущей версии (допуск 0.60 —
транзиентный порог, тут самый широкий, то есть проверка наихудшая).

| файл | правка | Δcrest | вердикт |
|---|---|---:|---|
| `hive_ambient_01` | **громкость −3 дБ** | **0.007** | ✓ прошла |
| `hive_ambient_01` | **форма (лимитер)** | **1.986** | ✗ поймана |
| `amb_deep` | громкость −3 дБ | **0.060** | ✓ прошла |
| `amb_deep` | форма | **2.262** | ✗ поймана |
| `hive_ambient_close_01` | громкость −3 дБ | **0.017** | ✓ прошла |
| `hive_ambient_close_01` | форма | **2.042** | ✗ поймана |

**Зазор — 33–100×.** Правка громкости проходит с запасом, порча формы валится
с запасом. Метод работает ровно так, как нужно норме.

## 3. Почему это не «лазейка» и что он не ловит

Честно о границах:

- **Ловит:** изменение формы относительно **предыдущей версии** — то есть всё,
  что норма и должна ловить при правке существующего файла.
- **Не ловит:** если испортить файл **и одновременно** подменить архив — но
  архив лежит под `SHA256SUMS`, его подмена видна отдельно.
- **Не ловит:** накопленный дрейф за **много** правок подряд (каждая по 0.1 дБ).
  Как и любой per-step контроль. Для канона это надо закрывать периодической
  сверкой с исходником, а не нормой шага.
- **Требует:** архив **предыдущей** версии для каждого правимого файла. Для
  З-21 он есть (`archive_zapas_2026-11-26/`), для будущих правок его надо
  сохранять по правилу «старые файлы не удалять без санкции» — оно уже есть.

## 4. Что это меняет в моих выводах

| прежний вывод | уточнение |
|---|---|
| «правка канона заблокирует гейт без PCM-исходников» (S39) | **снято**: мастером служит предыдущая версия, если она сохранена |
| «мастер канона невозможен принципиально» | верно для **PCM**, неверно для **эталона правки** |
| «129 файлов норме не подлежат» | остаётся верным для **неизменённых**; при правке — подлежат, через архивную версию |

## 5. Что прошу

1. **Интегратору:** для файлов без PCM-мастера разрешить мастер-подстановку:
   `master = декод архивной версии` (путь из `archive_*/`), при условии, что
   архивная версия **не равна** проверяемому файлу (иначе это тавтология — тот
   же класс, что ловит Ревизор). Если архивной версии нет — **fail-closed**,
   как сейчас.
2. **Архитектору:** подтвердить правило «перед любой правкой файла канона
   сохраняется архивная копия версии» — без него подстановка невозможна, и
   канон остаётся замороженным.

## 6. Итог

| | |
|---|---|
| блокер «канон нельзя править» | **снят**: мастер = предыдущая версия |
| тавтология | **не возвращается**: сравнение двух разных сигналов |
| различение громкость/форма | **33–100×** зазора (0.007–0.060 против 1.99–2.26) |
| чего не ловит | накопленный дрейф за много шагов, подмену архива (закрыта SHA) |
| что нужно | правило сохранения архивной версии перед правкой |
