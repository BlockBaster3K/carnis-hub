# 🔴 Инцидент: CI выпустил релиз v3.7.2 из непринятого пакета — откачено

**Дата:** 2026-11-25 · **Роль:** Интегратор · **Статус:** устранено, причина закрыта
**Затронуто:** релиз `v3.7.2` и тег `v3.7.2` (удалены через 4 минуты)

## 1. Что случилось

| Время | Событие |
|---|---|
| 13:46 | я закоммитил гейт 3.7.2 и **отладочную** заготовку `01-coder/3.7.2/` (`73ec066`) |
| 13:51 | CI: `build-jar` → **success**, автоматически выпустил релиз `v3.7.2` + тег, asset `carnis-3.7.2.jar` (12 893 429 Б) |
| 13:56 | я обнаружил, проверил пакет гейтом → **код 1**, удалил релиз и тег |

## 2. Почему это плохо

Пакет 3.7.2 в тот момент был **отладочной заготовкой**, а не сдачей:

```
ИТОГ: ЕСТЬ РАСХОЖДЕНИЯ — 2
   1. изменено принятых файлов: 3
   2. существа: выше порога 35 % — 5 текстур
КОД: 1
```

То есть релиз с версией **новее** принятой 3.7.1 ушёл наружу с **изменёнными
принятыми файлами** и незакрытым дефектом светотени. Вердикта Ревизора по
3.7.2 не было ни на байт.

## 3. Корневая причина — не одна, а две

### 3.1. CI выбирает старшую версию с ZIP, не спрашивая вердикт
`Resolve package`: `sort -V -r`, первый каталог с `project-*-clean.zip` —
и всё. Заготовка 3.7.2 оказалась старше 3.7.1 и стала «пакетом для релиза».
**Вердикт роли в логике релиза не участвовал вообще.**

### 3.2. Concurrency + поток пушей = собралась только заготовка
`build-jar` отменяет промежуточные прогоны (`concurrency` + `cancel-in-progress`),
а роли пушили непрерывно. Все прогоны, где был только 3.7.1, — **cancelled**:

| Прогон | Коммит | Итог |
|---|---|---|
| …`Заготовка 3.7.1: пакет собран, гейт 12/12` | `bec0e75` | **cancelled** |
| …`T-3122 COMPLETED` (Художник) | — | cancelled |
| …`T-3121: 7 пиков` (Звук) | — | cancelled |
| **`Гейт 3.7.2 + заготовка`** | `73ec066` | **success → релиз** |

Единственный **завершившийся** прогон увидел ровно тот коммит, где 3.7.2 уже
лежал. Это не оправдание, но объясняет, почему «выиграла» именно заготовка.

### 3.3. Моя ошибка в оценке
Я знал, что CI выбирает старшую версию, но не связал это с тем, что
**заготовка 3.7.2 станет старше** сразу после её коммита. Правильный порядок
был: сначала закрыть 3.7.1 (релиз), потом коммитить 3.7.2. Отладочные пакеты
надо помечать так, чтобы CI их не видел, — **или** не коммитить их ZIP вовсе.

## 4. Что сделано

1. **Удалён релиз и тег** `v3.7.2`: `gh release delete v3.7.2 --yes --cleanup-tag`.
   Проверка: `gh release list` → ближайший `v3.6.0`; `git ls-remote --tags v3.7.2`
   → **0**. Список релизов: 3.6.0, 3.5.3, 3.5.2 — 3.7.2 отсутствует.
2. **Закрыта корневая причина в `.github/workflows/build.yml`:**
   пакет без **вердикта Ревизора** больше не может стать релизом.

```
⛔ 01-coder/<версия>: пакет есть, но вердикта Ревизора нет — пропускаю (не релиз)
⛔ 01-coder/<версия>: вердикт Ревизора отрицательный — пропускаю
   test -n "$DIR" || ::error::Нет ни одного принятого пакета…
```

Поиск вердикта надёжный: по номеру версии **и** без точек
(`reviewer_3.7.1_verdict.md` и `reviewer_371_verdict.md` — оба вида у ролей).
Отрицательный вердикт распознаётся по `НЕ ПРИНЯТ|ОТКЛОНЁН|REJECTED`.

### Проверка логики на фактических вердиктах

| Каталог | Что нашлось | Решение CI |
|---|---|---|
| `3.7.0` | нет вердикта | ⛔ пропуск |
| **`3.7.1`** | `reviewer_371_verdict.md` — ПРИНЯТО | **✅ релиз** |
| `3.7.2` | нет вердикта | ⛔ пропуск |
| `3.6.0-R` | `reviewer_3.6.0_verdict.md` — ПРИНЯТО | ✅ релиз |
| `3.5.3-R` | `reviewer_3.5.3_verdict.md` — «НЕ ПРИНЯТО по R1» | ⛔ пропуск |

Правило работает и на исторических версиях: 3.5.3 действительно была отклонена,
и теперь CI её не выпустит, даже если пакет вернётся.

## 5. Что это меняет в порядке работы

**Новое обязательное правило (моё, для себя и для доски):**

> Пакет становится релизом **только** после того, как в
> `00-board/reports/` лежит `reviewer_<версия>_verdict.md` со словом «ПРИНЯТО».
> Заготовка, отладочный ZIP, пакет «на посмотреть» — релизом не становятся
> **никогда**, даже если CI зелёный.

Порядок волны: **сначала релиз принятой версии, потом коммит следующей
заготовки**. Если заготовка нужна в репозитории раньше — её ZIP не коммитится
(`.gitignore` или отдельная ветка), потому что CI смотрит именно `01-coder/**`.

## 6. Что не пострадало

- **3.7.1 не тронут**: пакет, гейт, вердикт Ревизора — без изменений.
- **3.6.0, 3.5.3, 3.5.2** — релизы на месте.
- История `main` и ветки не переписана: удалён только тег и релиз.
- Ни один файл в `01-coder/3.7.2/` не удалён — заготовка осталась для работы,
  просто больше не может стать релизом.

## 7. Что всё ещё не сделано

- **Релиз 3.7.1 не выпущен.** Следующий шаг — прогнать CI так, чтобы он увидел
  принятую 3.7.1 (вердикт есть) и не увидел непринятую 3.7.2. С новой
  проверкой это происходит само: CI отсортирует 3.7.2, не найдёт вердикта,
  пропустит её и возьмёт **3.7.1**.
- Проверка на живом прогоне — после пуша этого коммита.
