# 00-board — доска приказов

**Доска приказов — единственное место, где агент берёт задание и куда сдаёт отчёт. Промпты через чат больше не передаются.**

**Версия в работе:** 3.5.2 закрыта, готовится 3.5.3 · **Ветка:** `arena/d474d740-carnis-hub`
**Создано:** Интегратором, 2026-11-25 · **Наполняет:** Архитектор

> ⚠️ **Статус наполнения:** файлы `ROADMAP*.md` и `STATUS.md` — **заглушки**. Рабочие задачи в них пишет **Архитектор**. Пока в выжимке вашей роли нет задач — брать нечего, ждите. Не выдумывайте себе задание по чужим файлам.

---

## 1. Что такое доска

Доска приказов — единственное место, где агент берёт задание и куда сдаёт отчёт; промпты через чат больше не передаются.

Заказчик больше не перекладывает задания руками: он только **запускает** агентов. Задание каждый агент находит сам — в своей выжимке на доске. Отчёт пишет туда же, на доску.

Это меняет одну вещь, к которой надо привыкнуть: **никто не скажет вам в чат, что делать.** Если вы не прочитали доску — вы не начали работу.

---

## 2. Как взять задание

Порядок обязательный, оба шага. Пропустить первый — значит читать устаревшую доску.

```bash
git pull --rebase origin arena/d474d740-carnis-hub
cat 00-board/ROADMAP_<ваша_роль>.md
```

Роли и их файлы:

| Роль | Файл выжимки |
|---|---|
| Кодер | `00-board/ROADMAP_koder.md` |
| Ревизор | `00-board/ROADMAP_reviewer.md` |
| Художник | `00-board/ROADMAP_artist.md` |
| Звук | `00-board/ROADMAP_sound.md` |
| Архитектор | `00-board/ROADMAP.md` (полный план) |
| Интегратор | `00-board/ROADMAP.md` (полный план) + `00-board/STATUS.md` |

**Почему `git pull --rebase` — не формальность.** Клон делается с `--depth 1`, и без обновления вы читаете доску на момент клонирования. За время между запусками агентов Архитектор мог дописать задачи, а другая роль — сдать файлы. Устаревшая выжимка = работа не по той волне.

Тот же `git pull --rebase` — **перед каждой сдачей**, иначе push отклонится (при параллельной работе агентов это норма, а не ошибка).

## 3. Куда писать отчёт

**Путь:** `00-board/reports/<роль>_<что_сделано>.md`

Примеры:

```
00-board/reports/koder_3.5.3_package.md
00-board/reports/reviewer_3.5.3_verdict.md
00-board/reports/sound_wave29_heart.md
00-board/reports/artist_3.5.3_icons.md
00-board/reports/integrator_wave29_accept.md
```

**Правила:**

- **один отчёт = одна сдача** (не сваливайте две волны в один файл);
- имя содержит **роль** и **дату** либо версию — чтобы было видно, к чему отчёт;
- отчёт — это **файл в репозитории**, а не сообщение в чат;
- крупные артефакты (пакеты, .ogg, .png) в `reports/` **не кладутся** — они идут в зону роли, отчёт только ссылается на пути и хеши.

Отчёт без хешей и без путей — не отчёт. Проверяющий будет сверять по файлам, а не по формулировкам.

> ***Отчёт обязателен. Работа считается законченной, когда в репозитории лежат одновременно: (1) артефакты в зоне роли, (2) отчёт*** `00-board/reports/<роль>_<тема>.md`***. Отчёт — файл в репозитории, а не сообщение в чат. Обязательны: путь к каждому артефакту, SHA-256, числа проверок, строка «что осталось непроверенным». Отчёт без хешей и без путей — не отчёт. Нет отчёта — работа не закрыта, волна не идёт дальше.***

## 4. Кто что пишет — таблица прав

**Все читают всё, но каждый правит только свой участок.**

`00-board/` — общая зона чтения. Право записи в неё разделено: выжимки и `STATUS.md` принадлежат Архитектору, `reports/` — каждому агенту.

| Кто | Что читает | Что пишет |
|---|---|---|
| **Кодер** | всё | `01-coder/<версия>/`; отчёт — `00-board/reports/`. **`ROADMAP_koder.md` не правит** |
| **Художник** | всё | `04-artist/`; отчёт — `00-board/reports/` |
| **Звук** | всё | `03-sound/`; отчёт — `00-board/reports/` |
| **Ревизор** | всё | `02-reviewer/`; отчёт — `00-board/reports/` |
| **Интегратор** | всё | `06-build/`, `07-project/`, `VERIFICATIONS/`, `STATUS.md`, `.github/`; отчёт — `00-board/reports/` |
| **Архитектор** | всё | `05-architect/`, `00-board/ROADMAP.md`, `00-board/ROADMAP_<роль>.md`, `00-board/STATUS.md` |

### Ключевое правило

> ## Все читают всё, но каждый правит только свой участок.
> ## Правку чужой зоны — в отчёт и ждать решения Архитектора.

Не «поправил заодно». Не «там же одна строка». Файл, лежащий в чужой зоне, — это чужая ответственность, и правка в нём обнуляет чужую проверку. Заметили ошибку в чужой зоне — пишете в отчёт: что не так, где, почему. Правит владелец.

**Про `00-board/README.md` (этот файл).** Он принадлежит Интегратору по этой задаче — правила доски. Файл, однако, **общий контракт**, поэтому изменить его в одиночку нельзя: предложение по правке — в отчёт, решение — за Архитектором.

---

## 5. Порядок работы волны

```
Архитектор → приказы в доске
     ↓
Кодер + Художник + Звук        (параллельно, каждый по своей выжимке)
     ↓
Ревизор                        (проверяет по факту, не по отчётам)
     ↓
Интегратор                     (приёмка → CI → merge в main → релиз → акты)
```

### Правило ожидания

- **Ревизор начинает только тогда, когда пакет Кодера физически лежит в репозитории.** Не по отчёту, не по обещанию — по файлам в `01-coder/<версия>/`.
- **Интегратор начинает только после вердикта Ревизора** в `02-reviewer/`.
- **Никто не выносит вердикт «по отчёту».** Вердикт — это результат сверки с файлами.

Нарушение порядка стоит дорого: приёмка по отчёту пропускает дефект в сборку, а дефект в сборке стоит прогона CI и 12 МБ истории навсегда.

## 6. Handshake — отчитаться, не начиная работу

Перед началом работы каждый агент **обязан прочитать доску и отчитаться**, работу **не начиная**.

Формат отчёта:

```
00-board/reports/<роль>_handshake.md
```

Содержание:

```markdown
# Handshake — <роль>

- Прочитал: `00-board/ROADMAP_<роль>.md`
- Коммит, на котором читал: <полный или 7-символьный хэш>
- Задача понята: <одна-две строки своими словами, что требуется>
- Готов приступить: да
- Вопросы к Архитектору: <если есть, иначе «нет»>
```

**Хэш коммита обязателен.** По нему видно, что все агенты читали одну и ту же версию доски. Если у двух агентов хэши разошлись — они работают по разным волнам, и это надо поймать до начала работы, а не после сдачи.

Хэш берётся так:

```bash
git pull --rebase origin arena/d474d740-carnis-hub
git rev-parse HEAD
```

Работу начинать **после** отчёта handshake. Не наоборот.

## 7. Свежесть

- `git pull --rebase` — **перед каждым чтением доски**;
- `git pull --rebase` — **перед каждой сдачей**;
- при отклонённом push — не форсировать, а `git pull --rebase` и повторить;
- сдавать — через `tools/agent_push.sh` (сам делает rebase при non-fast-forward):

```bash
bash tools/agent_push.sh arena/d474d740-carnis-hub \
  "[роль] <краткое описание>" <путь>
```

**Зоны и предупреждения.** Скрипт печатает предупреждение, если затронуты зоны Интегратора (`STATUS.md`, `VERIFICATIONS/`, `06-build/`, `07-project/`, `.github/`, `README.md`). Для отчётов это нормально; для правки — нет, см. §4.

**Что запускает CI.** Прогон сборки стартует только от изменений в `01-coder/**`, `03-sound/**`, `04-artist/**`, `06-build/overlay.txt`. Пуш в `00-board/**`, `02-reviewer/**`, `05-architect/**`, `VERIFICATIONS/` и документацию **прогон не запускает** — прогоны не тратятся.

## 8. Структура доски

```
00-board/
├── README.md                 ← этот файл: правила
├── ROADMAP.md                ← полный план работ по версиям (заполняет Архитектор)
├── STATUS.md                 ← сводка: кто что делает сейчас, что сдано (заполняет Архитектор)
├── ROADMAP_koder.md          ← выжимка задач для Кодера (заполняет Архитектор)
├── ROADMAP_reviewer.md       ← выжимка задач для Ревизора (заполняет Архитектор)
├── ROADMAP_artist.md         ← выжимка задач для Художника (заполняет Архитектор)
├── ROADMAP_sound.md          ← выжимка задач для Звука (заполняет Архитектор)
└── reports/                  ← отчёты агентов (пишут сами агенты)
    └── .gitkeep
```

Имена каталогов и файлов — **ровно такие**, как выше. На них ссылаются промпты остальных ролей. Менять нельзя: переименование сломает чужие задания молча.

---

## 9. Чего на доске не делается

- **Не приёмка пакетов.** Доска — про задания и отчёты; приёмка живёт в `VERIFICATIONS/` у Интегратора.
- **Не обсуждение.** Вопрос к Архитектору — строкой в handshake-отчёте, не переписка в `reports/`.
- **Не переписывание чужой выжимки.** Не согласны с задачей — в отчёт, решает Архитектор.
- **Не секреты.** Ни токенов, ни ключей, ни ссылок с учётными данными — ни в отчётах, ни в выжимках. Токен приходит агенту извне и в репозитории не живёт.
