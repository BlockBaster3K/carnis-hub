# Интегратор: размер glowmask не сверялся с телом — доказано контролем и закрыто

**Дата:** 2026-11-26 · **Находка:** Ревизор (`4732f37`,
`reviewer_glowmask_two_standards.md`) · **Правка:** блок 14 в обоих гейтах

## 1. Что нашёл Ревизор и что из этого моё

Ревизор разобрал glowmask и нашёл две вещи:

1. **В проекте два стандарта свечения.** В принятом пакете 3.7.3 девять масок
   `*_glowmask.png`: ровно два цвета, прозрачный фон, оранжевый
   `(255,92,57)`. У Художника четыре маски `_glow.png`: непрозрачный чёрный
   фон, циан `(0,255,255)`. Он следует **своему** регламенту
   (`BENCHMARK_RULES.md`, правило 9 — «неоновый циан»), а гейт требует
   оранжевый. Это вопрос к Архитектору, не ко мне: менять норму с одной
   стороны спора я не стану.
2. **`check_glow9` не сверяет размер маски с текстурой.** Вот это — моё.

## 2. Доказательство дыры (до правки)

Не поверил на слово: собрал подлог. Взял канон 3.7.3 и сделал текстуру
`infected_skeleton` 64×64 (именно такую Художник нарисовал в rev4), оставив
принятую маску 64×32. Прогнал блок 14:

```
✓ infected_skeleton    цветов 2 (прозрачный + 255,92,57)
свечение: мобов 9, в норме 9, без glowmask 0, вне палитры 0
fail: []
```

**Девять из девяти «в норме», провалов ноль.** Причина: блок проверял только
палитру. Конвенция у маски правильная (два цвета, прозрачный фон) — поэтому
палитра молчит, а UV уезжают: маска 64×32 ложится на верхние две трети тела
64×64, и свечение окажется не там, где задумано. Глазами в пакете это
неотличимо от нормы.

## 3. Почему это класс, а не случайность

В гейте **3.8.0** та же проверка размера в блоке 16 (`check_new_creatures`,
З-Г5(B)) **есть** — «маска 8×8 при теле 64×64 — свечение где-то в углу».
То есть в одном блоке того же файла норма сформулирована правильно, а в блоке
14 — нет. Ровно тот класс дефекта, который я искал прошлыми импульсами
(«проверка есть, гейт её не зовёт», «охват уже названия»), только здесь —
«проверка есть в соседнем блоке, а в этом её нет».

## 4. Что сделано

Добавил в `check_glow9` **обоих** гейтов сверку размера маски с телом, с
fail-closed при отсутствии тела:

```python
body = os.path.join(base, mob + ".png")
if not os.path.exists(body):
    extra.append((mob, "нет тела")); continue     # сверить не с чем
bsz = Image.open(body).convert("RGBA").size
if im.size != bsz:
    extra.append((mob, "размер %dx%d != тело %dx%d" % (...))); continue
```

Отдельно поправил **формулировку** провала: раньше все причины шли через
«цвета вне палитры %s», и провал по размеру звучал как провал по цвету. Теперь:

```
свечение Р-3: infected_skeleton — размер 64x32 != тело 64x64
```

Это не косметика: с прежней формулировкой разбор ушёл бы искать цвет, а не
размер, — то есть отчёт направил бы читателя не туда. Я уже наступал на это с
«2092 px вне силуэта».

## 5. Проверка (три прогона)

| прогон | что ожидалось | факт |
|---|---|---|
| подлог (тело 64×64, маска 64×32) | блок 14 падает | **✗ поймано**, `fail` непустой |
| канон 3.7.3, гейт целиком | код 0, 9/9 в норме | **код 0**, «свечение: мобов 9, в норме 9» |
| гейт 3.8.0 без пакета | код 2 | **код 2** (пакета нет — корректно) |

Канон остаётся зелёным, потому что в нём **все девять масок совпадают по
размеру с телами** — проверил отдельно, 0 расхождений. То есть правка ничего
не «сломала под норму», она закрыла путь дефекту, которого сейчас нет.

## 6. Чего не делал

**Не трогал вопрос о двух стандартах свечения.** Это спор Архитектора с
Художником; моя часть — чтобы гейт ловил **обе** ошибки (цвет и размер), а не
решал, какой цвет правильный. Ревизор предложил оставить отгруженный
(оранжевый) — присоединяюсь к тому, что норма должна быть одна, но выбор за
Архитектором.

**Не правил `glowmask_r3_check.py` Художника.** Его чекер падает на его же
файлах по цвету и по `outside`; я это уже описал в §4б предыдущего отчёта.
Чужой инструмент правит его автор.
