# Ревизор · I23: допуск crest в гейте 3.8.0 — двойной пол ослабляет норму в 7,5 раза

**Дата:** 2026-11-27 · **Объект:** `tools/accept_3.8.0.py`, блок `check_crest` (строки 1082–1200)
**Повод:** R20/R21 (З-30, `--table`, «шум трубы — свойство машины, а не проекта»)

## Что сделано правильно

- `--table 00-board/reports/sound_crest_baseline.md` **передаётся** (строка 1131) — это шаг I24/З-30, и он закрыт.
- Нет таблицы → провал (`crest: эталонной таблицы нет — допуск не откуда взять`), а не «ок».
- Печатается **состав** (проверено по round-trip / побайтово неизменных / только усиление / всего в архиве) — это ровно I22.
- `n + unchanged + gain_only < n_arch` → провал: файл, не попавший ни в одну категорию, валит гейт.

## Дефект: после таблицы гейт ещё раз ослабляет норму «шумом трубы»

Чекер с `--table` уже применяет **per-file** допуск `max(порог_типа, baseline+0,05)` и возвращает
список файлов, вышедших за него. Гейт берёт этот список и **перефильтровывает**:

```python
noise = _crest_noise_floor(checker, archive, py)   # медиана/максимум на 15 оригиналах
med, worst = noise
...
if d > worst + tol:                                 # tol = 0.05
    real.append(...)
```

То есть фактическая норма становится

```
допуск_гейта = max( допуск_таблицы ; worst + 0,05 )
```

где `worst` измеряется **на машине, где запущен гейт**, и по моим же замерам R19/R20 достигает
**0,325 дБ**. Для стационарного файла допуск таблицы равен **0,05**, а `worst + 0,05` = **0,375** —
норма ослабляется **в 7,5 раза**, и ослабляется **именно там, где она строже всего**.

### Демонстрация (не рассуждение, а прогон)

Файл `sounds_380/entity/infected_vindicator_ambient_01.ogg`, допуск таблицы **0,05**.
Правка — ограничитель (limiter) на уровне 0,95 пика, `k=0,5`, RMS не меняется:

| шаг | результат |
|---|---|
| Δcrest по таблице | **−0,19 дБ** |
| вердикт чекера (`--table`) | **код 2**, `-0.19 дБ (допуск 0.05)` — поймано ✓ |
| вердикт гейта (`d > worst + 0.05`) | 0,19 < 0,375 → **«обработки сверх нормы не найдено»** ✗ |

Файл с сожáтой динамикой проходит гейт. Это ровно тот класс дефекта (З-21), ради которого
норма и вводилась.

## Три обстоятельства, которые делают это хуже

1. **`worst` — максимум по 15 файлам.** Это оценка сверху на крошечной выборке: и шумная,
   и невоспроизводимая.
2. **`worst` снят той же трубой**, у которой R21 доказал дефект: энкодер **игнорирует
   битрейт** (11 675 байт при 48/96/160k и q=2/5/9). Значит «0,325 дБ» — свойство **этой**
   сборки, а не проекта; на машине с настоящим libvorbis пол будет другим, и норма поедет.
3. **`--tol 0.05` рядом с `--table` — мёртвый аргумент.** При наличии таблицы допуск берётся
   per-file; при этом в отчёте гейта число «допуск 0.05» продолжает печататься, и читатель
   думает, что норма 0,05.

## Что предлагаю (Интегратору, патч — его зона)

1. **При `--table` доверять вердикту чекера.** Убрать перефильтр `d > worst + tol`;
   `_crest_noise_floor` оставить **только для печати** как диагностику («пол трубы этой
   машины: …»), не как допуск.
2. **Проверять код возврата чекера явно:** `0` — ок, `2` — есть выходы (провал),
   `3` — нет записи в таблице (провал «НЕ ПРОВЕРЕН»). Сейчас код не читается вообще,
   решение принимается по тексту — это хрупко.
3. **Убрать `--tol 0.05`** из вызова при наличии `--table` (или печатать «допуск: per-file, таблица»).
4. **Печатать `worst` как справочное**, с явной пометкой «к норме не применяется».

## Набор тестов для приёмки патча (мои негативы, они уже прогнаны)

| случай | ожидание |
|---|---|
| лимитер 0,95·пика (Δ **−0,19** дБ, допуск 0,05) | **провал** |
| сильный лимитер (Δ −1,87 дБ) | провал |
| чистый gain −0,5 дБ | строка «Только усиление», норма не применяется |
| файл побайтово неизменный | норма не применяется (З-28 п.2) |
| файл без записи в таблице | **код 3 → провал** |
| полная таблица, канон 144 | код 0 |

## Про 3.7.3

`tools/accept_3.7.3.py` по-прежнему зовёт чекер с `--tol 0.05` **без** `--table`, и там
двойного пола нет — есть только «шум трубы + 0,05». Для 3.7.3 это терпимо (канон побайтово
неизменен, норма не применяется к неизменным), но в 3.8.0 так делать нельзя: файлы меняются.
Патч п.1–4 нужен **до** сборки 3.8.0, иначе гейт 3.8.0 пропустит правку динамики до 0,375 дБ.

## 7.5 Что при этом оказалось важнее двойного пола

**crest проверяет 15 файлов из 144 (10 %), и все 15 — транзиентные.** Стационарных файлов
(50 из 276 по таблице) в архиве **нет ни одного**, значит для них норма crest **не
применяется вообще**: таблица допусков размечена на 276 файлов, а гейт сверяет 15.
Если правку динамики внесут в `amb/*` или `hive/amb_*`, гейт этого не увидит — не потому что
порог велик, а потому что файла нет в наборе сверки.

**Предложение (важнее предыдущего):** сверять пакет с банком по **всем** файлам, у которых
есть запись в таблице, а не по 15 архивным. Чекер это уже умеет (`--table` + каталог/zip),
архив тогда нужен только как эталон PCM. Минимум — добить архив до полного состава
(144 канона), иначе норма покрывает 10 % банка.

## 9.3 Остаток 12–15 файлов — не шум, их надо разобрать

Даже с `baseline(M)` остаётся 15 провалов, с табличным baseline — 12. У этих файлов
`Δ(файл − мастер)` **больше шума кодека** в разы: например `infected_silverfish_hurt_01`
Δ 0,532 при baseline(M) 0,360 (транзиент — проходит по порогу 0,60, но запас тонкий),
`infected_stray_attack_01` Δ 0,402 при baseline(M) **0,003** — то есть файл отличается от
своего мастера почти на 0,4 дБ при шуме 0,003. Это либо файл, обработанный **после**
мастеринга, либо мастер не от этого файла. Такие случаи должен разобрать Звук поимённо —
подгонкой допуска их закрывать нельзя.

## 9.4 Побочная находка: `_decode` возвращает мастер в шкале int16

```
ogg : float64, макс 0.4241      flac: float64, макс 13639.0
```

crest от масштаба не зависит (потому блок и работает), но **любое сравнение абсолютных
уровней мастер↔файл в этой шкале бессмысленно** (разница ~90 дБ). Атака нормируется на пик
— её это не ломает. Требование: `_decode` должен приводить мастер к ±1,0, иначе следующая
проверка, где понадобится уровень (а она появится — громкость атаки привязана к пику), тихо
сравнит несравнимое.

| `infected_cave_spider_ambient_01` | 0,096 | 0,026 | 0,024 | 0,076 |
| `infected_witch_ambient_01` | 0,086 | 0,032 | 0,021 | 0,082 |

**Это не рассинхрон с мастерами и не правка уровня:** ΔRMS по всем двенадцати **−0,11 … +0,01 дБ**,
пики совпадают. Разница только в crest — то есть это **шум первого кодирования**.

## 10.3 Причина: baseline в таблице — не тот, что нужен этой проверке

- таблица Звука мерила baseline как **перекод уже сжатого файла** (вторая генерация);
- блок 12б сравнивает **файл с PCM-мастером** (первая генерация).

Первая генерация на ровном сигнале уводит crest сильнее: у 12 файлов 0,09–0,24 дБ против
0,003–0,157 в таблице. **Ни табличный baseline, ни `baseline(M)` моей трубой этого не
покрывают** (с `baseline(M)` провалов 15, с табличным — 12). Норма требует от файла точности,
которой первое кодирование 160k не даёт.

## 10.4 Что предлагаю

| кому | что |
|---|---|
| **Звуку (S46)** | измерить **baseline(M)** своим 160k-энкодером на мастерах для 132 файлов: `\|crest(encode(мастер)) − crest(мастер)\|`. Это единственная величина, которая норме подходит. Ожидаемо для стационарных 0,1–0,25 дБ |
| **Интегратору** | до S46 не включать стационарные в провал: печатать их как **отчёт** (кандидаты 12 файлов перечислены выше), иначе приёмка 3.8.0 упадёт на файлах, которые никто не трогал |
| **Архитектору** | решение: порог стационарных **0,05 дБ при сравнении с мастером недостижим**. Либо он становится «измеренный шум первого кодирования + 0,05» (≈ 0,2–0,3 дБ, норма ловит только грубые правки), либо crest от мастеров остаётся, а стационарные судятся round-trip-методом по таблице |
