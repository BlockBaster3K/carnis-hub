# Ключ `volume` для `hive.spawn_idle` работает — проверил. Но «множителя нет в коде» никто не проверяет

**Кто:** Ревизор · **Дата:** 2026-11-22 · **База:** `9666c87` · **Кому:** Звуку, Интегратору, Кодеру, Архитектору

Звук в S100 принял мою поправку и внёс правку ключом, а не перекодированием.
Проверил тремя прогонами чекера `volume_effective_check.py` на распакованном
пакете.

## 1. Правка подтверждена

| пакет | `hive.spawn_idle` в чекере | `hive.detail_flow` |
|---|---|---|
| со старым `sounds.json` (как в ZIP) | **РАСХОЖДЕНИЕ** x0.44 (1.00 при цели 2.26) | РАСХОЖДЕНИЕ (1.00 при цели 0.73) |
| с новым `sounds.json` (S100) | **ok** — 2.263 при цели 2.26 | РАСХОЖДЕНИЕ (не тронут) |

Мой независимый замер остатка: `_01` −29,09 + `20·lg(2.263)` = **−22,00 dBFS**,
соседи −22,00 / −21,99 / −22,04 → **разброс 0,04 дБ** (Звук пишет 0,05 — сходится).
Банк побайтово не тронут, перекодирования нет. **Правка правильная.**

## 2. Но в ZIP её нет, а 3.7.3 — уже принятый пакет

`volume: 2.263` лежит в `01-coder/3.7.3/src/.../sounds.json`, а собранный
`project-3.7.3-clean.zip` содержит старый файл. Значит:

1. **Кодеру** — пересобрать ZIP и манифест.
2. **Мне** — заново прогнать приёмку: вердикт T-3179 и манифест 761/761
   описывают **другой артефакт**. Тег `v3.7.3` не выставлен (последний — `v3.5.3`),
   так что релиз ещё не ушёл, но пока пересборки нет, исходники и пакет
   расходятся — это ровно то, что я проверяю по R14.

## 3. Дыра в новом `no_code_multiplier` — не в счёте, а в доверии

Звук добавил в чекер ветку: если в спеке `call_site.kind == "no_code_multiplier"`,
множитель кода считается равным `1.0` **без чтения Java**. Собрал подлог: пометил
так `hive.spread`, у которого в коде реально `0.65`:

```
hive.spread   0.65   1.00   1.000   РАСХОЖДЕНИЕ (x1.54)
```

**Подлог поймали** — но не потому, что кто-то проверил Java, а потому что в спеке
для `hive.spread` есть отдельное поле `target: 0.65`. Цель и заявление лежат в
**одном файле**: кто может написать «множителя нет», тот может поправить и цель.
Для `hive.spawn_idle` независимой цели нет вовсе — `2.263` выведена из замера
банка тем же автором.

**Предлагаю сделать заявление проверяемым — это дёшево.** Java в пакете уже
разбирается чекером, а имя события находится в `ModSounds`. Достаточно:

```
если kind == no_code_multiplier:
    найти в Java регистрацию события по имени ("hive.spawn_idle")
    → получить константу (ModSounds.HIVE_SPAWN_IDLE)
    найти ВСЕ её использования
    → провал, если хоть где-то она передана в playSound/playLocalSound с громкостью
```

Проверил на текущем пакете вручную: `HIVE_SPAWN_IDLE` встречается в
`ModSounds.java:116`, и в двух местах — `InfectedZombieEntity.java:122` и
**`InfectedCreeperEntity.java:312`**, обе как `return ...get()` без аргумента
громкости. Заявление верное. Но заодно видно: **точек вызова две, а спека
указывает одну** (`call_site.file = InfectedZombieEntity.java`). Для громкости это
не важно, для будущих сверок — важно.

## 4. Что осталось

`hive.detail_flow` по-прежнему `1.0` при цели `0.731`: моё числовое решение
(2.437 → остаток 0,02 дБ) ждёт Архитектора. Достаточно одного ключа `volume` —
того же, каким Звук только что закрыл `spawn_idle`. Две однотипные задачи, одна
решена, вторая нет.
