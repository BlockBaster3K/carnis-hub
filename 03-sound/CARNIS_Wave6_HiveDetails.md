# ЧАСТЬ I. ИССЛЕДОВАНИЕ

## 1. «Как звучит дом, в котором живут без сна?»

Первый рефлекс — сделать «фоновый гул». Это ошибка: гул читается как **работающая техника**, а не как присутствие. Настоящий дом ночью звучит иначе — **редкими одиночными событиями в тишине**.

| Что известно про «оседание» дома | Следствие для дизайна |
|---|---|
| Причина — температурное сжатие/расширение и влага; материал «ползёт» относительно крепежа | звук — **не процесс, а разряд накопленного напряжения**: короткое событие |
| Механика — **stick-slip**: трение держит, потом срыв рывком | не тон, а **серия микросрывов** с неровным шагом |
| «Структурные звуки — обычно одиночное внезапное событие с последующей тишиной; звуки животных — как правило, непрерывные и нерегулярные» (бытовые акустические наблюдения) | **это и есть грань**, которую надо стереть: наши details должны быть «структурными» по форме (одиночные события + тишина), но «живыми» по содержанию |
| Ночью слышно больше не потому, что громче, а потому что **тише вокруг** | details не должны конкурировать с фоном — они должны **выступать из него** |

**Вывод №1.** Details = **события, а не текстура.** Ни одного непрерывного слоя. Файл — это «фраза» из 1–8 микрособытий, а тишину между файлами даёт планировщик (2–8 с).

## 2. «Что слышно в городе в 4 утра, когда все спят?»

Три наблюдения, которые прямо переносятся в звук:

1. **Источник не определяется, но присутствие очевидно.** В акустике это *acousmatic listening* (Шаффер/Шион): звук без видимой причины; причём «неопознанное акузматическое слушание — ситуация, которая сильнее всего обостряет причинное слушание». Игрок начинает **искать источник** — и это ровно то состояние, которое нужно.
2. **События не связаны между собой.** Ни ритма, ни повторов, ни «диалога». Каждое событие — отдельная причина.
3. **Слышны мелочи, которые днём маскируются.** Не громкость, а **контраст с тишиной**.

И физиология, которая делает верх идеальным местом для details:

| Факт | Значение | Риск |
|---|---|---|
| Слух наиболее чувствителен в **2–5 кГц** (резонанс слухового канала ~2.5–3 кГц даёт +10–15 дБ) | тихие детали в этой полосе **слышны** при RMS −30 dB | те же частоты — зона «harshness»: устойчивый узкий пик здесь **утомляет** |
| Маскировка **растёт вверх**: низкие звуки маскируют высокие («upward spread of masking») | низ IDLE-мобов будет частично маскировать details — это **плюс**: они не спорят | но при громком бое details полностью исчезнут → планировщик должен их **выключать**, а не «продвигать» |

**Вывод №2.** Полоса 1.2–5 кГц — единственно верное место, но с жёстким ограничением: **никаких длинных узких резонансов**. Отсюда правило: спад каждой частичной на −20 дБ — **не дольше 165 мс**, а «звонкость» (узкий пик над локальной медианой) измеряется покадрово.

## 3. «Как отличить „дом оседает“ от „дом живёт“?»

Отличие не в громкости и не в частоте — в **физическом законе, который слышно**.

| Признак | «Оседает» (неживое) | «Живёт» (наше) |
|---|---|---|
| **Распределение высот** | один доминирующий резонанс конструкции | **пузыри по закону Миннарта**: `f = 3.26 / a` (a — радиус в метрах). Микропузырь 0.65–2.7 мм = **1.2–4.9 кГц**. И главное: газ уходит → пузырь **уменьшается** → **каждый следующий выше предыдущего** |
| **Спад** | ровный, «металлический» | короткий, «влажный»: 44–164 мс на −20 дБ |
| **Шаг событий** | регулярный тепловой тик | **нерегулярный**: шаг зёрен в скрипе случайный в 0.45–1.6× (без нижнего «пола») |
| **Отношение событий друг к другу** | одинаковые | ни одно событие не повторяет предыдущее по высоте, длине и силе |

**Вывод №3.** «Живое» в среде создаётся **законом** (Миннарт: маленький пузырь = высокий звук, и он всегда уменьшается), а не добавлением «органических» обертонов. Именно поэтому `bubbles_01` — самый «живой» файл волны, хотя в нём нет ни одного синтезированного «голоса».

## 4. Ответ на ваш список вариантов: почему 6 файлов, а не 5

Ваша рекомендация — 2 flow + 1 membrane + 1 bubbles + 1 creak. Я добавил шестой — **`scuttle_01`**, и вот почему:

| Аргумент | Пояснение |
|---|---|
| 5 файлов описывают **только материалы** (жидкость, плёнка, газ, оболочка) | это «среда без жителей»: красиво, но игрок не чувствует, что в стене **кто-то есть** |
| `scuttle` — единственный файл, который описывает **агента**, оставаясь не-мобом | он не «шаги существа», а «движение в стене»: 8 сухих шагов, интервалы растут, звук уходит вглубь и исчезает |
| Он же даёт **фальшивое присутствие** | мозг ищет агента → не находит моба → напряжение растёт без спавна |

Про `wall_01/02` (движение в стенах): **отказался как от отдельного файла** — он либо скрип (`creak`), либо шорох (`scuttle`); третий вариант «шорох стены» физически неотличим от `creak` и только размывает банк.

**Итог волны:** `flow_01`, `flow_02`, `membrane_01`, `bubbles_01`, `creak_01`, `scuttle_01`.

## 13. Java: общий планировщик (взаимоисключение с IDLE)

```java
package com.carnis.sound;

import net.minecraft.util.RandomSource;
import net.minecraft.world.entity.LivingEntity;

import java.util.ArrayDeque;
import java.util.Deque;
import java.util.List;

/**
 * Планировщик ДЕТАЛЕЙ среды. Три правила, все обязательные:
 *
 * 1) Частота: одно событие за 2..8 с (экспоненциально), 3-8 событий за 30 с — по требованию.
 * 2) Взаимоисключение с IDLE: если в радиусе 16 блоков играл hive_spawn_idle за последние
 *    40..80 тиков (2-4 с), details НЕ играют. Среда молчит, пока говорит тело.
 * 3) Молчание в бою и после смерти: если рядом был hurt/attack за 60 тиков или death за 24 тика —
 *    details не играют. Это не «вежливость»: при 4 файлах в бою они превращаются в кашу.
 */
public final class CarnisDetailScheduler {
    private static final String[] EVENTS = {
        "amb_hive_detail_flow", "amb_hive_detail_flow",
        "amb_hive_detail_membrane", "amb_hive_detail_bubbles",
        "amb_hive_detail_creak", "amb_hive_detail_scuttle"
    };
    private final Deque<String> bag = new ArrayDeque<>();
    private final RandomSource rnd;
    private long nextAtTick = 0;

    // общие «занятости» — обновляются из CarnisHiveVoices / CarnisHurtSounds
    public static long lastIdleTick = -9999, lastCombatTick = -9999, lastDeathTick = -9999;

    public CarnisDetailScheduler(RandomSource rnd) { this.rnd = rnd; }

    public void tick(long now, LivingEntity anyHiveMobNear16, PlayDetail play) {
        if (now < nextAtTick) return;

        boolean idleSpeaking = now - lastIdleTick < 40 + rnd.nextInt(41);   // 2..4 с
        boolean inCombat     = now - lastCombatTick < 60;                    // 3 с
        boolean justDied     = now - lastDeathTick < 24;                     // 1.2 с
        if (idleSpeaking || inCombat || justDied) {                          // уступаем и перепроверяем скоро
            nextAtTick = now + 20 + rnd.nextInt(20);
            return;
        }

        String ev = nextFromBag();
        float pitch = 0.92f + rnd.nextFloat() * 0.16f;                       // 0.92..1.08
        play.accept(ev, pitch, 0.30f + rnd.nextFloat() * 0.08f);             // 0.30..0.38
        nextAtTick = now + 40 + (long) (-Math.log(1 - rnd.nextFloat()) * 120);  // 2..8 с, экспонента
    }

    private String nextFromBag() {
        if (bag.isEmpty()) {
            List<String> l = List.of(EVENTS);
            bag.addAll(l);
            java.util.Collections.shuffle((List<String>) bag, new java.util.Random(rnd.nextLong()));
        }
        return bag.pollFirst();
    }

    @FunctionalInterface
    public interface PlayDetail { void accept(String event, float pitch, float volume); }
}
```

**Важно про место воспроизведения:** details играют **не в позиции моба** (моба нет), а в случайной точке на расстоянии 3–14 блоков от игрока **у ближайшего блока Улья**. Если блоков Улья рядом нет — details не играют вообще: среда принадлежит зоне, а не игроку.
