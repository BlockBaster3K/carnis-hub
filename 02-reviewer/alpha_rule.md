# Правило альфы для гейтов (закрывает З-15)

**Автор:** Ревизор · **Дата:** 2026-11-26 · **Задача:** T-3159 п.1
**Инструмент:** `02-reviewer/tools/alpha_audit.py` · **Эталон:** `01-coder/3.6.0-R/project-3.6.0-R-clean.zip`

## 0. Короткая формулировка

> **Дефект альфы — это (1) сдвиг маски `α > 0` относительно эталона или (2) полутоновая альфа там, где стандарт требует только 0/255.**
> Смена *значений* альфы при сохранной маске дефектом **не является** — это бинаризация по стандарту.

## 1. Область действия (главное, из-за чего был спор)

| Область | Правило 0/255 | Сдвиг маски запрещён |
|---|---|---|
| `textures/entity/**` (19 PNG) | **да** | да |
| `textures/block/creeping_tendrils*.png` (A3R1, 4 PNG) | **да** | да |
| `textures/block/**` остальные (54 PNG) | **нет** — у блоков альфа = сила свечения, градиент законен | да |
| `textures/item/**`, `textures/particle/**`, `textures/misc/**`, `textures/hallucination/**`, `textures/models/**`, `textures/mob_effect/**` | **нет** — сглаживание и прозрачность по смыслу | да |

Обоснование границы: правило 0/255 объявлено в ТЗ 3.7.0 §2.3 и относится к палитре A4-p7/A3R1 (тела, маски свечения, щупальца). За его пределами полупрозрачность — рабочий инструмент: `misc/vein_overlay.png` (16 787 градиентных px), `block/pulsing_heart.png` (4 096 px, 150–155), 19 предметов, 2 частицы, 3 маски свечения блоков, `hallucination/phantom_eyes.png`. Если применить правило 0/255 ко всему дереву, эти 28 файлов превратятся в жёсткие пятна.

## 2. Что считать дефектом

| Код | Ситуация | Вердикт |
|---|---|---|
| **A1** | `α > 0` потерял хотя бы один пиксель относительно эталона (дырка в силуэте) | **дефект**, код 2 |
| **A2** | `α > 0` получил пиксель, которого нет в эталоне (нарост силуэта) | **дефект**, код 2 |
| **A3** | размер PNG изменился | **дефект**, код 2 |
| **A4** | в области 0/255 есть значения ∉ {0, 255} | **дефект**, код 2 |
| A5 | значения альфы изменились, маска та же (например 210/220 → 255) | **не дефект**; печатается справочно |
| A6 | файл новый, в эталоне его нет | не дефект; проверяется только A4 (если область 0/255) |

## 3. Команды для гейта

```bash
# геометрия + (опционально) стандарт:  код 0 ожидается на принятом пакете
python3 02-reviewer/tools/alpha_audit.py <пакет> \
        --baseline 01-coder/3.6.0-R/project-3.6.0-R-clean.zip

# область 0/255 отдельно (entity + щупальца): код 0 ожидается
python3 02-reviewer/tools/alpha_audit.py <пакет> \
        --baseline 01-coder/3.6.0-R/project-3.6.0-R-clean.zip \
        --require-binary --only entity/
```

`--require-binary` **без** `--only` запускать нельзя: он действует по объявленной области (§1), а не по всему дереву.

## 4. Что уже проверено этим правилом

На пакете 3.7.2 (`e65c017d…`): 117 PNG, **0 нарушений** (A1–A4 нет), три справочные бинаризации — `block/pustule_cluster.png` (192 px), `entity/incubation_overlay.png` (683 px), `entity/infected_skeleton_glowmask.png` (15 px). Маски всех трёх побитово равны 3.6.0-R.

На 3.7.1 (`7ca6bdb8…`) набор тот же, кроме `incubation_overlay` (там ещё 683 полупрозрачных, бинаризация пришла в 3.7.2).

## 5. Почему правило именно такое

1. **Проверять «значения альфы» бессмысленно:** проект сам требует их менять (0/255). Проверять надо **то, что нельзя терять**, — силуэт.
2. **Проверять только маску недостаточно:** полутоновая альфа в области A4 — дефект стандарта, и без отдельной проверки он пройдёт молча (так и было бы с `incubation_overlay` в 3.7.2).
3. **Область действия должна быть явной:** без неё гейт либо даёт 28 ложных нарушений (§1), либо не проверяет ничего.

# Часть II · Правило свечения (Р-3, T-3167)

**Формулировка (для гейта, однозначная):**

> **У glowmask существа (`textures/entity/<тело>_glowmask.png`) ровно один непрозрачный цвет — `(255, 92, 57)` с альфой `255`; все остальные пиксели — `α = 0`. Любое другое значение в непрозрачной части — дефект (Р-3).**
>
> **Правило не распространяется на glowmask блоков, предметов и брони** — у них свои цвета свечения и, для анимированных масок, законный градиент альфы (см. таблицу ниже). Область действия — как у правила альфы: существа + щупальца, не всё дерево.

## Два дефекта, которые правило вытащило

1. **Шапка `tools/glow_check.py`, п.3** обещает «ровно 7 непрозрачных цветов … (+ прозрачный = 8 RGBA)». У тел A4-p7 **прозрачных пикселей нет вообще**: замер — 4 файла, α только `255`, уникальных RGBA ровно **7**, `(0,0,0,0)` не встречается ни разу. Восьмого значения физически быть не может → это **дефект документации, не кода**: сам чекер считает правильно (`непрозрачных 7, вне палитры 0`). Исправлено в шапке.
2. **Обоснование пропуска glowmask в блоке 12б гейта** («одноцветные по определению»): из 13 масок **6 имеют 2–3 цвета**, а 4 — градиентную альфу. Само решение пропускать glowmask из аудита светотени верное (маска — не тело), но комментарий описывает неверное основание; при переносе правила в гейт его надо заменить на «glowmask проверяется правилом Р-3, а не аудитом светотени».
