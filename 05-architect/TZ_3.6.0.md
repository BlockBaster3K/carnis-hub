### K5 — `creeping_tendrils`: weighted-варианты по 4 `facing` (возвращён в план)

**Что есть сейчас.** `CreepingTendrilsBlock extends LadderBlock`
(`block/CreepingTendrilsBlock.java`), значит блок уже имеет свойство `facing`
(4 значения: north/east/south/west) и выводится по `blockstates/creeping_tendrils.json`:

```json
{ "variants": {
    "facing=north": { "model": "carnis:block/creeping_tendrils" },
    "facing=east":  { "model": "carnis:block/creeping_tendrils", "y": 90 },
    "facing=south": { "model": "carnis:block/creeping_tendrils", "y": 180 },
    "facing=west":  { "model": "carnis:block/creeping_tendrils", "y": 270 } } }
```

Все четыре `facing` указывают на **одну и ту же** модель — рисунок одинаков
вокруг, различается только поворот. Текстура сейчас `textures/block/creeping_tendrils.png`
**16×16** (в пакете `3.5.2-R`).

**Что сделать (код).** Добавить **взвешенный выбор варианта** так, чтобы:

1. вариантов было **3–4**, у каждого — **своя** модель/текстура;
2. вариант выбирался **один раз при установке блока** и **не менялся** при
   обновлении состояния (иначе рисунок «прыгает» при каждом тике);
3. выбор — **взвешенный**, веса задаются в коде константой и **документируются**;
4. `facing` продолжал задавать **поворот** (y 0/90/180/270), а вариант — **содержание**.

**Рекомендуемый способ (1.20.1, без несуществующих API):**

- свойство блока `variant` типа `Integer` (0..N-1) — добавить в
  `CreepingTendrilsBlock` через `BlockBehaviour.Properties` + свойства
  `StateDefinition`; значение по умолчанию — 0;
- в `getStateForPlacement` — выбрать вариант **взвешенно** через
  `context.getLevel().random` и вернуть состояние с этим `variant`;
- в `blockstates/creeping_tendrils.json` — развести варианты по **комбинации**
  `facing` и `variant`, то есть `facing=north,variant=0` → модель A,
  `facing=north,variant=1` → модель B и так далее;
- модели — `models/block/creeping_tendrils_0.json` … `_N.json`, каждая с
  `parent: minecraft:block/ladder`, `render_type: minecraft:cutout` и своей
  текстурой `carnis:block/creeping_tendrils_<i>`.

> ⚠️ **Про `BlockStateProperties`:** существующий `LadderBlock` уже объявляет
> `FACING` как `HorizontalDirectionalBlock.FACING`. **Не объявляй `facing`
> заново** — будет конфликт свойств и падение при регистрации. Добавляй
> **только** `variant`.

**Проверка приёмки (Ревизор):**

- `grep -c "variant" src/main/resources/assets/carnis/blockstates/creeping_tendrils.json` → число комбинаций = 4 × N (N = число вариантов);
- в `blockstates` для **каждой** комбинации `facing`×`variant` есть запись, и в каждой записи `y` соответствует `facing` (north 0, east 90, south 180, west 270);
- `variant` в `blockstates` **не меняет** `y`: это за поворот, а не за содержание;
- в коде: выбор варианта происходит в `getStateForPlacement`, **а не** в
  `getState`/`tick`/`neighborChanged` — иначе рисунок прыгает;
- веса вариантов **не нулевые** и **в сумме дают** нормализацию (как именно —
  указать в отчёте);
- `minecraft:block/ladder` остаётся `parent` — блок ведёт себя как лестница
  (можно залезть), поведение не сломано.

**Риск.** `LadderBlock` чувствителен к состоянию: добавление свойства меняет
`BlockState` и требует корректного `getStateForPlacement`. Ошибка проявится как
«блок не ставится» или «направление слетает» — проверяется только в игре,
это честно отмечается как непроверенное автоматически.

**Зависимость от графики.** Текстуры вариантов (3–4 PNG 64×64) готовит
**Художник** (партия A3/A6, критерии — в `prompts/04-artist.md`). Кодер
**не рисует** текстуры сам. Если графика не готова к моменту сборки 3.6.0 —
код делается с **текущей** текстурой 16×16, и переключение на варианты идёт
отдельной правкой после приёмки графики. **Сейчас 3.6.0 собирать рано.**

**Блокер 1 — продуктовый: «`_geo`-текстура очистителя.»** Файл
`bio_purifier_geo.png` не равен используемому `bio_purifier.png` (у `_geo` на

**Предпочтение координатора — (а), удалить.** Основание: рендерер явно указывает
на `bio_purifier.png`, `_geo` не совпадает с ней побайтово, ссылок ноль, а

## 8. Переформулированные критерии A3/A6 (для Ревизора и Художника)

Прежние критерии A6 — «совпадение кромок» + «содержимое не прижато к краю» —
**противоречили друг другу**: вместе они требовали пустого кольца по краю
плитки, а такое кольцо на стене образует **прозрачную решётку**. Отсюда четыре
неудачные пробы подряд.

Исправленная формулировка — **шесть критериев**:

1. попарный seam (стыки вариантов без щели);
2. сетка 3×3 и 5×5 со смешением — шов и периодичность;
3. совпадение кромок (побайтово, и у всех вариантов кромка одна);
4. читаемость в 16 px;
5. торцы и углы: кромка заполнена **≥ 45 %** непрозрачных в полосе 3 px; вдоль
   кромки нет прямой полосы длиннее **24 px**; углы **≤ 10 из 16 px**;
6. **нет решётки**: средняя альфа у границы плитки в проекции 16 px — не ниже
   **35 %** от альфы внутри плитки.

Стенд проверки (общий для Художника и Ревизора, лежит в репозитории):
`tools/tendrils/tendrils_check.py <каталог> <out.json>` →
`ИТОГ: ВСЁ СХОДИТСЯ` / `ИТОГ: ЕСТЬ ЗАМЕЧАНИЯ`.
