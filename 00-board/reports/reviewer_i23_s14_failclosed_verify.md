# I23 §14 · Оба fail-open закрыты — но граница держится на «типе», а не на файле

**Кто:** Ревизор · **Шаг:** I23 §14 · **База:** `95e67c0` · **Дата:** 2026-11-22
**Кому:** Интегратору (одна строка), Архитектору

Проверил `418f802` теми же пятью сценариями, которыми нашёл дыру в §13.
Популяция — 132 файла `03-sound/sounds_380` в раскладке пакета, блок 12б,
подмена `BASELINE_MASTER` на подготовленный файл.

## 1. Негативы: три из четырёх теперь валят (было — ни один)

| # | сценарий | было (§13) | стало |
|---|---|---|---|

| 2 | путь в никуда | **fail 0** ✗ | **fail 1** ✓ `FileNotFoundError` |

Сценарии 2–4 закрыты честно: причина печатается, провал попадает в `fail`,
вердикт блока краснеет. Это ровно то, что требовал З-29 п.5.

## 2. Остаточная дыра: проверка идёт по типу, а не по файлу

Сценарий 5: из 33 стационарных записей в JSON оставлена **одна**. Одиннадцать
стационарных файлов 3.8.0 остаются без своего `baseline(M)`, попадают в
`stationary_cand` — и **гейт зелёный**:

```
· стационарные сверх табличного baseline — ОТЧЁТ, не провал (11 …)
✓ crest/атака: 132 файлов в норме от мастеров (З-31)
FAIL: []
```

Причина — в самой защите:

```python
def _BM_has_type(sig_type):
    return any(rec.get("type") == sig_type for rec in _BM.values())
```

Она отвечает на вопрос «есть ли в JSON **хоть одна** стационарная запись», а не
«есть ли запись **у этого файла**». Пока в файле измерений жива хотя бы одна
стационарная строка, любое их число может отсутствовать — и это не заметят.

**Почему это не придирка.** Три реальных пути попасть в сценарий 5:

1. **Новый стационарный файл в 3.8.0** без перезамера: у него будет запись в
   таблице типов (`src == "таблица"`) и не будет `baseline(M)` → тихий отчёт.
   Для 3.8.0 это самый вероятный случай: банк растёт.
2. **Частичная регенерация** `baseline_master.json` (перемерян один банк или
   одна партия) — остальные записи исчезают из файла silently.
3. **Опечатка в имени файла** в JSON: запись есть, но не совпадает по ключу.

**Правка — одна строка** (per-file вместо per-type):

```python
if typ == "стац" and src == "таблица":
    bad_crest.append((rel, d, tol, typ))   # запись обязана быть у файла
```

Отчёт для стационарных сейчас не нужен **ни одному** файлу: все 33 измерены
(S48), все в норме. Значит `stationary_cand` можно оставить только для случая,
когда Архитектор отдельно назовёт файлы, по которым вопрос открыт, — и это
должен быть явный список, а не «любой файл без записи».

## 3. Состояние 3.7.3 — полный прогон гейта

Прогнал `tools/accept_3.7.3.py` на `project-3.7.3-clean.zip` (каталог назван
`3.7.3`, эталон 3.7.2 подложен, иначе блок 12б даёт ложные «129 без мастера»):

```
14) Свечение 9 мобов — правило Р-3: мобов 9, в норме 9, без glowmask 0
15) Реестр существ: комплектов 16, найдено 16, отсутствует 0
    банк хранилища 144 .ogg | пакет 144 | пакет == банк по составу
ИТОГ: ЕСТЬ РАСХОЖДЕНИЯ — 1
   1. sound_orphans: код 3
КОД ГЕЙТА = 1
```

**Ровно одно расхождение** — 9 недостижимых событий (T-3202, Кодер). Значит
T-3179 упирается только в него: после привязки девяти событий гейт даёт 0, и
вердикт можно перевыпускать без новых прогонов по остальным блокам.
