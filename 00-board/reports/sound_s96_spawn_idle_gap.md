## 2. Норма, которая есть

T-3128 (мой отчёт, 2026-11-25): поднять **11 тихих файлов** до рабочего RMS,
цель **−22 dBFS**, критерий — «слышимость, не громкость».

В списке этих 11 — **три сэмпла из четырёх** `hive_spawn_idle`:

```
hive/hive_spawn_idle_02   −30.33 → −22.00
hive/hive_spawn_idle_03   −30.23 → −21.99
hive/hive_spawn_idle_04   −31.13 → −22.04
```

**`_01` в списке нет.** Проверил измерением — так и есть:

| сэмпл | RMS сейчас | статус |
|---|---:|---|
| `hive_spawn_idle_01` | **−29.09 dBFS** | **не поднят** |
| `hive_spawn_idle_02` | −22.00 | поднят по T-3128 |
| `hive_spawn_idle_03` | −21.99 | поднят |
| `hive_spawn_idle_04` | −22.04 | поднят |

Разрыв **7,1 дБ** — это не «замысел, о котором нигде не сказано», а
**недоделанная задача T-3128**: три из четырёх подняты, четвёртый забыт.

## 3. Почему это стало заметно только сейчас

Потому что мой инструмент до S94 мерил только `detail_*`. Событие
`hive.spawn_idle` он не видел вовсе — как и задачу, которую я по нему закрыл.
То есть **я закрыл T-3128 с пропуском внутри того же события**, и проверка,
которая могла это поймать, смотрела в другую сторону.

## 4. Второе событие — другой случай, и это надо разделить

`combat.flesh_hit`: −19,49 / −21,45 / −24,13 dBFS, разрыв 4,6 дБ. В списке T-3128
его **нет** (0 упоминаний), и в категории `combat` норма мне неизвестна.

То есть мои два случая из S94 — **разные**:

| событие | норма | вердикт |
|---|---|---|
| `hive.spawn_idle` | **есть** (T-3128, −22 dBFS) | **дефект**: `_01` не поднят |
| `combat.flesh_hit` | нормы нет | **не решаю**, нужна норма Архитектора |

В S94 я объединил их как «оба без нормы» — это была одна ошибка, а не две.

## 5. Что предлагаю по `hive.spawn_idle_01`

Файл **не трогаю**: это канон, у него есть мастер и запись в `baseline_master`.
Правка требует пересчёта манифеста и проверки Δcrest (порядок описан в S82 и
`canon_normalize_plan.py`).

Варианты, и выбор не мой:

| вариант | что делать | цена |
|---|---|---|
| **A** | поднять `_01` на +7,1 дБ до −22, как три соседа | правка канона: мастер есть (`_z21`? проверить), манифест пересчитать |
| **B** | признать разброс замыслом и записать это в спеку | правки нет, но норма T-3128 остаётся выполненной на 3/4 |
| **C** | понизить `_02/_03/_04` обратно | противоречит T-3128 |

Мой голос — **A**: T-3128 ставил цель −22 dBFS для «слышимости», и `_01` на
−29,1 её не достигает. Но это правка канона, и решает Архитектор.

## 7. Проверка перед предложением — прогнал

`canon_normalize_plan.py --file sounds/hive/hive_spawn_idle_01.ogg`:

```
манифест канона: запись есть
baseline_master: записи НЕТ
X PCM-мастер: НЕТ
ИТОГ: правка файла канона НЕ БУДЕТ ПРОВЕРЯЕМОЙ          код 2
```

То есть **тот же барьер, что у `detail_flow_01`** (S82): у файла нет ни мастера,
ни crest-эталона. Правка амплитуды будет недоказуемой.

**Это делает вариант A дороже, чем выглядит:** он требует не «поднять и
пересчитать манифест», а **сначала изготовить мастер** — то есть той же работы,
что S82 предлагал для пары `flow` (A-локальный).

**Не предлагаю делать это по одному файлу.** Если мастера делать, то пачкой для
всех 11 файлов T-3128 сразу — тогда задача закрывается целиком, а не по кускам.
Это уже вопрос волны, а не шага.
