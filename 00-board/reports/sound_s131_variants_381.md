## Дефект инструмента, найденный и закрытый в этом шаге

Первая версия выравнивала crest срезом и давала замечания у 25 файлов из 27.

**Диагноз по замеру, а не по чтению кода:** `clip` умеет только **понижать** crest.
Порог среза `c = rms·10^(18/20)` = 0.794 оказался **выше** текущего пика 0.472, то есть
не резался ни один отсчёт: замер на шуме дал 13,483 → 13,483. У синтеза crest 10,81–14,68
против цели 18,0, поэтому срез был бесполезен **в принципе**, а не «недоточен».
Масштабирование перед срезом не помогало (проверено: те же числа).

**Решение:** двусторонний шейпер `shape_crest`.
* не хватает динамики → степенное расширение `sign(y)·|y|^p`, `p > 1`: громкое остаётся,
  тихое придавливается. Показатель подбирается **бисекцией по фактическому замеру crest**,
  а не по формуле.
* избыток → срез, как раньше.

Второй дефект того же узла: кодек добавляет перелёт по пику (−1,40 → −1,33), поэтому
посадка пика после кодирования не сходилась за 5 итераций. Теперь цель по пику **тоже
опускается по замеру** (`peak_t`), а не считается один раз.

## Разошедшиеся ожидания: единая цель crest 18,0

Промежуточный вывод «18,0 физически недостижим для непрерывных текстур» **не подтвердился**:
он был верен для среза, но не для расширения динамики. Тем не менее честная оговорка
остаётся: у текстурных событий (`creeper_a_poison_cloud`, `skeleton_a_bow_draw`,
`creeper_a_anchor`) цель 18,0 достигается показателем `p`, то есть ценой поджатия тихих
частей. Для «фона» это может читаться как неестественная пауза в хвосте. **Вопрос
Архитектору:** оставляем единую полосу 18,0 для всех 27 или даём текстурам отдельную
(например 15,0 ± 0,3) и правим `CREST_TARGET` по типу события.
