### Чего достать нельзя (причина, а не отговорка)

  даже при наличии JDK: мод тянет Forge 47.4.28, GeckoLib 4.4.4, Curios 5.9.1.
* **apt/deb.debian.org** — закрыт (`000`).

**Вывод:** локальная компиляция Java в этой песочнице невозможна. Сборка
проходит **только через CI** — и это не гипотеза: jar 3.8.0 собран там

### 2.2 Методика (проверена инструментами)

1. **Прочитать существующее, а не изобретать.** 229 `.java` в пакете
   3.8.1; 238 классов, 1190 методов, 2823 импорта — извлекается tree-sitter'ом
   за 0,1 с. Паттерн регистрации берётся из соседнего класса, не из головы.
2. **Разбор AST до правки.** tree-sitter даёт узлы `class_declaration`,
   `method_declaration`, `import_declaration` — по ним строю карту пакета и
   проверяю, что имя класса не конфликтует.
3. **После правки** — повторный разбор + сверка: все импорты существуют в
   пакете/Forge, все ссылки на ресурсы указывают в реальные файлы
   (это уже реализовано как блок D в `tools/accept_3.8.1.py`).
4. **Компиляция — через CI.** Пуш → GitHub Actions → в логе ищем `BUILD
   SUCCESSFUL`. До зелёного CI код считается **непроверенным**, и я так и пишу.

### 3.3 Обязательные правила (выстраданы, не вычитаны)

1. **`-fflags +bitexact`** — иначе libvorbis вставляет случайный serial и
   SHA-256 означает «этот прогон», а не «этот файл».
2. **Не класть звук вариантов в канонический банк** `03-sound/sounds/` — ломает
   приёмку уже выпущенных 3.7.3 и 3.8.0.
3. **Полоса crest** — сверять с кодом чекера, а не с README: чекер считает
   по допуску `max(0.60 транзиент / 0.05 стационар, …)`, а не по фиксированной
   полосе 17.90–18.04. Формулировка README «вне нормы 0 из 27» верна по чекеру
   и неточна по абсолютной полосе: 2 файла (`spider_b_leg_slam` 18.06,
   `creeper_a_launch` 18.04) выходят за верхнюю границу на 0,02 дБ. Оба
   сгенерированы, оба в паре «crest/пик» дают запас −0.23…−0.20 дБ.

## 4. РЕВИЗОР

### 4.1 Методика: вердикт = воспроизводимое доказательство

Каждый пункт вердикта обязан иметь команду и вывод. «Проверено» без команды —
не аргумент.

Порядок:

1. **Preflight:** `git fsck --connectivity-only`; `HEAD` vs `origin`; размер.
2. **Аудит пакета:** состав, версия в 3 местах, манифесты (внутренний +
   внешний, `sha256sum -c`).
3. **Гейт:** `tools/accept_3.8.1.py` (4 блока: A/B/C core9 + D java-refs).
4. **Звук:** levels / mono_norm / manifest_canon / orphans / volume_semantics.
5. **Регрессия:** гейты 3.7.3 и 3.8.0 обязаны остаться зелёными — если
   покраснели, ищем причину в своём коммите, а не списываем.
6. **Вердикт** с указанием: что проверено, чем, что осталось вне зоны.

### 4.2 Инструменты

`tools/` — 52 чекера. Ключевые: `accept_3.8.1.py`, `accept_3.8.0.py`,
`levels_check.py`, `mono_norm_check.py`, `manifest_canon_test.py`,
`sound_orphans.py`, `volume_semantics_audit.py`, `deps_gate_check.py`,
`release_jar_check`, `secret_guard.sh`.

Аудит jar — через `zipfile` без распаковки: список записей, число классов,
`mods.toml`, версия.

### 4.3 Главное ограничение роли — и как его закрываю

Раньше Ревизор был отдельным агентом. Теперь автор и приёмщик — одно лицо.
Это **системный риск**: легче пропустить свой же дефект. Компенсация:

* приёмка идёт **по чекеру**, а не по памяти о том, что я писал;
* каждый вердикт содержит команду и сырой вывод;
* **негативный прогон обязателен**: если проверка не умеет падать, она ничего
  не доказывает (проверка блока D ловила удалённый `infected_spider.geo.json`).
