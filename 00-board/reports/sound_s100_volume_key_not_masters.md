## 4. Правка проверена замером, а не на слово

Добавил в спеку `hive.spawn_idle` с `targets_by_sample`, прогнал `sample_loudness`:

```
hive.spawn_idle  разброс 7.1 дБ
   остаток после множителей: 0.05 дБ (допуск 1.0) -> объявление ПОДТВЕРЖДЕНО
```

И `volume_effective_check` по **исправленному исходнику**:
```
hive.spawn_idle  по сэмплам  1.00  2.263  ok
```

## 5. Что при этом выяснилось про поставку

`volume_effective_check` по **собранному ZIP** `3.7.3`:

```
hive.spawn_idle  по сэмплам  1.00  1.000  РАСХОЖДЕНИЕ (x0.44)
      hive_spawn_idle_01: volume 1.00 -> 1.000 (цель 2.26)  <-- вне допуска
```

**В пакете `volume` нет вовсе** — все 4 сэмпла играют как есть. То есть дефект
есть в поставке, и правка исходника **не попадёт к игроку**, пока пакет не
пересобран. Это уже не моя зона (Кодер/Интегратор), но зафиксировать обязан.

## 6. Попутно: мой чекер не умел события без множителя в коде

`hive.spawn_idle` играется из `getAmbientSound()` — там **нет аргумента
громкости**, множителя в коде не существует. Чекер искал `playSound(…, VOL, …)`,
не находил и отдавал **код 3 «вызов не найден»**. То есть событие было
**непроверяемым** — и это ещё одна причина, почему разброс жил незамеченным.

Добавил в спеку `call_site.kind = "no_code_multiplier"`: множитель кода = 1.0 по
определению, эффективная громкость = `volume` из JSON. Проверка прежних 9 целей
не изменилась (все `ok`), кроме `detail_flow`, который как был, так и есть
`1 из 9 вне допуска` — это `detail_flow_01` в пакете (`volume 1.0` вместо `0.731`),
известное и уже описанное.

Обе находки по громкости — **одна и та же причина**: пакет собран до правки.
Исходник 3.7.3 их уже не содержит.

## 8. Кому что

| кому | что |
|---|---|
| **Кодеру** | пересобрать ZIP 3.7.3 (или внести в 3.7.4): `hive.spawn_idle_01` volume 2.263 **и** `detail_flow_01` volume 0.731 |
| **Интегратору** | `volume_effective_check` теперь понимает `no_code_multiplier` — событий, которые раньше давали код 3, стало меньше |
