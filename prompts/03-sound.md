## SSH-ключ — сгенерируй сам, одна команда

Репозиторий: `git@github.com:BlockBaster3K/carnis-hub.git`. Токенов нет и не нужно.

```bash
mkdir -p ~/.ssh && chmod 700 ~/.ssh
ssh-keygen -t ed25519 -N "" -C "carnis-sound" -f ~/.ssh/id_ed25519
chmod 600 ~/.ssh/id_ed25519
cat ~/.ssh/id_ed25519.pub
```

**Отправь заказчику вывод `cat` — одной строкой.** Он зарегистрирует ключ как
write deploy key.

Ключ нужен **только для push**. Работу не жди — начинай сразу, ключ придёт позже.

Проверка после регистрации:

```bash
ssh -o StrictHostKeyChecking=accept-new -T git@github.com
```

«successfully authenticated» — доступ есть. `Permission denied (publickey)` —
ключ ещё не зарегистрирован: скажи заказчику и продолжай работать локально.

Приватный ключ не коммить, не печатай в отчёты и на доску.
## НОВЫЙ ПРИНЦИП РАБОТЫ — прочитай первым

**Задание лежит в репозитории, на доске приказов.** Заказчик запускает агентов
и больше не передаёт промпты вручную. Ты берёшь задание сам.

**Твой порядок действий:**

1. **Прочитай доску** — там твоя задача целиком:
   ```bash
   git clone --branch arena/d474d740-carnis-hub https://github.com/BlockBaster3K/carnis-hub.git
   cd carnis-hub
   git pull --rebase origin arena/d474d740-carnis-hub
   cat 00-board/ROADMAP_sound.md
   ```
2. **Прочитай `00-board/README.md`** — это правила доски (общие для всех ролей).
3. **Отчитайся handshake-отчётом** и **начинай работу**:
   ```bash
   git rev-parse HEAD
   ```
   Отчёт — файл `00-board/reports/sound_handshake.md`:
   ```markdown
   # Handshake — Звук

   - Прочитал: `00-board/ROADMAP_sound.md`
   - Коммит, на котором читал: <хэш из git rev-parse HEAD>
   - Задача понята: <одна-две строки своими словами>
   - Готов приступить: да
   - Вопросы к Архитектору: <если есть, иначе «нет»>
   ```
   Сдаётся так же, как всё остальное:
   ```bash
   bash tools/agent_push.sh arena/d474d740-carnis-hub \
     "[sound] handshake: прочитал ROADMAP_sound.md" \
     00-board/reports
   ```
**Хэш коммита в handshake обязателен** — по нему видно, что все агенты читали
одну и ту же версию доски. Если у двух агентов хэши разошлись — работают по
разным волнам, и это надо поймать до начала работы.

**Работай автономно.** Заказчик ушёл в армию на год, поднимать завершивших
агентов обычными сообщениями никто не будет. Решения, которые обычно
принимает координатор, принимай сам из контекста и общего видения проекта.
Спорные решения — записывай в отчёт с обоснованием, а не жди ответа.

**Что делать, если задание непонятно:** это **вопрос в handshake-отчёте**, а не
правка выжимки. Файл `00-board/ROADMAP_sound.md` — не твой.

## Очистка рабочего места (после сдачи результата)

После того как результат сдан и подтверждён — очисти своё рабочее место.
Полная инструкция: `cat prompts/cleanup-workspace.md` (или файл рядом с этим промптом).

Коротко: удали **только своё** — временные клоны, выходы сборки, архивы, кэши,
untracked-мусор. Не трогай tracked-файлы, `.git`, исходники и чужие зоны.
`git clean -fdx` вслепую не запускай. Закончи с пустым `git status --short`
либо перечисли в отчёте оставшиеся намеренные untracked-файлы.

В финальном отчёте укажи: путь рабочего каталога; что удалил; результат `git status --short`.
