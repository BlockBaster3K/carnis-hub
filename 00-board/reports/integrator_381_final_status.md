```

позитив: jar 3.8.0 из тега против принятого пакета
  ИТОГ: JAR соответствует пакету (все 647 ассетов совпали по sha256)
```

## Два дефекта в моей собственной обёртке — найдены прогоном

Оба проявились на первом же реальном пакете 3.8.1. Без этого прогона они уехали

**2. Версия для чекера дельты была литералом.**
`check_delta_372` вызывал `verify_373_delta.py` с `--version "3.8.0"` — жёстко,
мимо `VERSION`. После подмены `mod.VERSION` чекер всё равно судил пакет 3.8.1
по версии 3.8.0. Исправлено в самом гейте: `"--version", VERSION`. Для 3.8.0
значение не изменилось (там `VERSION="3.8.0"`), 3.7.3 отдельный файл.

После обоих исправлений: **`✓ версия 3.8.1: 4 из 4`**, `✓ mods.toml version:
3.8.1`.

Что показал разбор пакета 3.8.1:

```

из них с тем же именем и РАЗНЫМ содержимым: 9 (core9)
```

У этих девяти плоская версия **богаче**: hurt/death двигают по 7 костей, а
старые в `entity/` — по 2-3. Более того, `infected_skeleton.animation.json` в
`entity/` уже содержит `hurt` и `death` (по 2-3 кости), то есть «перенести»
означает **заменить** существующие на другие, а не добавить недостающие.

Это ключевая развилка, и я её не решаю сам:

| вариант | что получается |
|---|---|
| перенести как буквально сказано (замена файла целиком) | у зомби, паука, крипера, амальгамы **пропадут** `assimilate`, `pulsing`, `roar`, `slam`, `attack_scythe`, `attack_whip`, `bone_rattle` — они есть только в `entity/` |
| слить содержимое (объединение анимаций) | у 3 существ конфликтуют имена `idle`/`walk`/`attack`, и версии **не совпадают**: какую брать — не определено ни промптом, ни спекой |
| заменить только `hurt`/`death` | исчезают 4 файла из `entity/`, где эти анимации уже есть (по 2-3 кости) — это улучшение, но терять ли старые версии, промпт не говорит |

Пока не скажут, какой вариант, переносить нельзя: любой из трёх по-разному ломает
работающую игру, а проверить «стало лучше» нечем — в игре сейчас проигрывается
именно `entity/`.

# Проверка: разрешение build.gradle действительно закрывает дельту

Чтобы предложение было выполнимым, а не пожеланием, прогнал чекер дельты с
явным разрешением двух файлов сборки:

```
verify_373_delta.py ... --allow build.gradle --allow gradle.properties
  --version 3.8.1

Провалов: 0, предупреждений: 0
ИТОГ: СХОДИТСЯ
```

То есть механизм в норме уже есть (`--allow` принимает точный путь, строка 127
чекера, `allowed()` — префиксное совпадение), не хватает только записи в
`GROWN_380`. Решение «вписать её» — за Архитектором, потому что это расширение
области допустимых изменений, а не исправление ошибки.

Проверил и обратное — что разрешение не «открывает всё»: оно точечное, по
полному пути. `--allow build.gradle` не разрешает `gradle.properties`; их надо
перечислять поимённо.
