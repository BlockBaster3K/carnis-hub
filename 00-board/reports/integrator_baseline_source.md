# T-3170 / З-17: эталон гейта — из git, а не с диска

**Дата:** 2026-11-25 · **Роль:** Интегратор · **Зона:** `tools/`
**Статус:** ✅ выполнено · **Критерий приёмки выполнен**

## 1. Суть дефекта

Эталон 3.6.0-R читался **из рабочего дерева**:

```python
DEFAULT_REF = "01-coder/3.6.0-R/project-3.6.0-R-clean.zip"
```

У Ревизора рабочее дерево собрано через `sparse-checkout` (лимит 128 МБ на
диск), и `01-coder/3.6.0-R/` там **нет**. Файл не открывался — и проверка
выдавала **✗ расхождение**, хотя расхождения не было.

**Один и тот же пакет получал код 0 у Архитектора и код 1 у Ревизора**
только из-за устройства дерева проверяющего. Вердикт по 3.7.2 из-за этого
не выпускался вовсе.

## 2. Что сделано

### 2.1 Общий резолвер `tools/baseline.py`

Порядок поиска эталона:

1. **рабочее дерево** — если файл есть (быстро, полная совместимость);
2. **git-объект** — `git show <rev>:<path>`; он есть у любого полного клона
   независимо от `sparse-checkout`, потому что живёт в `.git/objects`;
3. **`UNAVAILABLE`** — если нет ни того, ни другого.

Резолвер возвращает и **происхождение** (`worktree` / `git:<rev>` / `none`),
чтобы в отчёте было видно, чем именно сверяли.

### 2.2 Пропуск ≠ расхождение

| Код | Значение | Когда |
|---|---|---|
| 0 | СХОДИТСЯ | проверено, дефектов нет |
| 1 | РАСХОЖДЕНИЕ | проверено, найдены отличия |
| 2 | ЗАМЕЧАНИЯ / **ПРОПУЩЕНО** | проверить не удалось (эталон недоступен) |

`run_tool` в гейтах больше **не** валит код 2 в `fail`; в итоговом вердикте
пропуски печатаются отдельным блоком «ВНИМАНИЕ: N проверок не выполнены»,
чтобы «ПРИНЯТО» не читалось как «всё проверено и всё сошлось».

## 4. Найденные попутно дефекты собственного резолвера

Оба ловились только на реальных деревьях, не на «обычном клоне»:

1. **`.git` бывает файлом** (`gitdir: …`) — worktree, submodule, часть
   CI-клонов. Проверка `os.path.isdir(".git")` такой репозиторий не видит.
   Исправлено: принимаем и каталог, и файл.
2. **`git show` требует путь ОТ корня репозитория**, а гейт передаёт
   абсолютный. Исправлено: `os.path.relpath(path, root)`.

## 5. Проверка в обе стороны (на копиях, не на рабочем дереве)

| Сценарий | 3.6.0-R | git | Результат |
|---|---|---|---|
| Обычное дерево | есть | есть | код 0, эталон **с диска**, блок 10: идентично 11, изменено 0 |
| **Дерево Ревизора** | **НЕТ** | есть | **код 0**, эталон `git:a000b665`, блок 10 сверен |
| Ни диска, ни git | НЕТ | НЕТ | **ПРОПУЩЕНО**, код 2, отдельная строка в вердикте |

Прогнаны все три гейта (`3.7.0`, `3.7.1`, `3.7.2`) в обоих деревьях —
регрессий нет, у Архитектора всё так же код 0.

**Критерий приёмки:** результат гейта **не зависит** от наличия `3.6.0-R`
в рабочем дереве. Выполнено.

## 6. Что это даёт Ревизору

Вердикт по 3.7.2 теперь можно выпускать: гейт отработает в его дереве так же,
как в дереве Архитектора. Пакет `01-coder/3.7.2/` уже принят гейтом — код 0.

## 7. Не проверено

- `sparse-checkout` с **неполной** историей (`--depth`): если в клоне нет
  коммита `a000b665`, эталон из git не достать — сработает честный пропуск.
  Вердикт будет «ПРИНЯТО с пропуском», а не ложный ✗. Это осознанно:
  лучше честный пропуск, чем неверный приговор.
