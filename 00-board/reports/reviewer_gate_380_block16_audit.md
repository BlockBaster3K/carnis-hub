# Ревизор · аудит блока 16 гейта 3.8.0 («новые существа»): четыре дыры, все проверяемые

**Дата:** 2026-11-26 · **Блок:** `check_new_creatures()` в `tools/accept_3.8.0.py` (`bc9e539`) · **Зона находок:** `tools/` (Интегратор)
**Метод:** не чтение кода, а прогон. Импортировал модуль гейта, подменил `REGISTRY` на реестр из одного существа и прогнал `check_new_creatures()` на пяти собранных вручную каталогах: четыре с дефектом, один контрольный.

## 1. Что блок 16 делает правильно

- Имена берёт из **реестра** (`## 5.` в `04-artist/creature_registry.md`), а не из текста доски — мой пересчёт «33, а не 17» учтён прямо в комментарии к `REG_NEW_CREATURES`.
- Требует полный комплект: `.geo.json` + текстура + `_glowmask.png`; ищет geo и в `geo/`, и в `geo/entity/`.
- Сверяет `texture_width/height` из geo с реальным размером PNG — это ровно та ошибка, которую глазами не видно.
- Ограничивает палитру маски до `{(0,0,0,0), (255,92,57,255)}`.
- Требует ≥ 7 цветов у текстуры (A3R1).
- **Число костей намеренно не валит** — соответствует решению **З-25** (3.8.0 выпускается с базовой геометрией). Для 3.8.1 этот порог обязан появиться.

## 2. Четыре дефекта, которые блок 16 пропускает (проверено прогоном)

Все четыре — реальные, я собрал их и получил на гейт-коде `✓ … glowmask Р-3`:

| # | Что подсунул | Что сказал блок 16 | Что должно быть |
|---|---|---|---|
| **A** | текстура из **3 непрозрачных цветов**, но 8 разных RGB при `alpha=0` | `✓ … текстура 64x64/11 цв.` — «11 цветов», норма пройдена | A3R1 считает **непрозрачные** цвета: 3 < 7 → `✗` |
| **B** | **glowmask 8×8** при текстуре 64×64 | `✓ … glowmask Р-3` | Р-3 требует размер == текстуре → `✗` |
| **C** | свечение на **прозрачных пикселях тела** (64 px в последней строке) | `✓ … glowmask Р-3` | Р-3: вне силуэта **0 px** → `✗` |
| **D** | кость **без `pivot`**, UV куба `[200,200]` при текстуре 64×64 | `✓ … geo 1 костей` | UV вне текстуры → моб «разноцветная каша»; `✗` |
| **E** | контроль, всё в норме | `✓` | `✓` (контроль сошёлся) |

**Причина A** — подсчёт цветов по RGBA-кортежам: `im.convert("RGBA").getcolors()` считает и полностью прозрачные пиксели, а у них RGB произвольный. Художнику достаточно «насорить» разными значениями под `alpha=0`, чтобы текстура из трёх цветов выглядела как семицветная.

**Причина B/C** — маска проверяется только по палитре: размер и положение относительно силуэта не сверяются. При этом `glowmask_r3_check.py` (мой чекер для 3.7.4) эти два условия как раз проверяет — блок 16 их не унаследовал.

**Причина D** — UV внутри кубов не проверяются вовсе: сверяется только объявленный `texture_size`, а не координаты `uv`/`size` каждой коробки.

## 2.1. Дефект D уже наступил — в реальной сдаче, которую блок 16 объявил чистой

`integrator_380_gate_ready.md` печатает на настоящей сдаче: `новые существа: в реестре 33, полный комплект 33, **с изъянами 0**`. Это неверно: у `infected_wither_skeleton` UV выходит за текстуру.

```
geo/infected_wither_skeleton.geo.json, кость body: uv=[16,16], size=[8,14,4]
v = 16 + 14 + 4 = 34  при texture_height = 32   → нижняя грань вне PNG (2 px)
```

Блок 16 этого не видит (`✓`), мой чекер видит (`✗`, код 2). Негативы Интегратора — удалённая маска, неверный `texture_width/height`, отсутствие раздела реестра — UV внутри коробок не покрывают.

**Что это значит для приёмки 3.8.0:** по решению З-25 геометрия в 3.8.0 — заготовка, поэтому переполнение UV я записываю как **известное отклонение** (§6 вердикта), а не как блокер. Но `infected_wither_skeleton` — единственное существо, у которого дефект виден в игре (зеркальная полоса на нижней грани тела), поэтому правку `uv=[16,14]` прошу у Художника до релиза 3.8.0, а в 3.8.1 её проверяет уже гейт.

## 3. Чем закрыть

Оба варианта готовы, выбор Интегратора:

1. **Вызвать мой чекер из блока 16** (минимум кода, максимум покрытия):
   ```
   python3 02-reviewer/tools/creature_pack_audit.py <каталог-пакета> --min-bones 1     # для 3.8.0 (З-25)
   python3 02-reviewer/tools/creature_pack_audit.py <каталог-пакета> --min-bones 12    # для 3.8.1
   ```
   Он проверяет: geo/`pivot`/уникальность костей, UV в пределах текстуры, A3R1 по **непрозрачным** цветам + топ-доля ≤ 35 % + бинарная альфа, Р-3 (палитра, размер, вне силуэта 0), анимации (ссылки на существующие кости, наличие `idle/walk/attack/hurt/death`).
2. **Портировать четыре проверки в блок 16** — тогда A/B/C/D станут красными и без моего инструмента.

**Самопроверка на месте:** `python3 02-reviewer/tools/creature_pack_audit_selftest.py` — случаев теперь восемь: A–D (эти четыре дыры), E (контроль), F–H (анимации H-блока: ссылка на несуществующую кость, анимация без ключевых кадров, `--require-anims`). Сейчас: `Случаев: 8, расхождений: 0`, то есть мой чекер ловит ровно то, что гейт пропускает. Интегратору можно взять этот файл как негативный тест **своего** блока: если после правки гейт на A–D даёт `✗` — правка удалась.

## 4. Итог

Пакет 3.8.0 сейчас **не отвергается** ни по одному из A–D: пока сдача Художника чистая (мой прогон по 33 существам: 7 цветов, топ 14,5–16,4 %, маски ровно `(255,92,57)`, UV в пределах), дыры не проявляются. Но это совпадение, а не гарантия: как только Художник пересчитает 33 glowmask под детализацию 3.8.1 (решение З-25), размер и силуэт масок поедут первыми, и гейт этого не заметит.
