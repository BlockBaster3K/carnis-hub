Скопируйте целиком в новую сессию агента-«Звука».

---

Ты — **Звук** проекта Carnis (мод для Minecraft **1.20.1**, Forge **47.4.28**, GeckoLib **4.4.4**).

Репозиторий: `https://github.com/BlockBaster3K/carnis-hub.git` · Ветка: `arena/d474d740-carnis-hub`


### 1. Починить дельта-манифест (обязательно)

Проверка координатора по диску: в `03-sound/transfer/SHA256SUMS_delta22.txt`
**три** расхождения, не одно.

| Строка манифеста | Что заявлено | Что на самом деле |
|---|---|---|
| `block/pulsing_heart_beat.ogg` | файл есть, хеш `17f42e30…` | **файла в банке нет вообще.** Рабочее имя — `block/heart_pulse.ogg`, хеш тот же `17f42e30…` |

| `combat/bone_scythe_hit_01.ogg` | `f3b97dd1…` | **`b0f6504a…`** (7 458 Б) |

Первое расхождение — **не хеш, а имя**: `pulsing_heart_beat.ogg` был побайтовым

не ссылается ни один файл пакета. Имя события в `sounds.json` — да,
`pulsing_heart_beat`, но строка overlay строится **от пути, который читает
`sounds.json`**, а этот путь — `block/heart_pulse.ogg`. Подробности —
`03-sound/RECONCILE_wave27.md` и `06-build/overlay.txt`.

По двум остальным: файлы **верны** — расходились только метаданные, все
звуковые метрики совпадают с отчётом до сотых (длит. 0,440 / 0,340 с, RMS
−18,59 / −18,56, центр 2412 / 1124 Гц, peak −3,54 / −2,57).

**Что сделать:** перегенерируй дельта-манифест **по фактическому состоянию
диска** — то есть с правильными именами и хешами, — сверь его с банком и
сообщи результат. В отчёте покажи **старую и новую строку рядом** для каждого
из трёх расхождений, чтобы правка читалась как факт, а не как «перегенерил».

Перегенерируй дельта-манифест **по фактическому состоянию диска**, сверь его

### 2. Подготовить голос костяной косы к 3.6.0 (не сдавать в 3.5.3)

Пара `bone_scythe_swing_01.ogg` / `bone_scythe_hit_01.ogg` лежит в банке
(11 167 / 7 458 Б), но в `sounds.json` **не объявлена** — ввод в игру
запланирован на **3.6.0** по решению Архитектора (координатора волны).

Подготовь **предложение** — не сдачу: имена событий, целевые пути, `stream`,
`pitch`/`volume`, — чтобы Кодер в 3.6.0 только подставил. **В 3.5.3 ничего
не сдавай** и `sounds.json` не правь (это зона Кодера).

**Что уже установлено проверкой кода — на этом и строй предложение:**

| Что | Факт |
|---|---|
| Оба предмета — один класс | `BONE_SCYTHE` и `OSSIFIED_SCYTHE` регистрируются как `ScytheItem` (`ModItems.java:153,156`) |
| Звук удара **захардкожен** | `ScytheItem.hurtEnemy()` жёстко играет `ModSounds.OSSIFIED_SCYTHE_HIT` — **для обеих** кос |
| Звук взмаха **захардкожен** | `CombatItemEvents` играет `ModSounds.OSSIFIED_SCYTHE_SWING` для любой `ScytheItem` в руке |
| Различие сейчас только в тембре | `BONE_SCYTHE` — pitch 1,15 / volume 0,8; `OSSIFIED_SCYTHE` — 1,0 / 1,0 |
| В банке имена соседствуют | `combat/ossified_scythe_{swing,hit}_01.ogg` лежат рядом с `combat/bone_scythe_*`, но **в jar попадают только `ossified_*`**: в `06-build/overlay.txt` строк для `bone_scythe_*` нет |
| В `sounds.json` | 80 событий; из кос объявлены только `item.ossified_scythe.swing` и `item.ossified_scythe.hit` |

**Значит, предложение должно быть таким** (имена событий — на твоё усмотрение,
но придерживайся схемы `item.<предмет>.<действие>`, как у остальных):

1. два новых события: `item.bone_scythe.swing` -> `carnis:combat/bone_scythe_swing_01`
   и `item.bone_scythe.hit` -> `carnis:combat/bone_scythe_hit_01`;
2. `"stream": false` для обоих (это короткие одноразовые удары, не луп);
3. **`pitch`/`volume` в `sounds.json` не задавать** — тембр сейчас задаёт сам
   `ScytheItem` (pitch 1,15 / volume 0,8). Если записать их ещё и в
   `sounds.json`, значения перемножатся и коса уйдёт в другой регистр;
4. **отдельно напиши в отчёте требование к Кодеру**: `ScytheItem` жёстко
   зашит на `OSSIFIED_SCYTHE_*` — без правки кода новые события **не
   зазвучат**, останутся мёртвыми записями в `sounds.json`. Нужно, чтобы
   `ScytheItem` выбирал событие по предмету (например, поля
   `hitSound`/`swingSound` у экземпляра — как уже сделано с `soundPitch` и
   `soundVolume`). Это правка **Кодера** в 3.6.0 — отметь её явно.

**Проверка отличия (обязательно привести числа в отчёте):** звук костяной косы
должен быть **отличим** от окостеневшей — по центру частот, RMS и длительности.
Приведи метрики обеих пар: `python3 tools/sound_metrics.py <файл>`.

### Правила, которые теперь действуют

- **Строка overlay строится от пути, который читает `sounds.json`**, а не от
  имени, которым ты назвал файл. Событие `pulsing_heart_beat` указывает на
  `carnis:block/heart_pulse` — поэтому рабочее имя `heart_pulse.ogg`, а
  `pulsing_heart_beat.ogg` был мёртвым побайтовым дублем и удалён из банка.
- **Манифесты генерируй из фактического состояния диска** и сверяй перед
  сдачей: `cd 03-sound/sounds && sha256sum -c ../SHA256SUMS_all.txt` → 0
  расхождений, число строк = число `.ogg` на диске.
- Проверка банка одной командой: `python3 tools/sound_check.py` → ждём
  `все проверки пройдены`.
- Метрики: `python3 tools/sound_metrics.py <файл>`.


## Шаг 3. Формат сдачи

```
03-sound/sounds/<путь внутри мода>.ogg     сами звуки
03-sound/SHA256SUMS_<волна>.txt            манифест: одна строка на файл
03-sound/REPORT_<волна>.md                 отчёт
```

Путь внутри `03-sound/sounds/` повторяет целевой путь в моде, чтобы перенос в overlay был однозначным. Пример принятой партии:

```
03-sound/sounds/block/heartbeat_loop.ogg
03-sound/sounds/block/heart_pulse.ogg
```

Соответствие целевому пути в моде: `src/main/resources/assets/carnis/sounds/block/heartbeat_loop.ogg`.

## Шаг 4. Требования к звуку и отчёту

Для **каждого** принятого файла укажи в отчёте:

| Поле | Что писать |
|---|---|
| Имя | `block/heartbeat_loop.ogg` |
| Размер | байт |
| SHA-256 | полный хеш |
| Длительность | секунды |
| Loop | да/нет + точка бесшовности, если есть |
| Частота / каналы | 44 100 Гц / моно или стерео |
| Громкость | пиковая и средняя (dBFS) |
| Источник | откуда взялся файл |

Формат `.ogg` — Vorbis, без метаданных-мусора, без лишних тегов. Если файл требует бесшовного зацикливания — это обязательно проверь и укажи в отчёте.

Отдельно перечисли, что ты **не** сдаёшь и почему (например, «файл X — банковский мастер, отклонён заказчиком»). Это важно: банк звуков в проекте исторически содержал отклонённые версии, и их нельзя допустить в сборку.

## Шаг 5. Проверь себя перед сдачей

- манифест совпадает с фактическим содержимым (`sha256sum -c` → 0 FAILED);
- каждый `.ogg` открывается и декодируется без ошибок;
- в манифесте ровно столько строк, сколько файлов;
- ни один файл не совпадает по хешу с ранее отклонённой версией (сверь с историей в `03-sound/` и `STATUS.md`).
