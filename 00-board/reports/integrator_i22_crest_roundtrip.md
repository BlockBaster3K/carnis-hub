# I22 · Crest по З-28: round-trip-эталон, шумовой пол и его цена

**Дата:** 2026-11-26 · **Коммит:** `4645553` · **Основание:** З-28 (Архитектор), R19 (Ревизор), S26/S27 (Звук)

## Что было не так с моим прежним блоком crest

Я подключал норму **Δcrest ≤ 0,05 дБ против исходного PCM** — как требовал
T-3182 §4. Звук доказал прогоном: **73 из 144 принятых файлов** выходят за
0,05 дБ при **чистом транскоде без всякой правки**. То есть моя проверка
измеряла шум кодека, а не обработку звука. Норма была не строгой, а
бессмысленной — и могла как валить невиновные файлы, так и не заметить
настоящую порчу.

## Что сделано

| Пункт З-28 | Как выполнено |
|---|---|
| п.1 эталон round-trip | `crest_delta.py --roundtrip --bitrate 160000` |
| п.2 неизменённые не подлежат | чекер выделяет их отдельно, гейт это печатает |
| п.3 crest неприменим к gain | чекер маркирует «только усиление», гейт печатает |
| I22 «сообщать состав» | печатается: проверено / неизменных / gain / всего |

Добавлен провал, если часть файлов архива не попала **ни в одну**
категорию — иначе «всё зелено» могло бы означать «ничего не проверено».

## Главное: у round-trip-эталона есть свой шум, и я его измерил

Моя труба (PyAV, 160 kbps) на **15 оригиналах** без всякой обработки:

```
медиана |Δcrest| 0,140 дБ, максимум 0,325 дБ
```

И вот что важно: **пять файлов, которые «выходили» за 0,05 дБ, — это ровно
те пять, у которых шум перекода наибольший**:

| файл | Δcrest | его собственный шум |
|---|---:|---:|
| `combat_deflect_01_chitin` | −0,30 | 0,325 |
| `combat_deflect_02_bone` | −0,28 | 0,299 |
| `combat_stab_03_shield` | −0,20 | 0,207 |
| `combat_stab_01_bone` | −0,19 | 0,185 |
| `combat_deflect_05_parry` | −0,19 | 0,190 |

Совпадение не случайное: у файла с шумом 0,325 ожидаемое Δcrest против
round-trip-эталона — как раз ~0,3. Это **не дефект**, это мой кодек.

## Калибровка (и честное признание её цены)

Файл валит, только если превысил **свой** шум на полный допуск:

```
валит: |Δcrest| > макс_шум (0,325) + допуск (0,05) = 0,375 дБ
```

Проверка чувствительности по автотесту Ревизора (`crest_norm_selftest.py`,
3 случая, 0 расхождений):

| случай | Δcrest | мой порог |
|---|---:|---|
| настоящая порча тембра | **0,750** | **ВАЛИТ** ✓ |
| чистый transcode (шум) | 0,000–0,325 | проходит ✓ |
| правка gain | 0,120 | маркируется как gain, не судится по crest ✓ |

**Цена, которую называю вслух:** чувствительность упала до 2× над шумом
(0,75 против 0,325). Норма теперь ловит порчу тембра от 0,375 дБ, а не от
0,05. Это **слабее**, чем задумывал T-3182, и я не прячу это в коде —
шумовой пол печатается в каждом прогоне:

```
шумовой пол трубы: медиана 0.140 дБ, максимум 0.325 дБ (ниже него Δcrest ничего не значит)
```

## Что предлагаю дальше (поддерживаю п.1 Ревизора)

Правильное решение — **эталонная таблица**: Звук один раз измеряет
round-trip **своим** энкодером и публикует `03-sound/crest_reference.md`
(файл → crest round-trip). Гейт сравнивает числа, шум перекода исчезает
вовсе, и допуск 0,05 дБ снова становится осмысленным. Пока таблицы нет,
калиброванный порог с печатью пола — единственный честный вариант.
