# Ревизор · З-18: что гейт 3.7.2 не проверяет (аудит самих проверок)

**Дата:** 2026-11-26 · **Объект:** `tools/accept_3.7.2.py` (819 строк) · **Метод:** чтение кода + пробы на синтетических каталогах (гейт не правил — его зона у Интегратора)

Повод — З-16: гейт напечатал `✓ Блоки: PNG 54, худший 32.8 % (6 цветов)` и пропустил текстуру с 6 цветами. Проверил, нет ли рядом ещё таких же «декоративных» проверок. **Нашёл три дыры, все воспроизвёл.**

## 1. Нет минимального числа цветов (это и есть З-16)

`_shade_scan()` (строки 428–497) знает только верхний порог `SHADE_MAX = 35 %`. Число цветов печатается, но **не сравнивается ни с чем**:

```
✓ Блоки: PNG 54, худший 32.8 % (6 цветов)      ← «6 цветов» никого не смутило
```

Правило «≥ 7 цветов» есть в ТЗ и в критерии T-3139, но в гейт не заведено. Цена: в 3.7.2 лежит **старый** `incubation_cyst.png` (6 цветов, `4e43c77db1e5`), хотя готовый фикс `04-artist/deliverables/Carnis_3.7.2_T3141_incubation_cyst.zip` (`7d30ac39dcf8`, 7 цветов, 14,5 %, 312 Б) лежит в репозитории с T-3141.

## 2. Полностью прозрачная текстура проходит молча — **доказано**

В цикле сканера: `if npx == 0: continue` — файл без единого непрозрачного пикселя **не попадает ни в `bad`, ни в счётчик худшего**.

Проба: каталог с одним `wiped.png` 64×64, α = 0 везде.

```
✓ Блоки: PNG 1, худший —              fail: []   код: 0
```

То есть затёртая (или ошибочно сохранённая без альфы) текстура проходит приёмку как «PNG 1, худший —». Сегодня такие файлы частично прикрывает блок 10 (`KEEP_IDENTICAL` vs 3.6.0-R), но **новые** текстуры T-3115/T-3141/T-3122 под ним не стоят.

## 3. Лимит 200 файлов обрезает скан и молчит об этом — **доказано**

`for p in files[:limit]` при `limit = 200`; в шапке при этом печатается **полное** `len(files)`.

Проба: 201 файл — 200 нормальных (8 цветов, топ 12,5 %) и последний по алфавиту `zzz_bad.png` (1 цвет, 100 %).

```
✓ Блоки: PNG 201, худший 12.5 % (8 цветов)     fail: []   код: 0
```

Сейчас в пакете 54 блока и 12 существ, до лимита далеко, но 3.7.3 добавляет текстуры, а строка «PNG 201» уже врёт о полноте проверки.

## 4. Ранее найденное, для полноты списка

| Код | Что не проверяется | Демонстрация |
|---|---|---|
| З-Г1 | клиппинг: без PyAV блок печатает «не декодировано», `fail` пуст → зелёный гейт | `_python_with("numpy")` вместо `"av"` |
| З-Г2 | нет нормы «пик ≤ −1,00 dBFS» и запаса ≥ 0,20 дБ: клипом считается только `peak >= 0 dBFS` (строка 646) | 15 файлов банка с запасом < 0,20 дБ проходят как «клип 0» |

## Что предлагаю (Интегратору — его зона `tools/accept_3.7.2.py`)

1. `_shade_scan(..., min_colors=None)`; при `ncol < min_colors` — в `bad`. Применять **не ко всем 54 блокам**, а к перекрашенным семействам: 24 файла из `Carnis_3.7.2_T3115_block_recolor.zip` + `incubation_cyst.png` из сдачи T-3141 + 8 тел A4-p7 + 4 щупальца A3R1.
2. `if npx == 0:` → `bad.append("<файл> — полностью прозрачная текстура")`, а не `continue`.
3. Лимит: либо снять, либо печатать `сканировано N из M` и добавлять `warn` при обрезке.
4. З-Г1: `_python_with("av")`; нет декодера → `fail`, не `warn`.
5. З-Г2: добавить проверку `peak > -1.00 + 0.20` (порог запаса — решение Архитектора) и `peak > -1.00` как норму.

## Итог

Пакет 3.7.2 сам по себе не пострадал ни от п.2, ни от п.3 (0 прозрачных текстур, 54 < 200) — **единственный фактический дефект остаётся З-16**. Но три дыры одного класса («напечатали число — не сравнили») означают, что зелёный гейт ещё не равен «всё проверено»; вердикт по 3.7.2 я держу закрытым до замены одного PNG.
