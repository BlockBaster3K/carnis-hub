## Шаг 3. Что должно лежать в папке сдачи

```
01-coder/<версия>/
├── project-<версия>-clean.zip          исходники проекта целиком
├── project-<версия>-clean.manifest.txt  внешний манифест: одна строка на файл
└── PHASE_F_<версия>_REPORT.md           твой отчёт
```

Требования к пакету:

1. **Имя ZIP строго `project-<версия>-clean.zip`**, манифест — `project-<версия>-clean.manifest.txt`. Имя в папке должно совпадать с номером версии, иначе CI соберёт не тот пакет.
2. **Внешний манифест** — одна строка на файл, формат `sha256␠␠путь` (два пробела), путь относительный, как в архиве. Сейчас в пакете 755 строк.
3. **Внутренний `MANIFEST.txt`** (внутри ZIP) — список путей: 2 строки заголовка + по одной строке на путь. Хешей в нём нет.
4. **Версия согласована в четырёх местах**: `gradle.properties` → `mod_version=<версия>`; `mods.toml` → `version="<версия>"` и `displayVersion="<версия>"`; `build.gradle` → `version = project.property('mod_version')`. `archives_base_name` остаётся `carnis` — итоговый jar будет `carnis-<версия>.jar`.
5. **Совместимость с 1.20.1 обязательна.** Только Mojmap-имена (никаких Yarn-имён вроде `getListenerRegistry`). Перед сдачей проверь каждый новый вызов API: метод должен существовать в официальных маппингах Mojang 1.20.1 и в Forge 47.4.28. Известные грабли этого проекта: `Level#getGameEventDispatcher` в 1.20.1 **не существует**; ручную регистрацию `GameEventListener` делать не нужно — vanilla `LevelChunk` регистрирует listener сам через `GameEventListener.Holder#getListener()`.
6. **Никаких локальных сборок.** В песочнице 1 ГБ RAM и JDK 11 — Gradle умирает от OOM. Сборку выполняет GitHub Actions. Ты не запускаешь `gradle build` и `runData`.

## Шаг 4. Проверь себя перед сдачей (правило «не на слово»)

```bash
# распаковать и сверить манифест
mkdir -p /tmp/chk && cd /tmp/chk && unzip -q ~/carnis-hub/01-coder/<версия>/project-<версия>-clean.zip
cd ~/carnis-hub/01-coder/<версия> && sha256sum -c project-<версия>-clean.manifest.txt | tail -3
```

Обязательно проверь и запиши числа в отчёт:

- число файлов в ZIP **= число строк в манифесте**, `sha256sum -c` → **0 FAILED**;
- все JSON разбираются (python `json.loads` по каждому `.json`);
- нет дублей resource-путей между `src/main/resources` и `src/generated/resources`;
- `mod_version` = номер папки;
- нет вызовов API, отсутствующих в 1.20.1.

## Шаг 5. Сдача

```bash
cd ~/carnis-hub
bash tools/agent_push.sh arena/d474d740-carnis-hub \
  "[coder] <версия>: <что изменил одной строкой>" \
  01-coder/<версия>
```

Скрипт сам перебазируется, если за это время кто-то уже отправил изменения, и не светит токен в списке процессов и в `.git/config`.

Push в `01-coder/**` **автоматически запускает CI-сборку**. Следи за прогоном: `https://github.com/BlockBaster3K/carnis-hub/actions`. Шаги `Build` и `Verify overlay reached the jar` должны стать зелёными.

**Если `Build` упал — логи прогона доступны тебе напрямую** (токен имеет `Actions: read`):

```bash
RUN=<номер_прогона>
curl -sL -H "Authorization: Bearer $GITHUB_TOKEN" \
  "https://api.github.com/repos/BlockBaster3K/carnis-hub/actions/runs/$RUN/logs" -o /tmp/logs.zip
mkdir -p /tmp/logs && cd /tmp/logs && unzip -qo /tmp/logs.zip
grep -nE "error:|FAILED|Execution failed|Could not resolve" * | head -40
```

Разбирай причину по тексту ошибки, а не по догадкам. Типовые причины этого проекта:
метод отсутствует в Mojmap 1.20.1 (проверяй по официальным маппингам Mojang), либо
конфликт версий зависимостей, либо битый ресурс. Починил — собери **пересдачу**
`01-coder/<версия>-R/` (старую папку не трогай) и отправь снова.
