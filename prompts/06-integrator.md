## ГЛАВНОЕ: СЕЙЧАС ТЫ НЕ БУДЕШЬ ПОЛУЧАТЬ ПРОМПТЫ ЧЕРЕЗ ЧАТ

Это **заключающий промпт волны 28**. До сих пор заказчик вручную копировал
промпт каждому агенту в чат. **Это больше не будет происходить.**

Новый принцип: **задачи лежат в самом репозитории.** Ты создаёшь в
репозитории **доску приказов** — специальный каталог, куда все агенты
заходят читать своё задание и куда пишут отчёты о работе. Заказчик больше
не участвует в передаче заданий: он только запускает агентов.

Твоя задача в этом промпте — **создать эту доску и описать правила** работы
с ней. Ничего больше. Никакого рефакторинга, никаких правок кода, никакой
приёмки пакетов — это потом, отдельными волнами.

## Твоя роль в проекте

Ты — **главный по репозиторию** (как работник библиотеки, который отвечает
за фонд и выдачу): приёмка, сборка, merge в `main`, релиз, акты в
`VERIFICATIONS/`, `STATUS.md`, overlay, workflow.

**Архитектор** (координатор волны) — это другой агент: он решает, что входит
в волну, и пишет приказы. Он **не** занимается репозиторием и **не** выдаёт
тебе файлы вручную. Твои входы — вердикт Ревизора в `02-reviewer/` и сдачи
остальных ролей в их зонах.

## Шаг 2. Что ты создаёшь — «доска приказов»

Создай каталог **`00-board/`** со следующей структурой. Имена каталогов и
файлов — **ровно такие**, на них потом ссылаются промпты остальных агентов,
менять их нельзя:

```
00-board/
├── README.md                 ← что это, правила, кто куда пишет
├── ROADMAP.md                ← полный план работ по версиям (заполнит Архитектор)
├── STATUS.md                 ← сводка: кто что делает сейчас, что сдано (заполняет Архитектор)
├── ROADMAP_koder.md          ← выжимка задач для Кодера (заполнит Архитектор)
├── ROADMAP_reviewer.md       ← выжимка задач для Ревизора (заполнит Архитектор)
├── ROADMAP_artist.md         ← выжимка задач для Художника (заполнит Архитектор)
├── ROADMAP_sound.md          ← выжимка задач для Звука (заполнит Архитектор)
└── reports/                  ← отчёты агентов (пишут сами агенты)
```

Ты сейчас создаёшь **пустую структуру с заголовками и заглушками** и подробно
описываешь правила в `00-board/README.md`. **Содержимое задач наполняет
Архитектор следующим шагом** — не выдумывай и не пиши за него рабочие задачи.

### Что пишешь в `00-board/README.md`

Обязательно эти разделы — от них зависит то, как остальные агенты будут работать:

1. **Что такое доска.** Одно предложение: «доска приказов — единственное место,
   где агент берёт задание и куда сдаёт отчёт; промпты через чат больше не
   передаются».
2. **Как взять задание.** Точная последовательность:
   ```bash
   git pull --rebase origin arena/d474d740-carnis-hub
   cat 00-board/ROADMAP_<своя_роль>.md
   ```
   Подчеркни: **сначала `git pull --rebase`**, потом чтение. Без этого агент
   прочитает устаревшую версию доски (клон делается с `--depth 1`).
3. **Куда писать отчёт.** Формат: `00-board/reports/<роль>_<что_сделано>.md`.
   Правило: **один отчёт = одна сдача**, имя содержит роль и дату.
4. **Кто что пишет — таблица прав:**
   | Кто | Что читает | Что пишет |
   |---|---|---|
   | Кодер | всё | `ROADMAP_koder.md` **не правит**; свои файлы — `01-coder/<версия>/`; отчёт — `reports/` |
   | Художник | всё | `04-artist/`; отчёт — `reports/` |
   | Звук | всё | `03-sound/`; отчёт — `reports/` |
   | Ревизор | всё | `02-reviewer/`; отчёт — `reports/` |
   | Интегратор | всё | `06-build/`, `07-project/`, `VERIFICATIONS/`, `STATUS.md`; отчёт — `reports/` |
   | Архитектор | всё | `05-architect/`, `00-board/ROADMAP*.md`, `00-board/STATUS.md` |

   Ключевое правило, вынеси его отдельно и крупно:
   **все читают всё, но каждый правит только свой участок.** Правку чужой
   зоны — в отчёт и ждать решения Архитектора.
5. **Порядок работы волны** — зафиксируй конвейер, чтобы никто не начал
   делать всё подряд:
   ```
   Архитектор → приказы в доске
        ↓
   Кодер + Художник + Звук   (параллельно, каждый по своей выжимке)
        ↓
   Ревизор   (проверяет по факту, не по отчётам)
        ↓
   Интегратор (приёмка → CI → merge в main → релиз → акты)
   ```
   И правило ожидания: **Ревизор начинает, только когда пакет Кодера физически
   лежит в репозитории; Интегратор — только после вердикта Ревизора.** Никто
   не выносит вердикт «по отчёту».
6. **Handshake.** Перед началом работы каждый агент обязан **прочитать доску и
   отчитаться**, не начиная работу: «прочитал `ROADMAP_<роль>.md` на коммите
   `<хэш>`, понял задачу, готов». Хэш коммита обязателен — так видно, что все
   читали одно и то же. Формат отчёта — в `reports/`.
7. **Свежесть.** Правило `git pull --rebase` перед каждым чтением доски и
   перед сдачей.

### Что ты НЕ делаешь

- **Не наполняешь `ROADMAP*.md` задачами** — это работа Архитектора.
- **Не пишешь код и не правишь чужие зоны.**
- **Не делаешь приёмку пакетов** — 3.5.3 примут позже, после вердикта Ревизора.
- **Не трогаешь `.github/workflows/`, `06-build/`, `VERIFICATIONS/`, `STATUS.md`**
  в этой задаче — кроме `STATUS.md` в `00-board/`, которая новая и твоя по
  этой задаче.

## Шаг 4. Проверь себя перед сдачей

- `00-board/` существует, в нём **ровно** перечисленные файлы и каталог
  `reports/`;
- `00-board/README.md` содержит **все семь** разделов из шага 2 — проверь
  по списку, а не «на глаз»;
- каждый `ROADMAP_*.md` — заголовок-заглушка с указанием, что задачи наполняет
  Архитектор (не пустой файл, а файл с шапкой: роль, версия, дата, статус);
- `00-board/reports/` — **пустой** каталог. Git не хранит пустые каталоги,
  поэтому положи внутрь `.gitkeep` (пустой файл) — иначе каталог не попадёт
  в репозиторий;
- в `00-board/README.md` **нет** токена и нет упоминаний секретов;
- `git status` чистый после сдачи.

## Шаг 5. Отчёт заказчику

1. **полный путь** созданного каталога и **sha256** `00-board/README.md`;
2. **дерево** доски (`find 00-board` или `ls -R`) — чтобы заказчик увидел
   структуру;
3. **разделы** README — перечисли семь заголовков, как они легли;
4. **хэш коммита**, которым ты сдал, — Архитектор пишет задачи начиная с него;
5. отдельно: **если ты переименовал каталог или файлы** (например, выбрал
   другое имя) — напиши это явно и **полностью**, потому что Архитектор будет
   писать по этим путям, и промпты остальных агентов ссылаются на них.

Токен не публикуй.

## Шаг 6. Что будет дальше — чтобы ты понимал последовательность

1. Ты создаёшь доску и описываешь правила (этот промпт).
2. **Архитектор** наполняет `ROADMAP*.md` полным планом работ и сдаёт это
   тем же коммитом.
3. **Архитектор** готовит промпты Кодеру, Ревизору, Художнику и Звуку с
   новым принципом: открыть репозиторий → прочитать свою выжимку →
   **отчитаться, не начиная работу**.
4. Заказчик запускает всех четверых. Они отчитываются «прочитал, понял,
   готов».
5. Только после этого заказчик даёт отмашку на работу, и начинается
   пошаговый цикл: параллельная работа → Ревизор → Интегратор.

**Твоя часть сейчас — только шаги 1–5 этого промпта.** Дальше тебя подключат

## Очистка рабочего места (после сдачи результата)

После того как результат сдан и подтверждён — очисти своё рабочее место.
Полная инструкция: `cat prompts/cleanup-workspace.md` (или файл рядом с этим промптом).

Коротко: удали **только своё** — временные клоны, выходы сборки, архивы, кэши,
untracked-мусор. Не трогай tracked-файлы, `.git`, исходники и чужие зоны.
`git clean -fdx` вслепую не запускай. Закончи с пустым `git status --short`
либо перечисли в отчёте оставшиеся намеренные untracked-файлы.

В финальном отчёте укажи: путь рабочего каталога; что удалил; результат `git status --short`.
