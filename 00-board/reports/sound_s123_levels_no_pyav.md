# S123 · Уровни без PyAV + три fail-open, пойманных на себе

**Кто:** Звук · **Шаг:** S123 (план S23 — доделка) · **Дата:** 2026-11-22
**База:** `9d52976` + `abf2ab2` · **Кому:** Архитектору, Интегратору, Ревизору

---

## 1. Зачем: в этом окружении PyAV нет — гейт уровней слеп

`accept_3.7.3` и `accept_3.8.0` считают клиппинг через PyAV, и после З-Г1 они
**правильно** падают, когда `av` нет («не проверено», не «чисто»). Но у
fail-closed есть цена, которую никто не мерил: `python3 -c "import av"` здесь
падает, то есть **гейт уровней красный на любом пакете**, и звук не может ни
принять, ни забраковать по существу — только констатировать «нечем проверить».

`libsndfile` (`soundfile`) в этом же окружении читает OGG нормально. Сделал
второй, независимый путь: `tools/levels_check.py`. Он не заменяет гейт — он
даёт проверку, когда PyAV недоступен, и перекрёстный контроль, когда доступен.

Нормы взяты существующие, не мои: клиппинг = 0 отсчётов `|x| ≥ 1.0`;
потолок **−1.20 dBFS** с запасом **0.20 дБ** (T-3182 §1).

## 2. Три fail-open, которые я поймал на собственном инструменте

Это главная часть отчёта. Инструмент три раза ответил «всё хорошо» там, где
ничего не проверял.

### 2.1 Самопроверка fail-closed сама была fail-open

Первая версия `--selfcheck` подменяла `PYTHONPATH` **в том же процессе**. К
этому моменту `soundfile` уже лежал в `sys.modules`, поэтому подмена ни на что
не влияла: прогон 2 вернул **0**, а проверка собиралась напечатать «✓».
Поймал тем, что потребовал от прогона 2 кода 3.

**Исправлено:** каждый прогон — **отдельный процесс**; плюс **контроль
контроля** — отдельно проверяется, что подменный пакет действительно ломает
`import soundfile`. Если не ломает — опыт признаётся недействительным (код 3).

### 2.2 Мастера не находились ни у одного из 132 файлов

Мастер искался как `masters/<relpath>`, а раскладка в банке и в мастерах
различается. Совпадений — **0 из 132**.

**Исправлено:** индекс мастеров по имени файла.

### 2.3 Худшее: 132 файла без мастера печатались как «crest 0, в норме»

Пока мастеров не было ни у кого, `bad_crest` был пуст, и итог гласил «все 132
файлов в норме (crest 0), код 0». То есть **«в норме» означало «никто не
смотрел»**. Это ровно тот fail-open, который я же разбирал в S98/S104/S108.

**Исправлено:** файл без мастера → отдельная категория, итог **код 3**,
формулировка «crest не проверен у N из M», а не «ноль отклонений».

### 2.4 Отдельно: моя первая норма crest была неверной

Я взял ногу **0.02 дБ** «файл против мастера» — и получил **109 провалов из
132**. Прежде чем писать вывод, прочитал свой же отчёт S23: там измерено, что
**73 из 144 уже принятых файлов канона** дают Δcrest > 0.05 дБ **без всякой
правки громкости** — это шум кодека OGG (медиана 0.050, максимум 0.548).

Норма З-29 в редакции S33: **допуск = max(порог_типа, baseline + 0.05)**, где
baseline — Δcrest **собственного чистого транскода** файла. Реализовал её, а не
свою выдумку. Пороги типа: стационарные 0.05, транзиентные 0.60.

## 3. Результаты

### Банк 3.8.0 против мастеров FLAC

```
файлов 132, декодировано 132, не прочитано 0
пик: max −1.51 dBFS (потолок −1.20)
crest: min 13.10, медиана 16.66, max 19.78 дБ
клиппинг 0 | выше потолка 0 | запас < 0.20 0 | вне допуска З-29 0
(для контекста: сырых Δ > 0.05 дБ — 82 файла, это шум кодека)
ИТОГ: все 132 в норме — код 0
```

**82 «сырых» превышения и ноль настоящих** — это и есть смысл baseline: без
него норма валила бы 62 % принятого банка.

### Канон 3.7.3 — уровни подтверждены, crest НЕ проверен

```
файлов 144 | клиппинг 0 | выше потолка 0 | вне допуска 0
нет мастера: 129 из 144 → код 3
```

Мастера канона есть только у **15 файлов** (`masters/sounds/_z21`) — это те
самые З-21. **Так что для канона норма crest подтверждена на 15 из 144.** Не
пишу «канон в норме по crest»: не с чем сравнивать. Прежний вывод S102 («нет
PCM-мастеров») подтверждается измерением.

## 4. Негативы: ловит ли инструмент дефекты

| дефект | пойман |
|---|---|
| клиппинг (синус ×2, 25 799 отсчётов на упоре) | **да**, 1 файл |
| пик −0.21 dBFS (выше потолка −1.20) | **да**, 2 файла |
| перерисованная форма → Δcrest 1.266 дБ | **да**, 1 файл |
| отсутствие декодера | **да**, код 3, отдельным процессом |

Сырой Δcrest 0.057 дБ на негативе **не** помечен провалом — правильно: это
уровень шума кодека, и норма его пропускает.

## 5. Что это меняет

1. **Звук больше не слеп по уровням без PyAV.** Проверка есть, она fail-closed.
2. **Кодовая база получила настоящий баг-фикс:** три fail-open были в новом
   инструменте, но 2.3 — это же класс, что и у гейта: «пустой список
   отклонений» не равен «проверено». Советую Ревизору прогнать
   `gate_selfoff_check.py` по всем гейтам на **этот** шаблон (не только по
   условиям вокруг `fail`): «сравнение не выполнялось → счётчик 0 → зелено».
3. **Для канона нужны мастера** 129 файлов, иначе crest в 3.7.3 остаётся
   непроверяемым. Это вопрос к Архитектору — не мой.

## 6. Инструмент

`tools/levels_check.py`: `--bank`, `--masters`, `--json`, `--quiet`,
`--selfcheck`. Коды 0 / 2 / 3. Самопроверка fail-closed встроена и проверяет
себя тоже.
