## Задачи

### Д1 — накладка звука: пауза между ударами схлопывается

**Где:** `FleshBulbBlockEntity.java:53`

Сейчас пауза считается как `phase = bulb.age % interval`, где `interval` меняется
**каждый тик**. Из-за этого реальные паузы «схлопываются»: моделирование
(`age` 1…`duration`, `duration` 1200/1500/1800) даёт минимум **2–5 тиков** при
звуке в 12 тиков → удары накладываются, 8–9 раз за цикл.

**Что сделать:** остаток от деления на меняющийся интервал **оставить нельзя** —
нужен **накопитель** (например, поле «тик следующего удара» и сравнение с `age`).

**Критерий приёмки:** приёмка считается **по паузе между фактическими стартами
звуков**, а не по номинальному `interval`.

- Требование: пауза **≥ 13 тиков на всём цикле** — не в среднем и не на типичном
  участке, а **в минимуме по всем трём длительностям** (`duration` 1200/1500/1800,
  `age` 1…`duration−1`).
- **Номинальный `interval` сам по себе критерием не является.** Значение
  `interval` в коде может выглядеть достаточным и при этом давать короткие паузы —
  именно это и случилось в Д1. Считать надо старты, а не интервал.
- **Накопитель обязателен.** Остаток от деления на меняющийся интервал
  (`age % interval`) не годится: нужен накопитель — например, поле «тик
  следующего удара» и сравнение с `age`. Решение без накопителя не принимается,
  даже если моделирование случайно даёт ≥ 13.
- В отчёте покажи **нижний предел паузы числом** и как он получен (метод
  моделирования, диапазон `age`, значения `duration`).

**Не исправляй формально.** «Появилось новое поле» — не результат; результат —
число, из которого видно, что наложения больше нет.

### Д5 — геометрия Нексуса

**Где:** `.geo.json` Нексуса

Сейчас 5 компланарных пар и 3 мёртвых куба.

**Что сделать:** убрать компланарные пары и мёртвые кубы.

**Критерий приёмки:** геометрия **изменилась байтами** против принятой
(26 846 Б); **0 видимых компланарных пар** и **0 мёртвых кубов**; файл валидный JSON.

**«Видимых» — это важно, и считать надо именно так:**

- нижние грани на уровне земли (**2 пары**) в счёт **не идут** — они не видны;
- пары, полностью скрытые третьим кубом (**4 пары**), в счёт **не идут** — тоже
  не видны;
- требование «0 пар вообще» **не ставится**: иначе пришлось бы переделывать
  `/root` и `/crown`, а это в задание не входило.

Методику подсчёта видимых пар **выпиши в отчёт**: какие пары считал, какие
исключил и почему. Ревизор будет считать тем же способом, и формулировка
«убрал все пары» без списка — не результат.

### Д6 — окостеневшая плоть: разброс

> ⚠️ **Исправлено решением координатора (2026-11-25).** В прежней редакции
> «Где» указывало на `MultifaceSpreader` (`FleshVeinsBlock.java:23`) — **это
> ошибка адресации**: `MultifaceSpreader` — код распространения жил, он разброс
> цветов не задаёт. Ниже — правильная постановка.

**Что измеряется.** Разброс — это метрика **текстур**, не кода: максимум
попарной разницы средних цветов вариантов `ossified_flesh`.

**Методика (волна 22), выписана полностью:**

1. берутся четыре файла `ossified_flesh_0.png` … `ossified_flesh_3.png`
   из `src/main/resources/assets/carnis/textures/block/`;
2. для каждого считается среднее по каналам R, G, B **только по полностью
   непрозрачным пикселям** (альфа = 255); 8-битный sRGB, без гамма-коррекции;
3. для каждой из **шести пар** считается `(|ΔR| + |ΔG| + |ΔB|) / 3`;
4. **разброс = максимум по шести парам**.

**Порог: ≤ 12.** Текущее значение — **41,25** (худшая пара
`ossified_flesh_2` ↔ `ossified_flesh_3`).

**Инструмент — в репозитории, общий:** `tools/flesh_spread.py`.

```bash
python3 tools/flesh_spread.py <каталог с PNG>
```

Печатает средние RGB по каждому файлу, все шесть пар, `РАЗБРОС = …` и
`ИТОГ: СХОДИТСЯ` / `ИТОГ: ЕСТЬ ЗАМЕЧАНИЯ`. Код возврата `0` при ≤ 12, `2` при
превышении. Прогнал сам на пакете `3.5.2-R` — даёт **41.25**, сходится с
замером волны 22.

**Что делать тебе:**

- **код не трогать** — `MultifaceSpreader` / `FleshVeinsBlock` к Д6 отношения
  не имеют, правка там ничего не изменит;
- **ждать файлы в репозитории**: четыре PNG `ossified_flesh_*.png` придут от
  Художника отдельной партией (см. `ROADMAP_artist.md`, Д6). Пока их нет —
  задача не выполнима, и подменять её правкой кода нельзя;
- когда файлы придут — положить их в пакет по целевым путям и **пересчитать
  разброс тем же скриптом**.

**Критерий приёмки:** `tools/flesh_spread.py` по четырём PNG в пакете даёт
**РАЗБРОС ≤ 12** и `ИТОГ: СХОДИТСЯ`. В отчёте — новое значение числом и
вывод скрипта. Ревизор пересчитает тем же скриптом.

```

├── project-3.5.3-clean.zip          исходники проекта целиком
├── project-3.5.3-clean.manifest.txt  внешний манифест: одна строка на файл

```

1. **Имя ZIP строго `project-3.5.3-clean.zip`**, манифест —
   `project-3.5.3-clean.manifest.txt`. Имя в папке должно совпадать с номером
   версии, иначе CI соберёт не тот пакет.
2. **Внешний манифест** — одна строка на файл, формат `sha256␠␠путь` (два
   пробела), путь относительный. Сейчас в пакете 755 строк.
3. **Внутренний `MANIFEST.txt`** (внутри ZIP) — список путей: 2 строки
   заголовка + по одной строке на путь. Хешей в нём нет.
4. **Версия согласована в четырёх местах**: `gradle.properties` →
   `mod_version=3.5.3`; `mods.toml` → `version="3.5.3"` и
   `displayVersion="3.5.3"`; `build.gradle` → `version = project.property('mod_version')`.
   `archives_base_name` остаётся `carnis` — итоговый jar будет `carnis-3.5.3.jar`.
5. **Совместимость с 1.20.1 обязательна.** Только Mojmap-имена (никаких
   Yarn-имён вроде `getListenerRegistry`). Перед сдачей проверь каждый новый
   вызов API: метод должен существовать в официальных маппингах Mojang 1.20.1
   и в Forge 47.4.28.
6. **Никаких локальных сборок.** В песочнице 1 ГБ RAM и JDK 11 — Gradle умирает
   от OOM. Сборку выполняет GitHub Actions. Ты не запускаешь `gradle build` и `runData`.
