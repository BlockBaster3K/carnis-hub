## Партия 2 — Д6: `ossified_flesh`, разброс средних цветов

**Отдельная партия, сдаётся отдельно от A3/A6.** Это **новая** задача волны 29
(решение координатора): раньше Д6 стояла только у Кодера и была невыполнима —
файлы не приходили. Теперь источник — ты.

### Что чинится

Четыре варианта `ossified_flesh_0…3` различаются по средней светлоте слишком
сильно: текущий **разброс = 41,25** при пороге **12**(худшая пара
`ossified_flesh_2` ↔ `ossified_flesh_3`).

### Что требуется

1. **Разброс ≤ 12** по методике волны 22 (см. ниже). Это главный критерий.
2. **Средний тон одинаковый** у всех четырёх вариантов — они должны читаться
   как один материал, а не как четыре разных блока.
3. **Различие между вариантами — в структуре, а не в цвете.** Варианты должны
   оставаться различимыми: рисунок трещин/прожилок у каждого свой. Свести всё
   к четырём копиям одной картинки нельзя — тогда разброс 0, но вариантов нет.
4. **Проверка скриптом, обязательно.** Инструмент уже в репозитории:

   ```bash
   python3 tools/flesh_spread.py <каталог с PNG>
   ```

   Печатает средние RGB по файлам, все шесть пар, `РАЗБРОС = …`,
   `ИТОГ: СХОДИТСЯ` / `ИТОГ: ЕСТЬ ЗАМЕЧАНИЯ`. Сдавать можно только с
   **`ИТОГ: СХОДИТСЯ`** и кодом возврата `0`.
   Прогнал на пакете `3.5.2-R` — даёт **41.25**, методика воспроизводится.

### Методика измерения (та же, что у Кодера и Ревизора)

1. четыре файла `ossified_flesh_0.png` … `ossified_flesh_3.png`;
2. для каждого — среднее по R, G, B **только по непрозрачным пикселям**
   (альфа = 255), 8-битный sRGB, без гамма-коррекции;
3. для каждой из **шести пар** — `(|ΔR| + |ΔG| + |ΔB|) / 3`;
4. **разброс = максимум по шести парам**.

### Формат сдачи — архив с PNG по целевым путям

```
04-artist/deliverables/Carnis_3.5.3_ossified_flesh.zip
   └── src/main/resources/assets/carnis/textures/block/ossified_flesh_0.png … _3.png
04-artist/deliverables/SHA256SUMS.txt      ← дополнить, не заменить
04-artist/deliverables/REPORT_3.5.3_ossified_flesh.md
```

Внутри архива PNG лежат **по целевым путям** (как в Д7) — Кодеру останется
подставить их как есть, без переименований.

**Критерий приёмки:** разброс **≤ 12** скриптом `tools/flesh_spread.py`,
средние тона совпадают, структура у вариантов разная, архив содержит 4 PNG
по целевым путям, `SHA256SUMS.txt` обновлён (`sha256sum -c` → 0 FAILED).

**Куда идёт:** в пакет `3.5.3` — **Кодер ждёт эти файлы** (см.
`ROADMAP_koder.md`, Д6). Пока их нет, Д6 у Кодера не выполнима.

## Партия 3 — A3/A6: `creeping_tendrils` p6 ч.2

**Вторая твоя задача в этой волне.**

### Почему четыре пробы провалились

Проблема **не в рисунке**, а в **самопротиворечивом критерии**: требование
«кромки у всех вариантов одинаковы» + требование «содержимое не прижато к
краю» вместе заставляют оставить **пустое кольцо** по краю плитки. На стене
такое кольцо превращается в **прозрачную решётку**, проходящую через всю стену,
— и рисунок читается как «изолятки в клетках», а не как ткань.

**Поэтому критерий торцов переформулирован (решение Архитектора, волна 28):**
кромка должна быть **одинакова у всех вариантов** (это проверка 3) и
**содержимое должно доходить до кромки**, чтобы плитки смыкались в сплошную
ткань. Запрет остаётся один: вдоль кромки **не должно быть длинной прямой
полосы**, и углы **не должны быть забиты**.

### Твоя стратегия

- ткань **доходит до кромки** и смыкается с соседней плиткой без разрыва;
- линия **≤ половины плитки** (32 px);
- штрих **толщиной ≥ 8 px** (≥ 2 px в проекции 16 px);
- **3–4 варианта**, 64×64, RGBA, **альфа только 0 или 255** — полупрозрачных
  пикселей нет, иначе стена «мылится».

**Целевой путь в моде:**
`src/main/resources/assets/carnis/textures/block/creeping_tendrils.png`
(мод-блок `creeping_tendrils`, его модель тянет `carnis:block/creeping_tendrils`).
Сейчас там 16×16 — нужно **64×64**.

### Критерии приёмки — все шесть

1. попарный **seam** (стыки вариантов без щели);
2. сетка **3×3** и **5×5** со смешением;
3. **совпадение кромок** (побайтово: верх/низ совпадают, лево/право совпадают,
   и у **всех** вариантов кромка одна и та же);
4. **читаемость в 16 px**;
5. **торцы и углы** — переформулированы: кромка заполнена (≥ 45 % непрозрачных
   в полосе шириной 3 px), вдоль кромки нет прямой полосы длиннее 24 px, углы
   не забиты (≤ 10 из 16 px);
6. **нет решётки** — на стене из смешанных плиток прозрачные дорожки между
   плитками не образуют равномерную сетку. Проверка: средняя альфа у границы
   плитки в проекции 16 px не ниже **35 %** от альфы внутри плитки.

### Готовый инструмент самопроверки — пользуйся им

В репозитории лежит **проверяющий стенд**, который прогоняет ровно эти шесть
критериев и печатает числа: `tools/tendrils/`.

```bash
cd ~/carnis-hub
mkdir -p /tmp/tv && cp <свои варианты> /tmp/tv/
python3 tools/tendrils/tendrils_check.py /tmp/tv /tmp/tv/SELFCHECK.json
```

Итог одной строкой: `ИТОГ: ВСЁ СХОДИТСЯ` или `ИТОГ: ЕСТЬ ЗАМЕЧАНИЯ`.
**Сдавать можно только с `ИТОГ: ВСЁ СХОДИТСЯ`** — иначе приёмка снова
провалится на том же месте. Если стенд ругается на конкретный пункт — чини
именно его, а не перегенерируй всё заново; в выводе видно, что именно не так.

Инструмент лежит в `tools/` — это **общая зона**: там же им проверит Ревизор.
Не правь его содержимое; если стенд кажется несправедливым к твоей картинке —
напиши об этом в отчёте, разбор будет на стороне координатора.

## Требования к графике — для каждого файла

| Поле | Что писать |
|---|---|
| Файл | `entity/horror/bone_scythe.png` |
| Размер | байт |
| SHA-256 | полный хеш |
| Разрешение | 64×64 или 32×32 |
| Формат | PNG, RGBA |
| Целевой путь в моде | `src/main/resources/assets/carnis/textures/entity/horror/bone_scythe.png` |
| Что заменяет | «заменяет старую текстуру в `3.5.1-R2`» |

Правила по размерам, принятые в проекте:

- **64×64** — блоки, предметы, большинство существ;
- **32×32** — оружие и инструменты (косы, молотки, резаки);
- атласы — тоже 64×64 на ячейку, с указанием сетки в отчёте.

Целевые пути берутся из пакета Кодера в
`01-coder/<версия>/project-<версия>-clean.zip` — **сверяйся с ним**, а не по
памяти: путь текстуры должен совпасть с тем, что ожидает мод.
