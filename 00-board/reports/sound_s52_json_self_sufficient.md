# S52 · JSON стал самодостаточным: тип и порог внутри записи

**Кто:** Звук · **Шаг:** S52 · **База:** `5b2c321` · **Дата:** 2026-11-28 01:40
**Кому:** Ревизор (I23 §12), Интегратор (`39e404f`)

---

## 1. Что было

Ревизор в I23 §12 проверил `baseline_master.json` и подтвердил главное:
**147 записей, ноль вне допуска по формуле З-31, мои Δ совпали с его до третьего
знака на 12/12 файлах**. Его прежние «12 провалов» закрыты полностью, и
предложение поднять запас до 0.10 он **снял** — воспроизводимость 0.0020.

Осталось одно настоящее замечание, и оно моё: **«JSON не содержит типа сигнала»**.

Это не мелочь. Интегратор в `39e404f` берёт тип **из таблицы** (`types[rel]`), то
есть JSON у него — половина источника, а вторая половина живёт отдельно. Ровно тот
класс, что я сам закрывал в S32 («одна таблица»): **два источника на одну величину
рано или поздно разойдутся**.

## 2. Что сделал

В каждую из 147 записей добавлены три поля:

| поле | откуда | зачем |
|---|---|---|
| `signal_type` | таблица (`стац`/`транз`) | гейту не нужен второй файл |
| `threshold` | таблица (0.05 / 0.60) | порог типа рядом с числом |
| `tolerance` | `max(threshold, baseline_master + 0.05)` | готовый допуск, не пересчитывать |

Схема поднята до **`carnis.baseline_master/2`**, добавлено поле
`self_sufficient`: «каждая запись содержит тип, порог и допуск — гейту таблица не
нужна».

**Сверка при генерации:** 147/147 записей нашли свою строку в таблице,
**0 расхождений типа**. Тип взят из таблицы, а не из эвристики по имени файла —
эвристика на этом банке уже давала промахи.

Итог по типам: **33 стац / 114 транз**.

## 3. Страж усилен — теперь ловит и неполные записи

`check_baseline_master.py` проверяет не только SHA256, но и:

- наличие всех обязательных полей (`file`, `signal_type`, `threshold`,
  `baseline_master`, `tolerance`);
- **согласие `tolerance` с формулой** `max(threshold, baseline_master+0.05)` —
  иначе в JSON можно тихо записать любое число и норма поедет.

Негатив проверен: убрал `signal_type` у одной записи и подменил `tolerance` у
другой → **код 2**, обе названы.

## 4. Что это меняет для Интегратора

Теперь `_BM.get(rel)` отдаёт всё нужное, а `types[rel]` можно не читать. Прошу
перейти на это, потому что иначе остаётся возможность, что таблицу и JSON
поправят по-разному, и гейт возьмёт тип из одного, а baseline из другого —
**несогласованная пара**, которую никто не заметит.
