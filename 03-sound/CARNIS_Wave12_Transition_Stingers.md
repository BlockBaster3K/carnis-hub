# CARNIS — Волна 12: AMB_HIVE_TRANSITION_STINGER

**Задача.** Переход между зонами беззвучен: игрок пересекает границу «периферия → ядро» и не получает сигнала. Три коротких stinger'а завершают зональную систему волны 11.

**Сделано:** 3 файла (`zone_stinger_intensify` 2.40 с, `zone_stinger_release` 1.70 с, `zone_stinger_deep` 2.80 с), исследование, конструкция, метрики, профили, `sounds.json`, субтитры, Java-интеграция переходов, чек-лист.

**Плюс по протоколу Архитектора:** файлы волны 11 переименованы и перенесены в `src/main/resources/assets/carnis/sounds/hive/` (`hive_amb_*` → `amb_*`). Карта путей — в §7.

---

## 0. Главное из исследования: почему «суб-дроп» делают неправильно

Стандартный рецепт суб-дропа — «синус 150 → 30 Гц». Замерьте это на ноутбуке, и вы услышите тишину: на 30 Гц динамик 3 Вт не выдаёт почти ничего, а ухо на 30 Гц имеет порог на 40–50 дБ выше, чем на 1 кГц. ТЗ требует **спектр 50–2000 Гц** — и это не ограничение, а подсказка: суб должен быть **слышимым**, а не «чувствуемым», потому что stinger играет один раз и не может рассчитывать на сабвуфер.

Отсюда три решения, на которых построена вся волна:

1. **Каждый низкий «голос» — это гармонический ряд, а не синус.** `tone_harm(f, nharm=5, tilt≈0.75)` даёт основной тон плюс гармоники с затуханием `k^−0.75`. На 40 Гц тело слышно через 2-ю и 3-ю гармоники (80, 120 Гц), а сама 30–50 Гц полоса остаётся на месте для тех, у кого есть саб.
2. **Поток идёт вниз или вверх по спектральному центру, и это измеримо.** У `deep` центр за 2.8 с: **367 → 125 → 91 Гц** (погружение). У `intensify` начало: **975 → 554 → 208 Гц** (всасывание вверх, потом тело внизу). У `release` наоборот: уходит вниз и потом гаснет. Траектория центра и есть «направление» перехода.
3. **«Мембрана» — это не звук натяжения, а звук ПЕРЕХОДА объёма.** Всасывание (suction) делается не свипом синуса, а свипом **центра полосы шума** — так же, как волна 9 делала присасывание блока. Синус на такой траектории даёт «свист», шум — «всасывание воздуха».

И четвёртое, чисто психологическое: **release не должен быть просто «intensify наоборот»**. Обратное всасывание читается как «втянуло обратно». Поэтому у `release` есть то, чего нет у `intensify` — **выдох**: шесть полос поочерёдно, с задержкой 55 мс, уходят вниз и гаснут. Мембрана не просто ослабла, из неё вышел воздух.

## 1. Конструкция

### 1.1 `zone_stinger_intensify` — 2.40 с, «оно заметило»

```
0.00–0.62   всасывание: 7 полос 200/400/800/1300/1900/2600/3400 Гц, выдох вверх
0.00–0.55   воздух: свип центра 220 → 900 Гц (шум, не синус)
0.55        напряжение: щелчок 300–1400 Гц, 220 мс, тихий (−22 дБ от пика)
0.58–2.10   тело 55–140 Гц: гармоники + шум-партнёр в той же полосе
0.62–1.60   roughness: AM 40 Гц, глубина 35 %
1.60–2.40   спад, последние 300 мс в ноль
```

**Почему suction именно из 7 полос.** Одна полоса с ползущим центром даёт «свист». Семь фиксированных полос, каждая со своей огибающей и разной задержкой, дают **слоистое всасывание** — эффект тот же, что в волне 9 (присасывание блока из 6 полос), только длиннее и выше. Гейн полос падает с частотой (`(200/c)^0.18`), поэтому верх не «кричит».

### 1.2 `zone_stinger_release` — 1.70 с, «отпустило»

```
0.00–0.45   обратное всасывание: свип центра 900 → 200 Гц
0.00–0.28   выдох: 6 полос 800/520/340/220/150/100 Гц, задержка 55 мс каждая
0.00–1.45   низ-тело 48 → 54 Гц, БЕЗ AM (это и есть отличие от intensify)
0.40–1.70   быстрый спад
```

AM здесь нет вообще — не потому что забыли, а потому что пульс = «живое, напряжённое». Отсутствие пульса и есть «отпустило».

### 1.3 `zone_stinger_deep` — 2.80 с, «давление»

```
0.00–0.50   суб-дроп 150 → 30 Гц (гармонический ряд, 5 гармоник)
0.00–1.80   погружение: свип центра шума 1100 → 70 Гц
0.85–2.40   гул 30–50 Гц + шум-партнёр 28–120 Гц
0.95–1.65   AM 40 Гц, глубина 32 % (roughness-полоса)
2.40–2.80   спад
```

Дроп и гул — **разные источники**, не один: дроп приходит сверху (150 Гц) и падает, гул уже находится внизу и остаётся. Поэтому 30 Гц «приходит», а не «включается».

## 4. Java-интеграция

### 4.1 Правило выбора stinger'а

Плотность зон из волны 11: `threshold < surface < deep < core`. Переход читается по разности плотности, а не по именам зон — иначе `surface → deep` и `deep → core` потребуют отдельных правил.

```java
package ru.carnis.common.ambience;

import net.minecraft.sounds.SoundSource;
import net.minecraft.world.entity.player.Player;
import ru.carnis.common.CarnisSounds;

/** Плотность зоны: чем больше, тем «глубже» ощущение. */
public final class ZoneTransitionStinger {

    private static int RANK(CarnisZoneAmbience.Zone z) {
        return switch (z) {
            case THRESHOLD -> 0;
            case SURFACE   -> 1;
            case DEEP      -> 2;
            case CORE      -> 3;
            case BASE      -> 0;
        };
    }

    /** Вызывается при смене зоны. Возвращает true, если stinger проигран. */
    public static boolean play(Player p, CarnisZoneAmbience.Zone from, CarnisZoneAmbience.Zone to) {
        int a = RANK(from), b = RANK(to);
        if (a == b) return false;
        // ставим перед фейдом амбиента: stinger «несёт» переход, а не комментирует его
        var level = p.level();
        if (b > a) {
            // в глубину — специфичный «давление», в остальные плотные — усилие
            var ev = (to == CarnisZoneAmbience.Zone.DEEP && a <= 1)
                    ? CarnisSounds.ZONE_STINGER_DEEP.get()
                    : CarnisSounds.ZONE_STINGER_INTENSIFY.get();
            level.playSound(null, p.blockPosition(), ev, SoundSource.AMBIENT, 1.0f, 1.0f);
        } else {
            level.playSound(null, p.blockPosition(), CarnisSounds.ZONE_STINGER_RELEASE.get(),
                    SoundSource.AMBIENT, 1.0f, 1.0f);
        }
        return true;
    }
}
```

### 4.2 Почему `pitch = 1.0` и почему нельзя иначе

Pitch-вариация у stinger'а **ломает его смысл**: `deep` содержит дроп 150 → 30 Гц, и при pitch 0.9 он уезжает в 27 Гц — там уже нечего слышать. Все три файла должны играть ровно. Это единственный слой в проекте, где pitch фиксирован жёстко.

### 4.3 Порядок относительно смены зоны

```
tick: зона изменилась (с гистерезисом из волны 11)
  t+0 мс    stop(AMBIENT)          — гасим старый bed
  t+0 мс    play(stinger)          — stinger стартует сразу, его onset 67–83 мс
  t+250 мс  play(новый zone bed)   — новый bed входит под хвост stinger'а
```

Stinger специально **перекрывает** тишину между bed'ами: 250 мс паузы волны 11 перестают читаться как «звук пропал», потому что в них играет переход.

### 4.4 Channel budget (после волны 12)

| Слой | Лимит | in-game RMS |
|---|---|---|
| transition stinger | 1, cooldown 3 с | −20.5…−24.1 |
| zone ambience | 1 stream | −38.2…−37.0 |
| HIVE базовый bed (fallback) | 1 stream | −40.2 |
| DETAILS | ≤1 | −33.2 |
| бой | по приоритетам волн 7–10 | −13…−20 |

Cooldown 3 с обязателен: при быстром беге по границе кластера зона может меняться несколько раз в секунду, и без cooldown игрок получит очередь из stinger'ов.

## 5. Что пришлось переделать

Три ошибки, и первые две — из тех, что «не слышно по одному файлу»:

**1. Эквализация ПОСЛЕ AM съедает модуляцию.** Заданная глубина 0.47 после EQ профиля измерялась как **0.17**. Причина: EQ перераспределяет энергию между несущей и боковыми полосами модуляции. Порядок обязан быть **EQ → сжатие → AM**. В волне 11 это же правило стоило 0.42 → 0.28.

**2. Насыщение (tanh) ПОСЛЕ AM тоже съедает модуляцию** — срезает вершины, которые и есть модуляция. Итог: **сжатие до AM, модуляция после**. Это неочевидно и стоило двух итераций.

**3. Crest 15–16 дБ не даёт уложить RMS при пике −13.** Требование «спектр 50–2000, без верха» запрещает добирать RMS широкополосным шумом — на верхах он сразу слышен как «шипение» и одновременно поднимает тональность края полосы до 18 дБ. Решение: **сжатие пикового диапазона** (tanh на −3…−6 дБ) поднимает RMS, не добавляя верха; crest доводится до нужного бисекцией. Побочный эффект: stinger становится плотнее по звуку — для короткого события это плюс, а не минус.

Плюс одна методическая: **метрика атаки «1 → 70 % пика» врёт на сложных сигналах** (атака 540 мс при фактическом onset 74 мс, потому что 70 % пика достигается на *втором* событии — пульсе). Правильная метрика для ТЗ «начало не резкое» — **onset: время до −20 дБ от пика**. Она и приведена в таблице.

**Важно для Кодера:** если событие в `sounds.json` называется `carnis:hive/amb_surface`, файл обязан лежать в `sounds/hive/`, а не в `sounds/amb/`. Именно эту ошибку пути исправляет перенос. Базовые `amb/hive_ambient_01…03` остаются на месте — они не входят в зональную систему.

## 8. Дальше

Зональная система завершена: **четыре состояния + три перехода**. Игрок всегда знает, где он и что произошло с пространством.

Осталось:

1. **`HIVE_SPAWN_HURT_CRITICAL`** (2–3 файла) — предсмертная реакция, мост между волной 5 и волной 4. Следующая по ТЗ.
2. **`PLAYER_HURT_ARMORED`** — принцип волны 10 для игрока в броне.
3. **Интеграция волны 11 + 12** (промпт Кодера) — когда файлы размещены.
