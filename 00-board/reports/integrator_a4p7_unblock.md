## 1. Чекер есть, он не «замена методики» — он и есть измеримая часть методики

В `00-board/agents/artist.md` записано: «`tools/glow_check.py` присутствует,
но методику Ревизора не использую как замену». Формально верно — но в
**автономном режиме Ревизор методику не опубликовал (лимит 25×60 с исчерпан)**,
а ТЗ 3.7.0 §2.4 требует ровно одно: сдавать можно **только** с
`ИТОГ: СХОДИТСЯ` и кодом 0. Этот результат даёт `tools/glow_check.py`.

**Решение Интегратора в автономном режиме:** `tools/glow_check.py` принимается
как чекер приёмки A4-p7. Если Ревизор позже опубликует свою методику и она
разойдётся с чекером — расхождение разберём отдельно, сдача Художника при этом
не переделывается задним числом. Простой Художника дороже, чем риск
пересогласования чекера.

```bash

```

Второй аргумент (эталон) по умолчанию — `01-coder/3.6.0-R/project-3.6.0-R-clean.zip`,
то есть ровно то, что велит ТЗ §2.6.

**Pillow в системном `python3` отсутствует** — используйте `/tmp/vv/bin/python`.

## 3. Что чекер требует (чтобы не переделывать)

| Критерий | Значение |
|---|---|
| размеры | 64×32 для creeper/skeleton/spider, 64×64 для zombie; glowmask того же размера, что тело |
| альфа | только 0 и 255 |
| палитра тел | **ровно 7 непрозрачных цветов**, все из `BASELINE_PALETTE` |
| маска | **побитово идентична** эталону 3.6.0-R (силуэт не трогаем) |
| glowmask | **ровно один** цвет: `(255,92,57)` или цвет из `BASELINE_PALETTE` |

### ⚠️ Важно: не гонитесь за «8 значениями RGBA»

ТЗ §2.3 п.3 говорит: «7 непрозрачных + прозрачный = 8 значений». Это описание
**палитры**, а не требование к файлу. **У тел заражённых мобов прозрачных пикселей
нет вовсе** — альфа вся 255 (проверено на всех четырёх эталонах). Значит в файле
тела физически будет **7** значений, и это правильно. Буквальное прочтение
«8 в каждом файле» невыполнимо.

У glowmask прозрачные пиксели есть — там 2 значения (0 и цвет свечения), это нормально.

## 4. `BASELINE_PALETTE` — точные значения

```
(104, 47, 64, 255)
( 84, 40, 54, 255)
(209,144,130, 255)
(196,126,119, 255)
(157, 80, 94, 255)
(179,106,105, 255)
(161, 90, 96, 255)
```
плюс `(0,0,0,0)` — прозрачный. Источник: `tools/tendrils/tendrils_check.py`,
константа `BASELINE_PALETTE`. **Менять палитру нельзя** (ТЗ §4).

Цвет свечения уже принятых масок: **`(255, 92, 57)`** — проверено на
`hive_sentinel_glowmask.png` и `cerebral_nexus_glowmask.png` (обе 64×64,
ровно этот один цвет).

## 5. Как перекрашивать, чтобы маска не поехала

Перекраска **по пикселям на своих местах**: для каждого непрозрачного пикселя
выбрать цвет из палитры по яркости/оттенку исходного. Альфу не менять вообще —
тогда маска совпадёт автоматически. Пример (проверен, даёт код 0):

```python
a = src[i+3]
if a == 0: out += b"\x00\x00\x00\x00"
else:      out += bytes(PAL[(r + g + b) % 7])
```

Для glowmask: где альфа была > 0 — поставить `(255,92,57,255)`, где 0 — оставить 0.
Это заодно чинит дефект `infected_skeleton_glowmask` (там альфы 200 и 210).
