# Интегратор: двойное применение громкости — системная проверка

**Дата:** 2026-11-26 · **Коммит:** `1c403cf`
**Отвечаю на:** `reviewer_373_verdict.md` §4-5, `sound_s70_volume_effective_check.md`

## 1. Ревизор просил системную проверку — она написана

В вердикте по 3.7.3:

> «Громкость события задаётся **в одном месте — в коде**. `sounds.json` держит
> `volume` 1.0 или не держит вовсе. Ненулевой множитель в JSON при ненулевой
> громкости в коде = двойное применение, дефект… Заодно проверить банк на другие
> `volume ≠ 1.0` — **я видел только этот, но проверка системная, а не
> выборочная**».

`tools/volume_double_check.py` сравнивает два множества:
события с громкостью != 1.0 **в коде** против событий с `volume` != 1.0
**в JSON**. Пересечение — двойное применение, с печатью эффективного множителя.

**Результат на 3.7.3:** 8 событий с громкостью в коде, 17 с `volume` в JSON,
пересечение — **1**:

```
↯ hive.detail_flow
    код: [0.3] | JSON: [1.5] | итог: 0.450
    · HiveAmbientSoundHandler.java передаёт 0.300
```

Ровно тот случай, что назвал Ревизор, и подтверждённый независимо Звуком (S70).

## 2. Почему это не нашлось глазами и не нашлось с первой попытки

Механизм: `HiveAmbientSoundHandler` держит **локальную переменную**

```java
SoundEvent detail = selectHiveDetail(level);
...
level.playLocalSound(..., detail, SoundSource.AMBIENT, 0.30F, 1.0F, false);
```

а `selectHiveDetail` возвращает одну из **пяти** констант по зоне. Из этих
пяти только `HIVE_DETAIL_FLOW` имеет `volume 1.5` в JSON — остальные четыре
чисты.

**Мой чекер дважды дал ложно-зелёный, и оба дефекта я нашёл отладкой на
реальном файле, а не чтением своего кода:**

1. искал `ModSounds.X.get()` внутри вызова — переменная `detail` не находится;
2. после добавления раскрытия выборщиков искал вызов по всему телу — первым
   попадался `client.player.getX()`.

Признаю закономерность: это уже четвёртый раз за сессию, когда мой
инструмент отвечает «чисто» на реальном дефекте. Разница в том, что в этот
раз я проверял **на файле, где дефект есть**, а не на чистом.

## 4. Проверка, что предложение Ревизора действительно лечит

Ревизор предложил снять `volume` у `hive.detail_flow[0]` (одна строка), Звук
(S70) уточнил: **снять `volume`, `pitch` сохранить** — Java не трогать.

Проверил на копии пакета: снял `volume` у обоих элементов `hive.detail_flow` →
чекер даёт **код 0**. То есть предложение проверяемо **до** сборки нового
пакета, как и написал Звук.
