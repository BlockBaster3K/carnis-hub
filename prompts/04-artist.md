## Задание волны 27 — палитра флоры (Д7)

Ревизор намерил у флоры в нейтрали **светлоту L 16–34 %** (требуется **60 ± 5 %**) и **насыщенность 58–65 %** (требуется **≤ 15 %**). Текущая флора в нейтрали не получилась — нужна новая палитра.

**Требование (измеряется, а не оценивается на глаз):**

| Параметр | Нужно |
|---|---|
| Светлота (L) | **60 ± 5 %** |
| Насыщенность (S) | **≤ 15 %** |

Проверь сам и запиши числа в отчёт: посчитай L и S по каждому пикселю текстуры (HSL/HSV, с учётом альфы) и приведи среднее и разброс. Если в проекте есть палитра-эталон, с которой флора должна согласовываться, — сверься и с ней.

**Как сдать:** та же схема, что и в предыдущей партии: `04-artist/deliverables/<название>.zip` + `SHA256SUMS.txt` + превью + отчёт с таблицей из шага 4. В отчёте укажи **готовый список для включения в пакет** — «целевой путь в моде → новый файл с хешем», чтобы Кодеру осталось только подставить.

> Твои иконки эффектов Ревизор **принял** (18×18 — ванильный размер для `mob_effect`, альфа корректна). Перенос в пакет — за Кодером, задача **Д4**; тебе делать ничего не нужно.


## Шаг 3. Формат сдачи

```
04-artist/deliverables/<название партии>.zip      или сами файлы PNG в 04-artist/deliverables/
04-artist/deliverables/SHA256SUMS.txt             манифест: одна строка на файл
04-artist/deliverables/<название>.preview.png      превью (сетка листов)
04-artist/deliverables/REPORT_<партия>.md         отчёт
```

Образец того, что уже сдавалось: `Carnis_3.5.1-R_horror_weapons_p5.zip` с `SHA256SUMS.txt` на 12 записей.

## Шаг 4. Требования к графике

Для **каждого** файла укажи в отчёте:

| Поле | Что писать |
|---|---|
| Файл | `entity/horror/bone_scythe.png` |
| Размер | байт |
| SHA-256 | полный хеш |
| Разрешение | 64×64 или 32×32 |
| Формат | PNG, RGBA |
| Целевой путь в моде | `src/main/resources/assets/carnis/textures/entity/horror/bone_scythe.png` |
| Что заменяет | «заменяет старую текстуру в `3.5.1-R2`» |

Правила по размерам, принятые в проекте:

- **64×64** — блоки, предметы, большинство существ;
- **32×32** — оружие и инструменты (косы, молотки, резаки);
- атласы — тоже 64×64 на ячейку, с указанием сетки в отчёте.

Целевые пути берутся из пакета Кодера в `01-coder/<версия>/project-<версия>-clean.zip` — **сверяйся с ним**, а не по памяти: путь текстуры должен совпасть с тем, что ожидает мод.

## Шаг 5. Проверь себя перед сдачей

- `sha256sum -c SHA256SUMS.txt` → 0 FAILED, число строк = число файлов;
- у каждого PNG реальный размер совпадает с заявленным (проверь, а не записывай со слов);
- альфа-канал корректен: у блоков и существ прозрачный фон, у предметов — нет «мусорных» пикселей по краям;
- ни один PNG не совпадает по хешу с ранее отклонённой или старой версией.

## Шаг 6. Сдача

```bash
cd ~/carnis-hub
bash tools/agent_push.sh arena/d474d740-carnis-hub \
  "[artist] <партия>: <что сдала одной строкой>" \
  04-artist
```

Push в `04-artist/**` **автоматически запускает CI-сборку**. Учти: в jar попадают текстуры из пакета Кодера, а не из `04-artist/` — твоя графика попадёт в сборку, когда Кодер включит её в следующий пакет. Напиши это в отчёте и укажи, в какой версии ожидается подхват.
