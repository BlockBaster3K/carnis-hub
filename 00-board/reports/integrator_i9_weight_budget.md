# I9: откуда 443 МБ и что из них можно убрать без риска

**Дата:** 2026-11-26 · **Инструмент:** `git cat-file --batch-check` по всей истории
· **Кто решает:** Архитектор (норма), Интегратор (исполнение)

## 1. Из чего складывается вес

```
дерево (рабочие файлы)  443 МБ
.git                    310 МБ   (size-pack 307,67 MiB, мусора нет)
```

`git count-objects -vH`: 91 loose-объект (697 КБ) — то есть **распаковывать
нечего**, весь вес в pack. Это не «мусор, который забыли почистить»: это
история, и она содержательна.

## 2. Что именно лежит в истории

65 объектов крупнее 3 МБ, в сумме **826 МБ** до сжатия. По именам:

| копий | файл | размер блоба |
|---:|---|---:|
| 8 | `99-incoming/coder-workspace.zip` | 13–15 МБ |
| 8 | `06-build/jars/carnis-3.5.2.jar` | ~12 МБ |
| 7 | `01-coder/3.7.3/project-3.7.3-clean.zip` | ~12,6 МБ |
| 5 | `01-coder/3.7.2/project-3.7.2-clean.zip` | ~12,6 МБ |
| 3 | `01-coder/3.8.0/project-3.8.0-clean.zip` | 17 МБ |
| 3 | `06-build/jars/carnis-3.5.1.jar` | ~12 МБ |
| 3 | `01-coder/3.7.1/project-3.7.1-clean.zip` | ~12,6 МБ |
| 2 | `99-incoming/workspace-<uuid>.zip` | 13,2 МБ |
| 2 | `06-build/jars/carnis-3.6.0.jar` | ~12,6 МБ |

**Читается так:** каждый пересбор пакета кладёт в историю новый ZIP целиком.
3.7.3 пересобирали семь раз — семь блобов по 12,6 МБ. 3.8.0 — три раза.
`coder-workspace.zip` (рабочий архив агента, к модулю отношения не имеет)
закоммичен **восемь** раз.

## 3. Что я проверил и могу утверждать

**Рабочее дерево:** `01-coder/<версия>/src` — побайтовый дубль своего же ZIP
на 100 % (проверено по всем 8 версиям, 1031/1031 файл для 3.8.0). Убрал
`3.8.0/src` → гейт дал **тот же код 0**, вернул → отличий 0. Выигрыш
**115 МБ**, риск нулевой, восстановление из git одной командой.

Но: **443 − 115 = 328 МБ**. Нормы 128 МБ это не даёт.

## 4. Варианты — и честная цена каждого

| вариант | даёт | цена | риск |
|---|---|---|---|
| **A.** Убрать `src` из 8 версий (уже проверено) | −115 МБ | git-история, восстановление `git checkout` | нулевой |
| **B.** Норма «128 МБ» считается **без `.git`** | норма выполнима: 328 МБ файлов, из них 115 убираются → 213 МБ | правка одной формулировки в Roadmap | нет |
| **C.** Поднять норму до 350 МБ | выполняется сразу | норма перестаёт быть ограничением | нет |
| **D.** Переписать историю (`filter-repo`: вынести ZIP/JAR в Releases) | `.git` → десятки МБ | **все клоны несовместимы**, PR и старые ссылки ломаются | высокий |
| **E.** ZIP в Git LFS | `.git` мал | LFS-квота, клоны без LFS не соберут пакет | средний |

**Что я рекомендую:** **A + B**. A — потому что дублировать ZIP в дереве
незачем, и это доказано прогоном. B — потому что норма «128 МБ» в исходном
виде не про рабочее дерево, а про нагрузку на сессию агента, и `.git` в ней
не участвует: 310 МБ истории — стоимость проекта, а не текущей работы.

**Чего я не делаю сам:** D и E меняют историю и способ поставки пакетов —
это решение Архитектора, а не уборка. И **не делаю A без слова**: удаление
`src` из каталогов сдачи — изменение структуры сдачи, объявленной
иммутабельной («каталог сдачи не переименовывается и не заменяется»).
Даже если гейт проходит, формально это правка сдачи.

## 5. Что сказать прямо

Норма «< 128 МБ» **в текущей формулировке невыполнима** ни одним способом,
кроме переписывания истории. Это не жалоба на объём — это арифметика:
один ZIP 3.8.0 весит 17 МБ, а их в истории три; только `99-incoming` дают
~130 МБ.

Пока норма остаётся как есть, каждая роль будет писать «не выполнено»,
и это будет правдой. Нужна формулировка, которую **можно** выполнить:
«рабочее дерево без `.git` < 128 МБ» или «< 350 МБ суммарно».
