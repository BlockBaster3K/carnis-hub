# Кодер · K7 — одношаговый порядок заготовки следующей версии

Статус: завершено как воспроизводимый порядок для 3.7.5+ (2026-11-20). Порядок не создаёт ZIP/JAR и не меняет принятую версию.

## 1. Выбрать достоверный источник

1. Источник — **полный ZIP последней принятой версии**, а не незакрытая заготовка и не ZIP с ожидающими ревизиями. Записать версию, commit и SHA-256 ZIP.
2. Если файл отсутствует из-за sparse checkout, читать его непосредственно из Git (`git show <commit>:<path>`), сохраняя временную копию вне checkout; не менять sparse patterns только ради чтения.
3. Проверить архив: `unzip -t`; составить список файлов и исключить дубликаты, абсолютные пути и пути с `..`.

## 2. Создать новую заготовку

1. Создать **новый**, отсутствующий ранее каталог `01-coder/<новая-версия>/`; не перезаписывать прежние версии.
2. Извлечь только содержимое принятого ZIP с относительными путями; не класть ZIP, старый манифест, `.jar`, логи или кэш внутрь проекта.
3. Побайтово сохранить все исходные файлы. Выполнить только необходимые разрешённые обновления версии и внешние сдачи. Любая иная разница должна иметь отдельное основание и быть записана в отчёте.
4. Версию изменить ровно в четырёх местах: имя каталога, `gradle.properties: mod_version`, `mods.toml: version`, `mods.toml: displayVersion`. Остальные значения (Minecraft/Forge и т.п.) не трогать.
5. Сдачи Художника/Звука добавлять побайтово по целевым путям; аудио не перекодировать. Если требуемая сдача или новый банк ещё не готовы, оставить соответствующий шаг ожидающим и не маскировать ожидание старой копией.

## 3. Проверить заготовку до сборки релизного пакета

1. Сверить число и перечень файлов исходного ZIP и новой заготовки; сформировать таблицу SHA-256 различий.
2. Убедиться, что все незаявленные файлы совпадают с источником, а изменения соответствуют только версии и согласованным дельтам.
3. Проверить версию во всех четырёх местах и убедиться, что каталог новый.
4. Зафиксировать в отчёте исходный ZIP/commit/hash, версии, количество файлов и список различий.
5. Не собирать `.jar`; ZIP релизного пакета, соседний манифест, `sha256sum -c` и профильный гейт — отдельный этап после готовности всех входных сдач.

## Применимость сейчас

K7 задаёт повторяемую процедуру, но **не разрешает пересобрать 3.7.3 из прежнего банка**: решение T-3182 требует сначала получить обновлённые 15 OGG от Звука. Текущий `4c4632c` остаётся промежуточной сборкой и не считается релизной приёмкой.
